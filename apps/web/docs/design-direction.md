# Clementine website direction

Surface: apps/web. Mode: Experience leading to a Mac download.

## Latest user direction — mobile and six chapters, 2026-10-02

The first seven-film candidate received a B-minus: isolated chapters did not flow.
The user wants an immersive scroll journey, with the dog only in the hero. Clem
loops while the visitor reads. On scrolling, she makes a playful jump, picks up a
blank document, and offers it toward the viewer. That document carries the visitor
into the architecture. The supplied real photo remains character authority:
reddish caramel fur, white forehead blaze, white muzzle and chest, upright ears.

The next refinement preserves that world and improves mobile reading, makes
recording and interactive Spaces first-class chapters, and explains the actual
multi-agent, multi-model architecture. The journey now follows six chapters:
the loop, memory, tools, recording, agents and models, then Spaces and workflows.

## Interaction contract

The hero is the only character performance. Its quiet idle loops; native scroll
scrubs the document handoff and takes over with a real HTML paper artifact. The
paper recedes into the same position at the beginning of the architecture journey.
Both sides of that handoff follow native scroll directly; smoothing only one side
breaks the shared paper pose. Overlapping mobile containers stay transparent until
their entrance reveal, and entrance geometry is remeasured when the hero changes
height during hydration or responsive layout changes.

After the handoff, desktop uses one pinned viewport and one continuous physical
3D world. Native scroll moves its camera through all six chapters, with bounded
damping to soften abrupt movement. Damping must settle when input stops, preserve
reverse travel, and freeze on pause; it must not replace browser scrolling or
intercept wheel and touch input. The world does not swap films or run independently
of the visitor. A continuous copper route and the same paper task connect the
chapters.

Mobile and short viewports use a natural document flow. Each chapter has room
for its real content, 16px body text, and native controls with 44px touch targets.
The world remains visual continuity behind the reading experience. Avoid shrinking
desktop panels to fit a phone or trapping the visitor inside a fixed-height scene.
Direct chapter selection, normal touch scrolling, and keyboard navigation remain
available. Reduced motion and data saving use a readable static story.

Readable HTML explains the architecture, retaining direct controls for loop
stages, memory examples, tool paths, projects, and independent model pins. The
team explains orchestration, specialist instructions and independent model pins,
and completion review. The recording example changes between transcript, summary,
and action items from one illustrative launch sync. The Spaces example filters a
launch board and opens a source preview; its workflow view changes the trigger
and resulting trace. These are working local examples, not links to live accounts.
Jev is described as built-in System One integration when connected; completion
review compares results with the request and evidence. Examples remain explicitly
illustrative. See [feature evidence](feature-evidence.md) for claim boundaries.

The last architecture view leads into real product screenshots and download
links. Open-source code and the MIT license stay directly accessible. The page
never calls the live daemon or modifies a user's projects, Spaces, or accounts.

## Visual system

Keep soft 3D Clem, Plus Jakarta Sans, terracotta, amber light, tactile cream paper,
and warm dark ground. Use physical camera travel and a single object handoff as
the signature motion. Avoid alternating giant film headers and separate demo
blocks, repeated dogs, background playback in every section, and decorative
entrances unrelated to the same task.

## Alternatives and acceptance

Native scrolling must remain available at all times. The hero respects pause,
reduced motion, data saving, offscreen and hidden-document playback. Static mode
presents all explanations in document order. WebGL failure retains a dog-free
poster and usable HTML. Invisible story panels are inert. Direct chapter links,
keyboard access, reverse-scroll state, the real media handoff, and all new demo
states belong in acceptance. The six-chapter/mobile revision has its own
[verification record](mobile-features-verification.md); earlier four-chapter results remain historical.

Generated assets and earlier films remain archived with provenance. A successful
build or internal review is not final user design approval or Railway deployment.
