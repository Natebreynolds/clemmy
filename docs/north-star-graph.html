Clementine · north star · target · when the cuts are done

One graph engine. Chat, workflows, and cron are the same machine. Brains are pipes. The host owns the turn.

This is the destination, not the tree today. Vendor SDKs (Claude Agent SDK, OpenAI Agents Runner) remain OAuth pipes so Max/Pro and Codex still bill. They do not own routing, tools, budgets, or the terminal. A brain is a property of a graph node. Ready nodes run concurrently. One crossing kernel. One Outcome, on every surface.

Gates and harness shouldn’t stop the models — only help them, and inform the user.

operating doctrine · encoded as the squeeze test below

accepted source → admitted graph → exact call authority → fenced reservation → receipt / read-back → one Outcome

The stack ONE ENGINE, NOT TWO LANES

Today Discord can fork into a Claude SDK mega-loop and desktop into an OpenAI Runner mega-loop, while a shadow graph looks on. Target: every ingress writes one accepted source, one graph runs, pipes only complete a node.

Three altitudes, one kernel PROPORTIONAL, NOT A MEGA-LOOP

Complexity is allowed in the kernel. The user should feel a faster Clem. Conversation does not pay construct ceremony. A light write still crosses the write kernel.

conversation

  • Durable turn → natural reply
  • No capability search, task graph, or background run unless they asked Clem to act
  • One model step, zero tools unless needed
  • Greeting is not a 5k-token proposal

read

  • Bounded discovery, sourced results
  • Checkpoints only for breadth or duration
  • Does not inherit write reservation or read-back ceremony
  • Proven tools are consumed, not rediscovered

construct / write

  • Exact capability + account + schema
  • Fenced dispatch, one user-facing effect
  • Create+fill of this artifact is one effect; send is another requirement if they asked for both
  • Durable receipt; honest blocked with owner if it cannot finish

Chat · workflow · cron SAME ENGINE, DIFFERENT GRAPHS

A workflow is not a second product. It is an admitted graph with a longer lifetime. Cron is the same graph fired by a clock. Chat is the same graph fired by a person.

  • API keys remain for voice, embeddings, or if we choose Console billing

Squeeze test WHAT THE HARNESS MAY NEVER DO

may Guide

  • Project durable context from the log
  • Freeze capability, account, schema, effect
  • Make effects exactly-once so the model can retry fearlessly
  • Label outcomes with evidence (never rewrite her words)
  • Park and resume; ceilings re-enter
  • Interrupt only for discretion, credentials, essential input, uncovered irreversible, uncertain committed write
  • Tell the truth on every surface

must never Squeeze

  • Rewrite or replace model prose
  • Decide route / effect / completion from vocabulary
  • Ask the user to do bookkeeping (second search, “want me to start,” restart vs review)
  • Let a judge outrank evidence
  • Stop a model mid-reasoning
  • Stall — blocked without owner + resume is a failure
  • Run a second SDK harness beside the graph
