## Implemented behavior

- Dictation uses accessible tap-to-start/tap-to-finish controls, visible starting/listening/transcribing states, cancellation and useful permission errors. AudioContext resume starts in the initiating gesture; all permission/setup/cancel races release capture. Transcription results append to the latest draft only while the original draft owner is current. Cancellation aborts transcription fetch. Existing browser speech fallback retains its original selection rule and now reports errors and retains all transcript segments. No new transcription-provider fallback was introduced.
- Mobile now has an explicit Talk to Clem conversation loop. It transcribes, sends through the same chat engine/admission/context/Plan rules as typing, reads new replies, and listens again. `voice:true` survives pending retries, accepted source events and steers. Existing drafts/files block starting voice rather than being silently consumed. Voice and dictation exclude each other; stopping voice, navigation, backgrounding, failed capture and stale async results cannot send into another conversation. Ending voice does not pretend to cancel an already accepted task; the task Stop control remains available.
- Mobile speech uses a proof-authenticated `/m/api/chat/speak` route sharing desktop's bounded spoken-text formatter and configured speech service. Explicit system-voice fallback remains supported. Abort closes upstream speech. Native WebKit allows audio playback after network waits while retaining video gesture gating (`mediaTypesRequiringUserActionForPlayback = .video`); paired-main-frame microphone permission checks remain unchanged. Browser speech has a start watchdog; AudioContext unlock has a bounded wait.
- Native WidgetKit extension supplies small/medium Talk to Clem and Your Space widgets. Medium quick actions include Talk, Dictate and the chosen Space. The Space preview is a bounded, explicitly chosen saved snapshot with its age; the widget has no network client, model, microphone or credentials. `Space details → Use in iPhone widget` requires an exact native storage receipt before showing success. Clear/sign-out/unpair cleanup is implemented. UTF-8 truncation and whitespace normalization match native limits. App and extension share `group.ai.breakthroughcoaching.clem`.
- Strict `clem://voice`, `clem://dictate`, `clem://space` and `clem://space?id=<slug>` routes open the paired app through foreground, connection and biometric gates. Voice/dictation land on their controls and require a foreground tap; URLs never start recording. A pairing-bound pending route survives unavailable startup until an exact destination receipt. Warm widget taps use the existing web document, retaining drafts/uploads; missing/not-ready warm handlers leave the intent parked and retry on explicit readiness. Unfinished new-chat scopes are retained. Old effects cannot acknowledge another widget tap or another Space.
