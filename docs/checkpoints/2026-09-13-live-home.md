# Real Home surfaces — 2026-09-13

The owner asked to move the Home direction into the installed application so Clem can build useful Home surfaces. This changes `/console/home`; the explicit `/console/dev/home-mock` remains a design preview. It does not seed the owner's Home with mock business data.

## Product and implementation

- Home keeps its prominent chat composer and the existing Needs you, Running, recent results, Made, Spaces, and quick actions. Build home accepts a natural request or pins an existing Space. Connected starter recipes reuse the existing Space gallery.
- A tile references a real Space. Its saved HTML, stored data, phone projection, refresh machinery, and audit remain owned by Spaces. Desktop renders the existing read-only WorkspaceFrame preview; Open Space provides the full interactive surface. Home opening does not itself dispatch authored actions or paid research.
- Desktop offers small/medium/wide, Now/Watching, move to first, and remove from Home. Removal keeps the Space. The native `home_get` / `home_update` tools provide exact placement and arbitrary before/start/end ordering; normal authorized placement is a reversible local write and needs no additional approval or Plan.
- Mobile reads the same layout and Space data through authenticated paired-app routes. Its compact tile shows the existing phone projection and opens the full Space. Mobile can add existing Spaces and ask Clem to build; dedicated mobile resize/reorder/remove controls are not included in this pass.
- `state/home-layout.json` is versioned, atomically written under a cross-process lock, and revision checked. Concurrent changed writes conflict with the current layout; exact no-op retries do not duplicate tiles. Missing state is a fresh Home; malformed state is an error and is never silently replaced. There is no fixed tile-count cap.
- Both desktop and mobile report failed refreshes and keep saved values visible. Home placement and Space content have separate revisions so editing content does not repin or overwrite placement.

Primary files: `src/runtime/home-layout.ts`, `src/tools/home-tools.ts`, `src/tools/tool-registry.ts`, `src/dashboard/console-routes.ts`, `src/channels/mobile-routes.ts`, `apps/console-web/src/screens/Home.tsx`, its `components/home` additions, and `apps/mobile-web/src/components/HomeTiles.tsx`.

## Generic harness defect found during qualification

The first live create-and-pin run hit `outside_accepted_scope`: after a new Workspace was created, the collision guard treated a placement edit to Home as an overwrite of that Workspace. `accepted-mutation-scope.ts` now looks up the retained mutation scope within the operation's deliverable family. A new Workspace and existing Home can belong to the same accepted task. A Home edit cannot grant overwrite authority to a failed Workflow/Workspace create. Existing per-call authority checks remain in place. This is not a Home keyword exception and adds no new gate.
