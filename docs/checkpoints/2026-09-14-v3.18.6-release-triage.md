# 3.18.6 release regression triage

The owner requested publication of the combined Home/chat UI and harness update, with production defects fixed and obsolete test expectations corrected. Publication remains authorized. The candidate is macOS-only, for Apple Silicon and Intel, as was 3.18.5.

## Functional fixes

- Mixed Composio discovery caches account decisions by toolkit and read/write effect. Read-only account routing cannot authorize a write, and an unavailable write reviewer cannot suppress a usable read.
- Concurrent searches merge current-source discovery proof after asynchronous account checks, immediately before publication. Previously each could overwrite the other’s independently checked tool. A controlled concurrent discovery test and the research/restart journey exercise this.
- Fresh MCP discovery invalidates its own namespace cache. Invocation freshness retires an exact missing operation; a newly named operation is independently discovered, without guessing an alias. Schema changes still use normal exact-operation supersession.
- Compound Space completion compares accepted arguments against the same call’s immutable raw and normalized digests. The call, accepted task, source, tool, and bound digest must all match. Changed content and unrelated calls remain invalid.
- Completed asynchronous research settles a finite verified selection with an explicit completeness flag. The evidence producer’s verification is unchanged. Existing successful settlements replay without replacing their immutable payloads.

## Test contract corrections

The original canonical journey run had 174 tests, 151 passing and 23 failing, including parent failure counts. These were not 23 independent production defects.

- Optional completion review may deliver a completed read with an honest unreviewed disposition; the fixture still requires failed-open status and verified=false.
- Discovery publishes independently proven reads and writes. Tests no longer require writes to stay hidden until Plan. Unknown versions, schema drift, removed operations, unproven accounts, and unauthorized business I/O remain negative cases.
- The direct-catalog fixture explicitly names its selected operation so a bounded initial card does not rank twelve unrelated seeded entries ahead of it. The selected current operation still must enter the frozen snapshot without same-turn staging.
- Workflow dispatch is a host coordination call; the workflow body owns its business effect. Mutation counts and physical execution assertions remain separate.
- Repeated identical refused frames retire after two attempts, with a paired do-not-retry response on the next request. The next accepted source still receives an independent repair response. Accepted Act work uses its own recovery rather than the ambient governor.
- Full discovery results are read from durable tool output, not the abbreviated activity preview.
- The sole-mailbox mixed-discovery fixture checks write rejection separately from the independently available read. A failed or unavailable write review must never authorize that write; it also must not suppress the read. The final full unit run exposed this remaining pre-refinement expectation; the corrected 29-case account-routing suite passes.

## Performance comparison

The recording byte-ledger journey was run on the actual published v3.18.5 tag (00943a2c), using Node 22. Initial SDK/wire bytes were 29,188/29,210; cumulative unique discovery/schema bytes were 50,076. The candidate measured 29,211/29,233 and 51,366 before the final focused fixes. Initial tool schemas were exactly 18,121 bytes on both versions. The changed discovery guidance explains most of the increase; this is not a new 29 KB regression from a 16 KB production surface.

The historical 16 KiB initial / 32 KiB cumulative competitive targets remain explicitly reported, including whether they are met. They are not claimed achieved. The release regression check now permits at most 5% growth against the measured published baseline, while retaining the functional, cache, hidden-model-work, worker-I/O, and exact byte-accounting assertions. No runtime context truncation or tool-hiding was added to fit a benchmark. The separate 10,000-catalog planning benchmark retains its original 16/32 KiB limits.
