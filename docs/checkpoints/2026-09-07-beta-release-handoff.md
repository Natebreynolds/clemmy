## 2. Architecture clarification: the SDK removal is not complete

The owner asks why a Claude "lane" remains after the intended SDK removal. Separate provider transport from execution ownership. Provider-specific authentication, request/stream conversion and model identity are expected; a second provider-owned agent loop with different execution/recovery rules is a separate architecture question.

Observed here:

- Both current runs record provider Claude, model Opus 5, transport `host_harness`, engine `host_v1`. Their diagnosed retrieval/verification failures occur in shared Clem code. Do not blame the Claude Agent SDK for this Plan failure.
- `respond-bridge.ts` gates its standalone Claude interactive runner behind `allowStandaloneClaudeInteractiveBrainForTests`; ordinary chat falls through to the common harness. That is real containment, not deletion of all SDK code.
- `package.json` still includes `@anthropic-ai/claude-agent-sdk` and the `@openai/agents` package family. The source contains runtime imports as well as types/tests. Thus "both SDKs are gone" is not an accurate repository claim.
- `src/agents/orchestrator.ts` still branches on `claudeAgentSdkWorkerEnabled(workerModel)` and calls `runClaudeAgentSdkWorker`; `src/tools/worker-tools.ts` also contains a provider-specific worker dispatch. The helper's SDK worker flag defaults on for a Claude model. Retained workflow SDK helpers also exist. This review has not run fan-out or traced every enclosing reachability guard, so distinguish a present dispatch branch from proof that a particular live request entered it.

**Before release, inventory production entry points** for chat, workers, workflow steps, background runs, judges, recovery and resume. For each, name the engine owning the model/tool loop, provider transport, reachable legacy fallback and evidence. Test actual routed execution, including worker failure and restart, rather than inspecting labels alone. Make tools, scope, continuation, Stop and completion converge on the shared host wherever the intended architecture requires it. Retire proven dead agent runners/dependencies after migrating remaining users; keep necessary provider adapters. Do not delete SDK packages blindly while imports, MCP adapters, model types or auxiliary consumers still need them. Do not claim global SDK removal based on the ordinary-chat switch.

Name telemetry clearly: engine, provider, transport and purpose are different fields. Old `claude-agent-*`, `sdk_brain` or `lane:codex` labels can mislead reviewers even when the shared engine is executing. Cosmetic renaming alone does not close an active execution split. Provider-neutral execution and supported subscription/auth routes must remain tested together.
