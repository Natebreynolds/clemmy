## Owner's 2-3-4

**#2 Read answers are checked by Jev alone.** A turn whose accepted source
produced no write (no mutating settlement other than a restorable local
execution) asks Jev only; a Jev "not done" goes back to the model; no verdict is
an honest unavailable review. Writes, plans, memory and inherited reviews keep
the second-model review. Live v5 (`fcb64c373`): R23 read fixture, Jev accepted,
`reviewerStarted: false`, 39 s; R25 on v6, 4.7 s.

**#3 Provider outage.** A provider 5xx / overload that outlives the model
boundary's retries now stops resumably ("try continuing from here?") with the
completed work saved, never a dark failure. Falling over to another brain is
already built (`RouterModelProvider.buildBrainChain`) but the live home's
`.env` carries `CLEMMY_BRAIN_FALLOVER=off`; the owner removes that line.

**#4 One action of a multi-action tool that only reads is a read.**
`exact-call-variant-read.ts`. Asked only when the carrier declares itself
destructive or the risk is unknown/unknown, and never for a call whose
arguments carry a send, recipients or a request method. The call's top-level
enum/const values are fixed; Jev screens (change probability ≤ 0.35) and the
configured judge confirms (≥ 0.9) from the tool's own description and schema.
A native tool's description comes from its server's tool list only when its
bytes hash to the manifest's `operationVersion`. Agreement proceeds with basis
`exact_variant_read` (before coverage and Plan-mode refusal, after safety,
crossing, readiness and checkpoints), books as a read (no write reservation,
Jev-only review), and is remembered per operation, definition and values in
`state/operation-variant-read-verdicts.json`. A source held from learning gets
the reading for its own call and nothing is remembered. Every reading is frozen
per logical call (`exact_call_variant_read_basis`).
