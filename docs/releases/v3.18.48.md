# v3.18.48 — Clem's words stay with her question, the checker costs a third, an approved set ends once, and a write never replaces an outside edit in silence

**No database migration** (harness schema stays at 99). The Mac build comes
from the release workflow (signed and notarized). The Windows x64 build of
the same commit is qualified by the private Windows pipeline from this tag,
**unsigned** until a code-signing certificate exists.

## What Clem says before she asks stays in the reply

- **A question no longer swallows the answer that came with it.** When Clem
  reads a document, writes what works and what she would change, and then
  asks you one thing, the whole reply used to collapse to the question. Three
  turns in a row read as an interrogation while her critique sat unseen in
  her own history. The reply now keeps her words ahead of the question, the
  card still ends on the question, and your answer still counts as the
  answer to it.

## The checker reads the work, not the transcript

- **Each written file is read once.** A file Clem wrote appeared four times
  in one review: the write's receipt, two read-backs and a step note. Any
  result that carries exactly the saved content is referenced to the one
  place it is shown, with everything beside it (a warning, a missing
  requirement) left in front of the checker.
- **A re-review sends only what changed.** After a repair the checker used to
  re-read the whole evidence. It now continues its own conversation with the
  blocks that are new or changed and the first lines of the blocks that are
  gone.
- **A plan's execution does not re-review its discovery.** The reviewed plan
  already carries its selected tools; the dumps that found them stay out of
  the execution review, and a plan publication is stated by size and digest.
- Measured on one deck build: the checker went from three calls and 168k
  tokens to one call and 47k, and the whole turn from 855k to 363k prompt
  tokens, 134 s to 71 s. Each evidence section's size is now journaled so
  the next cut is measured, not guessed.

## A correction while Clem works is folded in, not fatal

- **A steer mid-task no longer kills the turn.** "Make it 4 slides, not 5"
  sent while Clem was writing used to end in "I could not reopen the saved
  checkpoint" with nothing written. The cause was a write whose own field sat
  beside the carrier instead of inside its arguments; the carrier, the
  identity and the dispatch now name one call, and the steered write lands.
- **A refused argument names the allowed values.** "mode: Invalid input" cost
  a search and a retry on every write; the refusal now lists the values.
- **The same refusal three times ends the step with the reason said plainly,**
  however many reads land in between, including a read beside the refused
  write in the same step.

## Finding the way in

- **A provider result names its app.** A search for a call-tracking product's
  "daily call volume" returned a video-meetings app and it was taken as the
  product. Each result now carries the app's own name and description, and
  the search says which of three things is true: not found yet, not
  connected, or not among the connectable apps, so Clem offers the way in
  instead of substituting.

## The approved set ends once, in Clem's words

- **One card, one tap, one ending.** Two checks approved together used to end
  the conversation twice, the second ending calling the first "still
  outstanding." Every member keeps its own receipt; the set's last member
  speaks once with every member's own recorded result, under failure, delay,
  a Stop during its wait, and a restart.
- **The card's question is written once.** A call meets the off-machine door
  twice in one step; the second pass reuses the first card's words (four
  checker calls and 15 s became one call).
- **A write's full review asks for medium effort** with the same evidence
  and deadline: 54 s and 4,579 output tokens for a 414-character verdict
  became 15 s.

## Workflows that finish hand over what they made

- **A run started together with others speaks only for itself,** so the
  first to finish no longer says it has nothing on the second.
- **The held request continues from each run's own facts** — its report,
  every step's recorded output and the path of every file it committed —
  instead of a one-run summary and settlement counts. The brain no longer
  searches the home folder for a note a run had saved.
- **A failure the host diagnosed itself is not told as a locked keychain.**

## A file write binds to what this conversation last saw

- A read records what it returned and a write what it committed; a later
  write expects exactly that on disk and meets an edit made outside as a
  typed conflict, never replacing it in silence. No read is demanded first,
  and create, append, chunked and exact-span writes work as before. The base
  is frozen with the operation, so a completed write recovers its receipt
  without another write.
- **"Change that first bullet" is an edit, whatever mode the first call
  picked.** A refused create no longer narrows the job to "create new file",
  and a turn seeded from an earlier write is offered every mode of the tool,
  so the correct replace is a legal call rather than a reason to reach for
  the shell.
- **The file tools say where a relative path lands** (Clem's files folder),
  so a file named by its Clem path is read as given, not searched for.

## Known

- The Windows beta is unsigned and installs with the usual SmartScreen step.
- Several writes of one kind on a connected app still open one card per
  step on the consent path; one card for the set is next.
