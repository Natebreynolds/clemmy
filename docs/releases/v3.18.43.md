# v3.18.43 — Clem finishes or asks, never stops blocked; answers arrive first; she learns from her checks

**No database migration** (harness schema stays 95), so this updates in place
over 3.18.42. The Mac build comes from the release workflow (signed and
notarized). The Windows x64 build of the same commit is qualified by the
private Windows pipeline from this tag, **unsigned** until a code-signing
certificate exists.

## A turn ends done or with Clem's question

- **A stop Clem explains is her question.** When a turn has to stop, Clem says
  what she did and what is left, and ends with one question whose answer
  picks the work back up. That turn now waits on your answer instead of
  showing "Stopped here".
- **A review that cannot pass is said, not held.** When the check after her
  work still disagrees, Clem tells you what it could not confirm and asks,
  rather than the turn ending blocked.
- **A workflow that stopped and asks you, asks.** A chat-started workflow's
  ending is written by Clem from the run's report, in plain words; when it
  ends by asking you something, that is how the turn ends.
- **A file Clem fixed in the shell is checked as she left it.** Writing a file
  and then adjusting it with a command no longer reads as the file having
  "drifted" when the turn finishes.

## No more refusal loops

- **A refused call says the real reason and the move that works.** A call the
  app turned away before it ran used to be told "correct the arguments" even
  when the arguments were never the problem, so Clem kept rewording the same
  call. It now names the cause: send it through the tool that carries changes,
  look the capability up again, send it once more unchanged, or stop and say
  what is left.
- **Small local changes run.** A reversible change on this computer that the
  request's plan did not list runs instead of being refused.
- **Clem's own tools are always within reach.** Refreshing a Space and Clem's
  other built-in tools work on every turn.
- **Workflow steps can call Clem's own tools.**

## Answers arrive first, and are checked right after

- An ordinary answer reaches you as soon as it is ready. The same check runs
  straight after; its result shows on the answer ("Checking…", then
  "Checked"), and if it finds a problem Clem posts a short correction in her
  own words.
- Work that changes something outside, plans and memory corrections are still
  checked before they reach you.

## Clem learns from her checks

- When a check catches a problem and Clem fixes it, or a tool call is refused
  and her next one succeeds, she keeps a short general lesson ("When …, …").
  The nearest few ride along at the start of a related request, marked as
  learned from a check, never as something you said. Lessons that would add
  confirmation steps are refused. The Memory tab shows this as "Learning from
  checks".

## Spaces and workflows

- **A Space's data can come from a local file**, re-read on every refresh with
  no model involved.
- **A Space button press is the approval** for the action it runs, sends and
  deletes included; one press, no second card.
- **A creation test Clem already read is not posted again.** Its result used to
  reappear in the chat a few minutes later as a separate report.
- A workflow run's temporary files are never treated as part of what it was
  asked to produce, and a run is held to its target, not to the method a step
  described.
- "Run it once and leave it off" does exactly that.
- Workflow pages, reports and the sidebar use readable names.

## Watches and Home

- **What Clem can see:** watches that look at the sources you choose and bring
  what they find to Home, with a calmer Clem presence there.

## Meetings

- A focused private companion during live meetings, with suggestions you
  direct, private research with selected context, and recap continuity.

## Memory

- Open the exact memory behind a task and correct it safely; saved facts show
  where they came from.

## The apps read plainly

- Today is one calm column with one Needs you and one While you were away; the
  composer stays put while you scroll.
- Automations, Needs you, approval cards and reminders speak in Clem's words,
  without tool names, codes or ids. The phone reads like the desktop.
- An offline computer says it cannot reach the internet, rather than that the
  model keeps dropping.

## Known issues

- Saving a memory can take over a minute when the check disputes how Clem
  worded her confirmation: each rewording is reviewed again before she asks.
- The follow-up correction after a check can run longer than the point it
  corrects.
- The Windows build is unsigned.
