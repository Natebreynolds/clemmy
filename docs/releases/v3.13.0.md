# v3.13.0 — she can ask you now

Release type: behavior release. One capability, restored and then made
useful: the assistant can reach the person she is working for, before she
commits to work, when the answer would change what she does. Root-caused
from two live runs on the previous build that both began substantial work
with no conversation — for two different reasons. Suite at the cut: 9,358
tests passing, 0 failures.

## The defect

The tool for asking the user a question existed, was well built, and was
effectively unreachable on the lane the desktop actually runs.

Schema-on-demand advertises a small set of tools at turn start and defers
the rest behind a search. That set is the acquisition kernel, plus tools
the user literally named, plus a short recall and recently-used tail —
and asking matched none of them. The other brain lane had always
assembled the ask tool unconditionally as a structural tool, so the same
system was capable of asking on one brain and mute on the other. Nothing
detected it, because each lane was internally correct.

The practical effect: to ask a question, the model would first have had
to go searching for the ability to ask, while every tool needed to just
start working was already loaded. It chose the loaded path every time. A
missing affordance reads as a personality flaw.

Compounding it, the tool's description explained autonomous-mode
mechanics and ended by narrowing what it was for — it never taught the
judgment that decides whether a question is worth asking.

## Asking is a normal step now

- **The ask tool is first-class on every lane, every turn**, in the same
  kernel as memory recall and result recall. The framing is deliberate:
  that kernel is how the assistant obtains what it does not already have,
  and the user is a source of information no repository contains.
- **Its description is a decision policy.** Ask when the ambiguity would
  materially change what you do — which account, which records, what
  window, what destination, anything named but unbound. Ask when you have
  hit a boundary only the user can decide. Do not ask what you could look
  up, and do not re-ask what the session settled. If part of the work is
  unblocked, do that part first, then ask once, with concrete options and
  a recommendation first.
- The existing distinction between a clarification and a request for
  sign-off is preserved: in autonomous mode, permission for work already
  requested still resolves itself, because that was never a question. A
  genuine clarification still reaches the user.

## A separate pass decides what is open

The decision to ask cannot be made well by the model that is trying to
finish the task, and it cannot be made from the request text alone. This
release adds a third option.

On a chat turn where the runtime resolved real capabilities, a cheap
cross-family pass considers several readings of the request — holding the
runtime's own facts, which a text classifier cannot see — and reports only
the dimensions where those readings would produce **different results**. A
settled request produces nothing at all. An open one arrives as data with
a floor pointing at the ask tool; the words remain the model's own.

It runs at preflight rather than at the write, because a question about
what the user meant is worth little once execution is under way.

**It can inform a turn and never fail one.** A judge that errors, times
out, or returns anything unparseable resolves identically to silence. The
pass is time-boxed, bounded to three dimensions, and has a kill-switch.

## Pinned against the way this broke

Both live requests are now fixtures. The suite fails if the ask tool ever
falls back behind discovery on any lane, if its description stops naming
the trigger, if the rendered block ever scripts a sentence, or — the pin
that matters most — **if either brain lane runs this pass without the
other.** Lane asymmetry is what hid the original defect for weeks; it is
now a test failure.

## Compatibility

No schema migrations and no new configuration. New optional knobs:
`CLEMMY_TURN_OPENNESS` (kill-switch) and
`CLEMMY_TURN_OPENNESS_TIMEOUT_MS` (default 4000).

Known-open and tracked next: triggering at the commitment boundary graded
by reversibility, letting delegated background work reach the user through
the chat that spawned it, and retiring the preflight vocabulary the
openness pass replaces.
