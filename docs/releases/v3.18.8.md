# Clementine 3.18.8

This patch makes scheduled workflows and long conversations more reliable, removes several places where a simple request stalled or asked an unnecessary question, and fixes two settlement rules that reported finished work as failed.

- Scheduled reads no longer wait on the account reviewer. A saved read with one connected account resolves directly, and a scheduled step's own deadline governs its account review instead of the chat search budget. Platform 49 stopped expiring during provisioning.
- The first scheduled read after a daemon restart works on the first attempt. The reviewed-CLI port now replaces the restart placeholder instead of refusing it and retiring the capability. The Friday dashboard's Salesforce reads no longer fail once per restart.
- Scheduled workflow discovery reaches the connected provider catalog when a step's tool scope is omitted, so a step can find the exact operation it names instead of stopping on a built-ins-only answer.
- A conversation from the same person continues its own thread. Messages that entered through a mirrored session used to open a fresh, empty session each time; Clementine now keeps the audience's conversation and, in a new chat, carries the questions she still has open with that person.
- Created records settle on the provider's own identity. A draft, event or row that comes back with an id, a link and a provider tag no longer marks the run failed for lacking a receipt.
- A Plan turn that runs out of budget publishes the plan it has instead of stopping before publishing.
- An honest failure report settles after one review instead of buying a second identical verdict.
- Clementine attempts a call before asking which connected account, mailbox or calendar to use; the runtime resolves that from remembered defaults and the conversation's established routes. An edit to an existing record uses the account it is read through.
- Long sessions compact between turns on providers that do not reliably serve a cached prefix, keeping every message and the recent tool results while older results stay recallable.
- Discovery journals which sources answered, how long each took, and why a named operation was missing, so a "connector unavailable" reply can be traced to its cause.
- The completion review records which model actually answered when the pinned reviewer was substituted mid-call.
- Plan mode plans and Execute executes, end to end. A Plan turn reasons at medium effort, publishes on the first structurally sound candidate after at most two reviewer send-backs, reports every structural problem in one response, and steers an interpreted collection to a shape Execute can run. Execute revalidates the reviewed steps after a daemon restart, admits the exact reviewed Salesforce CLI call, types a paused batch of approvals as an approval pause, and counts a created record that echoes its content as its own verification.
- Clementine binds a write to the mailbox she reads from when no send default was ever answered, reviewed against the request, so a draft no longer stops to ask which mailbox.
- A Claude sign-in that the keychain is slow to hand back is not an expired sign-in; a CLI-owned credential waits briefly for the CLI's own refresh; a local credential failure pauses a brain for a minute, not fifteen.
- The skill named by the context packet is callable on the Plan lane, and an exact Salesforce CLI identifier acquires even when an unrelated connector is down.
- Default model selections follow the current Codex catalog.
- Hotpatching a locally installed daemon targets the newest installed bundle.
- A Plan turn may exercise a carrier-declared non-destructive call once as a preparation probe and bind the arguments that worked, so a guessed API path fails during planning instead of during Execute; the probe is accounted as preparation, never as a write.
- Act's first Salesforce call is the reviewed CLI: an ad-hoc shell read is admitted, the packet names the reviewed operation, and a shell call for a reviewed operation is refused by naming that operation and its arguments.
- The Codex transport waits up to two minutes between stream frames, journals every transparent retry where the person can see it, and falls over to the next brain on a dead socket instead of stopping the turn.
- A mid-conversation "remember …" binds every later request in that conversation; it grants no write authority.
- Reviewed plan identity is compared once, the same way at publish, revalidation and admission, and an Execute that stops before its first model call does not consume the revision.
- A Plan continuation after a question keeps the disclosures the earlier turn already made.
- A generic provider call the carrier declares non-destructive is answered by the harness instead of minting an approval card; sends, deletes and workflow checkpoints still card.
- Publishing a plan reports every structural problem in one response, assigns a missing step id from position, and the plan card arrives with a one-line reply rather than a second copy of the plan.
- The heartbeat names only toolkits the request or a search actually named.
- Extended thinking on the BYO wire is never switched on by a harness effort tier.
- The stop message names only the newest failed tool result; a published outline is reported as published with its gaps; the verification note is one plain sentence.

Known open at this tag: a mobile-queued send still parks on a card (pin left red by decision); a Codex-family judge pin is unreachable under BYO all-in routing (pin a Claude judge, or extend the all-in exception); the Plan probe has passed the consent and settlement pins but not yet a full live Plan→Execute run.

Available for Apple Silicon and Intel Macs. This patch preserves the Home and chat experience shipped in 3.18.6.
