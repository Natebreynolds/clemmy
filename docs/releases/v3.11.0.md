# v3.11.0 — the fast-run release: waste removed, truth surfaced, validated against a real failure

Release type: reliability + performance release. Every change was
root-caused from one live client-class run (a 50-firm scrape that took 40
minutes and was cancelled) and is pinned with that run's own recorded
inputs — then re-proved against other vendors, because the fixes key on
verbs and shapes, never on providers. Suite at the cut: 9,344 tests
passing, 0 failures. All commits are independently revertable slices.

## Speed: the mechanical waste is gone

- **A timed-out job start keeps its provider run.** Aborting never stopped
  the provider — it only discarded the response carrying the run id, so
  paid work became invisible and was re-bought. Job-starting calls
  (RUN/ACTOR/TASK/CRAWL/EXPORT/…, verbs not vendors) now survive their
  timeout; the call's own receipt detection parks the job with the
  watcher, which delivers the real result. The corrective says "still
  running, already billed — do not start a fresh one."
- **Blocking sleep is refused.** `sleep 75/90/115` — five minutes of a
  40-minute run spent deliberately doing nothing. A command whose only job
  is waiting is refused with the recovery: the job is watched, results
  arrive automatically, continue or end the turn.
- **Dispatch width follows the provider, not a guess.** Program tool
  dispatch was pinned at a flat 8 for every provider; it now starts
  24-wide, halves on the provider's own 429/Retry-After, and re-widens as
  clean results accumulate — the same reactive mechanism the batch runner
  already used. Worker wave sizes are deliberately unchanged (those caps
  are cost-bound, not guess-bound).
- **Schema-first dispatch.** A first-use action loads its real provider
  contract once per session, so a missing required field is refused
  locally, naming the field — instead of a paid provider 400 plus a model
  turn to recover.
- **Guidance and enforcement agree.** The pre-turn fan-out directive told
  the model one lane while the read-fanout rail refused toward another —
  the model obeyed and was punished for it. Both now carry the same
  discriminator (same-shape reads → one program; per-item reasoning →
  workers; bakeable writes → batch), with an invariant pin that fails if
  they ever diverge again.

## Truth: a run can tell you what happened

- **Billable provider jobs are named in the run report** — how many were
  started, on what family, and how many have no confirmed result yet. No
  more discovering spend from the provider's own dashboard.
- **A delegated run parked on approval says so** — amber "Paused — waiting
  on your approval" with the pending subject and a link, replacing the
  optimistic "Working on this in the background" that made six blocked
  minutes look like progress.
- **A repeated CREATE is told it already exists** — the model is pointed
  at the object it already built (advisory, never blocking) instead of
  recreating it and losing track of its own deliverables.

## Autonomy: fewer interrupts, not weaker rails

- **Credential reads are refused, never turned into an approval.** Reading
  API tokens/.env/vault files is a question whose answer is always no —
  so an autonomous run is no longer stopped to ask it. The secret never
  enters the model's context, and the corrective steers to the
  already-authenticated connection. One approval path removed.

## Validated, not asserted

- **The failed run is now a test suite.** `failed-run-replay` replays that
  run's literal slugs, shell commands, and payloads against the current
  harness and asserts every waste handled — then asserts the same for
  non-Apify vendors, pinning the class rather than the anecdote.
- A dormant suite time-bomb was found and defused: frozen fixture dates
  had begun expiring against production code that reads the real clock,
  turning one test red and its sibling vacuously green. Both are now
  time-relative; a scan found no other instances.

## Deliberately NOT in this release

A pace advisory ("you've been running 30 minutes — consider delivering a
partial") was built and reverted the same day, on principle: elapsed time
is the user's information, never pressure on the model. Time pressure
invites rushed, worse work; method guidance ("batch these") already
belongs to the fan-out rails. The user's surfaces (card clock, run
report) carry the pace.

The remaining latency — model deliberation across many small steps — is
architectural and is the next milestone (graph-provisioned parallelism,
splitting the compose_reply core), not a patch.

## Compatibility

No schema migrations, no new required configuration. New env knobs (all
optional): `CLEMMY_CODEMODE_CONCURRENCY` now sets the adaptive ceiling
(default 24). Known-open items tracked for the graph milestone:
compiler-provisioned fan-out, mega-core split, chat-run resume/dedupe,
pinned-goal provenance, steer notes into running background tasks.
