# v3.14.0 — the prompt stops rebuilding itself, and the question arrives first

Release type: performance + behavior release. Two live runs on the previous
build failed for two different reasons; both are fixed here, along with a
prompt-cache defect that was quietly taxing every turn of every
conversation. Suite at the cut: 9,372 tests passing, 0 failures.

## The prompt cache stops rebuilding on most turns

The advertised tool set was recomputed every turn from the tools the user
happened to name plus a recently-used tail, so it drifted: live sessions
show 4 → 5 → 8 → 10 tools, and one that shrank from 8 to 7.

Tool definitions sit first in the cache hierarchy, so **any** change to
them invalidates the tools block, the system prompt, and the entire
message history. The practical effect was that most turns of most
conversations rebuilt the whole prompt cache and re-paid the persona, every
tool schema, and all prior messages at ten times the cached rate — with the
latency that implies. Measured hit ratio across a long session sat near
0.88 with dips to 0.74 at exactly those boundaries.

The monotonic floor that prevents this already existed, and its own comment
cites the vendor documentation; it had been wired into one of the two
tool-selection paths and not the other — including the path the desktop
actually runs. The floor only ever grows, so the tools block converges to
byte-identical and then holds for the rest of the session. Ordering is
deterministic by construction, since the advertised list is built by
filtering a stable array rather than iterating a set — non-deterministic
tool ordering is the other documented way to break the same cache.

## The question now arrives before the work, not after it

Two fixes to the openness pass introduced in the previous release, both
found by running real tasks:

- **It never ran on a novel request.** It was gated on the turn's resolved
  capabilities carrying a write effect — but capability resolution only
  produces entries when a *proven* procedure matches. An unfamiliar request
  resolves to nothing, so the pass stayed silent on precisely the requests
  that are most ambiguous. Either signal now suffices, on both lanes.
- **A certain unknown no longer waits on a model.** When a request names a
  destination but never says which instance — two connected mail accounts
  and no account named — the runtime already knew that before any tool ran.
  That now goes directly to the pass, leads the list, and survives a judge
  that errors or times out, because it was never an inference.

The failure this fixes, in full: a request to pull stale accounts and draft
emails read the outbound playbook, queried the CRM, and enriched every
account across six agents — then every draft failed at the last step with
"you have 2 accounts connected, so I need to know which one to use." That
flag was set before the first tool ran. The question that ended the run was
knowable at its first instant.

## Where the tokens go is now visible

Every turn records what occupied its prompt, split by whether it can be
cached: persona and tool schemas as stable (large is fine when invariant),
the per-turn packet, history, and message as variable (must stay small),
plus a share figure and a tool-schema count — a real prompt cost that no
existing telemetry captured. Observation only; it reads what is already
being sent and changes no byte of any prompt.

This exists because per-step cost is prompt assembly paid once per step and
therefore roughly a hundred times per task, and every proposal to cut it
was a guess. Measured on a real run: nineteen minutes wall clock, about one
minute of tool execution, the rest spent thinking between roughly a hundred
steps.

## Compatibility

No schema migrations, no new configuration. The tool-set floor honours the
existing `CLEMMY_JIT_MONOTONIC` kill-switch.

Known-open and tracked: a delegated background task still cannot reach the
user with a question; activity cards render an attempt and its settlement
as peer rows, so a clean failure can read as contradictory; and the Claude
lane still has no reasoning-effort control while the other lane tunes it by
complexity.
