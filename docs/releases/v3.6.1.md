# Clementine v3.6.1

Release notes — 2026-08-01

This patch publishes signed and notarized macOS artifacts. A Windows artifact
is not included because the production Windows signing identity is not
configured; the release uses the repository's documented `[mac-only]` path
rather than publishing an unsigned installer.

## What this patch fixes

Some upgraded installations could reach the daemon's nominal ready point and
then stop answering the console, Discord, Slack, and mobile health routes. The
failure was global event-loop starvation, not a channel-specific chat bug:
startup maintenance synchronously waited on legacy workflow lock evidence,
while speculative CLI discovery could synchronously walk a very large PATH.

v3.6.1 moves those operations behind explicit runtime boundaries:

- Broad workflow recovery and drain inventories use atomic point-in-time run
  snapshots. A busy or damaged record cannot make a maintenance scan block all
  channels; every later mutation still takes the strict record lock and
  re-reads authoritative state.
- Workflow lock owners are fully written and fsynced before one atomic rename
  makes them visible. Interrupted older owners that are exactly zero bytes can
  be reclaimed after a bounded ambiguity grace with directory-generation
  fencing, including when an old PID has been reused. Nonzero malformed,
  multiple-owner, and unexpected evidence remains fail-closed.
- CLI discovery now performs asynchronous metadata reads, yields between
  bounded batches, and single-flights concurrent warmup/dashboard/tool calls.
  Its cache uses unique atomic temp files, and speculative warming begins only
  after ingress is ready.
- Canonical tool-memory migration runs once at explicit daemon or standalone
  webhook/Discord/Slack startup boundaries and records a durable marker.
  Recall, list, MCP selection, and prewarm paths are read-only; already-migrated
  v3.6 homes are adopted without rewriting their alias/procedure corpus.
- A terminal desktop readiness failure stops and reaps a still-live daemon
  before Electron opens its synchronous error dialog, so a modal cannot strand
  a child behind attached stdout, stderr, or IPC pipes.

## User-visible result

- Console health and connected channels remain responsive while workflow
  recovery, CLI inventory, and memory maintenance run.
- Discord, Slack, webhook, console, and mobile continue to share one daemon and
  one accepted-source/retry contract; this patch does not add a channel-specific
  bypass or a second execution harness.
- Local CLIs remain available on demand even when the optional warm-cache
  optimization is disabled. `CLEMMY_CLI_DISCOVERY_WARMUP=off` and
  `CLEMMY_MCP_PREWARM=off` are recovery switches for speculative warming only;
  they do not remove tools or change graph authority.
- `CLEMMY_CONFIRM_FIRST` remains the irreversible same-shape batch-write safety
  boundary. The retired conversational `CLEMMY_CONFIRM_BEAT` mechanism is not
  restored.

## Compatibility and rollback

This patch does not advance the v3.6 memory or harness schemas. Existing v32
homes remain compatible with v3.6.0, although rolling back also restores the
older startup behavior. Legacy tool-choice aliases remain readable even if the
explicit canonical migration cannot finish.

## Release verification

The production-home acceptance used a copy-on-write clone containing three
real legacy zero-byte workflow owners. The patched daemon reached ingress in
about five seconds and remained responsive past the prior 90-second desktop
failure window without deleting those locks. Repeated probes across workflow
lane ticks all returned HTTP 200. With default CLI warming enabled, a PATH with
1,769 executables produced a 1,730-CLI cache while health remained responsive.

The clean release worktree passed 8,283 isolated tests: 8,282 pass, zero fail,
and one documented platform skip. Additional release gates passed public
hygiene 3/3, release assets 40/40, startup-focused tests 114 pass with one
platform skip, expanded workflow tests 198/198, policy protections 9/9, memory
evaluation 29 scenarios at 100% pass@k/pass^k, strict pass-k 9 cases at 100%,
strict jobs 5 cases at 100%, plus clean root and desktop typechecks.

## Clementine 4 follow-up

v3.6.1 is a release-quality liveness patch, not the full Clementine 4 graph
runtime. The next hardening step is to consolidate the remaining exact-key
dedupe and background-transition locks behind the same crash-safe primitive,
then continue replacing orchestration ceremony with graph-owned intent,
capability, context, effect, reducer, and terminal nodes.
