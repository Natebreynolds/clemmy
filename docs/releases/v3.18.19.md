# v3.18.19 — an interruption is bounded across restarts

Release type: one defect-class removal, root-caused from a live 43-hour loop on
the owner's machine and shipped with that failure replayed as its pin.

## The defect

A Plan->Execute turn — *"Execute this reviewed plan exactly and verify the saved
result."* — was interrupted on 09-20 at 04:44Z and then **re-admitted 3,292
times over 43 hours**. It never completed, never gave up, and never told its
owner, while reporting `resumable: true` about a frame that had already failed
thousands of times.

The hourly shape names the mechanism exactly: claims ran at **5x the
daemon-restart count** and exhaustion skips at **1x**. Every restart handed the
dead checkpoint five fresh attempts. The daemon restarted 135 times in that
window — almost all clean `SIGTERM`, not crashes — so the bound was zeroed 135
times.

That is the re-entry budget working exactly as designed and pinned: *"a new
checkpoint (progress) starts a new count, and a restart starts over, so a
genuinely transient store failure is never permanently terminalized."* Both
properties are correct. Together they mean nothing bounded the **interruption**.

The notice was honest and useless: it promised *"it will be retried after the
next Clementine restart"*, and the restart arrived every ~20 minutes. The typed
stop's only next edge was the thing that erased it. Because the "one-time"
notice Set is process-local too, the owner received **59 copies** of it.

## What changed

A bound that is orthogonal to that counter and **durable**: an interruption
whose re-entry budget has already been spent once — this engine's own record
that the frame stopped advancing — and which has been re-admitted past a ceiling
read back out of the log, stops being re-admitted and commits the honest
terminal that already existed (`needs_input`, resumable, `needs.kind='continue'`).

Three deliberate choices:

- **It counts attempts, not wall clock.** A machine asleep for three days must
  not spend a recovery window that never got to run.
- **It requires the prior exhaustion first**, so work that is genuinely
  advancing is never terminalized by an attempt count. Pinned both ways: a spent
  frame stops with zero dispatch, and a 40-re-admission frame with no spent
  budget still gets its turn and keeps its recovery state.
- **Its reply does not say "pick up where it left off."** That would over-promise
  an exact resume of a frame that never advanced. It says it stopped retrying,
  that nothing was lost or repeated, and that `continue` takes it from there.

It engages on the first tick of a fresh process, before the in-memory counter
can be spent, so the 59-notice repetition ends with it. Nothing here adds a
dispatch; it only withholds one.

Pre-flighted read-only against the live stuck session before shipping: budget
already spent `true`, durable re-admissions `25/25`. Confirmed still looping at
00:57Z on the restart before this release.

## Also carried

An efficiency wave from the engine owner, written after the v3.18.18 tag:
**proven-operation skip plus a staged tool surface** — when an operation is
already proven, skip discovery and hand the brain a bounded pre-staged schema
set rather than the whole catalog (`active-tool-surface.ts`,
`active-surface-heartbeat.ts`, `proven-operation.ts`). Fail-open by
construction: *"a miss leaves discovery unchanged."* It targets the measured top
cost on this machine — 8.2 model calls per turn, ~5 brain round trips, the brain
averaging 20.4s and 34,076 input tokens per call, 87% of all model time.

## Known red, carried forward

`tool-catalog.test.ts` — *"an explicit no-run workflow read does not expose the
immediate queue control"* — fails, and already failed in v3.18.18. It is a
genuine design conflict, not a regression: the assertion (2026-08-24) encodes a
minimal hot-set surface, while `6778d1b6` (09-20) added `workflow_run` and
`workflow_get` to the always-loaded acquisition kernel. Removing them satisfies
the assertion and immediately breaks the next one, and it would cost prompt-cache
stability, which is where this machine's token waste actually lives. Left for an
owner decision rather than resolved by weakening either side. That same commit
also silently killed the watcher fan-out re-arm pin, restored in v3.18.18.
