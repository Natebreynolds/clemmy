# v3.18.27 — Clem helps you set up, jobs end with a direction, workers do the work

Mac-only release. Harness schema 92 → 93 and memory schema 36 → 37 (one way:
reinstalling an older app does not take the databases back). Qualification and
live evidence below are recorded as measured; signed and notarized artifacts
come from the release workflow and are not claimed here.

## What changed

### Clem helps you set up Clementine

- Clem knows what is set up and what is not: the main model, a second model to
  check her work, Jev, meeting recording, connected apps, MCP servers, phones,
  phone alerts and the calendar watch, and what each one gives you. Ask how to
  set something up or where something is and she answers with a link that
  opens that place ("Open Meetings"); a request that needs something missing
  says what to set up.
- From Clem reads in order: what waits on you first, with her answers to tap,
  then updates, then the one part of Clementine worth setting up next. The
  phone shows the same groups and answers as the Mac.
- A home nobody has set up shows no failures: the calendar watch stays quiet
  until a calendar is found, Noticing and scheduled jobs wait for a model, and
  a check that failed shows when it looked, never a raw error.

### Jobs, lead agents and workers

- A project can name a lead agent. Clem hands it whole jobs; the lead plans,
  fans out its own workers and checks in on the conversation that handed it
  the job. In a project with a lead, Clem still does quick work herself, and
  does a piece herself when you ask her to.
- Workers can run requests their lead already learned are reads, discover and
  call the tools the lead leased them and, in Auto, make those tools' outside
  changes as the lead would (never admin actions). The host's record of what a
  worker actually did rides beside its result, so a worker's own account
  cannot pass off work that never ran, and a success with no real work is not
  counted. A worker gets the facts of a sibling item its own item refers to.
- One job card everywhere, desktop and phone: the checklist first, the next
  step with its control, the latest update, files by name and the report.
  No job ends without a clear direction: a stopped job says what got done,
  what is missing and the one decision it needs, in words.
- In a job handed to an agent, only your own words allow or refuse a
  connector, including words in a later change to the job. A shell safety
  refusal closes that route only, not the job. A step that used up its own
  time budget continues; answering a job's question resumes it; a brief
  provider refusal is waited out; an account out of usage or credit is named.
- A run settles the work items it finished from its own proven calls, and a
  refused work declaration is owed only until its accepted retry.

### Cards and approvals in Clem's words

- Every approval card reads like the question card: her question, why, the
  exact content under "Exactly what happens", and answers to tap. Needs you,
  Home and the phone use the same words; a reopened card reads as it did live;
  a decided card leaves the chat. The dashboard script permission card asks
  in plain words. Deleting a workflow you ask for reaches you as one card.
- Standing approval answers only a yes/no; a choice between ways forward
  reaches you. Installing or signing in a command-line tool is local work.
- When an MCP server does not say what its tools do, Clem proposes which ones
  look things up, which change things and which still ask every time, and you
  approve once.
- Content that tries to steer Clem (instructions hidden in a page, a file or
  an email) is reported to you, not followed or silently ignored.

### Models

- A conversation switched to an agent pinned to a model answers on that model.
- A model the provider refuses for your sign-in stops in words and is no
  longer offered; a reasoning effort a model refuses is replaced by the
  nearest one it takes.
- A new Quick checks role (a fast model of the main model's family) runs
  Clem's small interpretation checks, with a deadline that falls back to the
  main model; Settings › Models shows it on the Mac and the phone. The full
  completion review is kept for writes at stake, and Settings names the
  checker that actually runs.
- Tools named with an `mcp_` prefix no longer make Claude bill a request as
  extra usage.
- The tool list stays steady within a conversation and a judge retry sends
  the compacted conversation, so prompt caching holds across turns.

### Memory

- What you ask Clem to remember is reviewed against your own words and kept
  with a durable receipt; a correction replaces the exact saved fact in its
  own scope, and Clem says it is saved only once memory shows it.
- That review applies to memory you state, not to statements Clem decides to
  keep on her own, so ordinary turns are not held for it.
- A correction your own message already made (the old fact retired for your
  new words when the message was saved) counts as made. Clem no longer tries
  to correct it a second time, and a correction that really cannot be
  confirmed stops with plain words.

### Browser

- With Browserbase set up, the cloud browser is Clem's browser and local
  Chrome is the fallback. A task owns its browser; the live view follows the
  page Clem is on, on the desktop and the phone; every open browser is listed
  in one place and can be handed to another conversation; sign-ins carry over
  for one browser at a time.
- A key Browserbase refuses is caught when saved and explained; Browserbase's
  regional connect addresses are accepted; a local Chrome that never answers
  says why and is proven to have changed nothing.

### Files Clem saved open beside the conversation

- A saved-file card is the way in: tap it and the file opens in a panel
  docked beside the conversation, like the browser, while the conversation
  stays open and usable. This works wherever Clem saved it, a project folder
  included; before, a file outside Clem's own folder lost its Open button.
- Markdown reads formatted, other text as text, pictures as pictures, and a
  page in a project in the page viewer in the same panel. "Open in its app"
  opens documents on this Mac, never scripts, apps or installers.
- Only files the record says this conversation (or its workers) wrote can be
  shown, found by the name and folder on the card: never another
  conversation's file, a sensitive file or a link to some other file.

### Phone and desktop

- Phone: conversations live in the menu with a live mark (working, or a new
  reply), running work stays visible after you leave, one style of round
  button at the top of every screen, a slim composer, lists that read as
  words, swipe left to pin or archive, and updates as formatted reports.
- Desktop: the same live marks, Needs you named in words, content
  fingerprints replaced by "Locked to this exact version", workflows and
  models named in words, and only a failed delivery stands out.
- Live check-ins stay with their task on the desktop and the phone.
- Reopening a conversation no longer shows a helper from a finished turn as
  "Working on this in the background".

### Reliability

- Fewer "I could not reopen the saved checkpoint" stops: a local change whose
  outcome is uncertain (for example a shell command that wrote a file and then
  timed out) is saved and shown to Clem, who checks state and continues; an
  MCP result whose structured copy wraps its text is a success. When a stop
  does happen, its reply is always published and the run closes.
- Recovery after a failed command may look at the local files again; a reply
  still being worked on says so in plain words.
- `write_file` can replace one exact passage of a file, keeping its prior
  bytes.
- Reading a database with a stream redirect is no longer mistaken for a write.
- The desktop shell: a shutdown step that never finishes no longer keeps the
  app from quitting, and the Browserbase live view no longer shows a blank
  frame. These two arrive with this signed build; they were not hotpatched.
- Phone pairing and relay checks report actual readiness.
- Storage: exact retained histories are prepared outside the writer lock and
  the learning backlog is inventoried. No history is converted and the
  database does not shrink in this release.

## Known limits

- The Claude SDK brain lane is frozen and not used for chat in production
  (every brain, Claude included, runs on the host engine). Its memory test
  fails: that lane can say "Saved" while a memory capture is still pending.
- When a turn does stop, its reply can still show internal checkpoint lines
  ("Retained work (durable checkpoint) … rh_…"); a rewrite in Clem's words is
  next.
- A main model that guesses a tool argument the tool does not take (a text
  `query` on the output query, a size cap on a web read) costs one round
  before it retries correctly.
- Browserbase's live cloud acceptance is partly owed; local Chrome may ask on
  the Mac before it allows remote control.
- Physical iPhone, dark theme and long-pause resume on a real run are not yet
  checked live.
- CI's unit-test job is still red on one journey, the ordinary-conversation
  expectation (greetings, acknowledgements and arithmetic in one request),
  as in v3.18.26; local journeys are run separately.
