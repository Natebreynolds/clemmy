# v3.18.49 — an agent's work is a card you can follow, a hand-off is judged as a hand-off, a tapped option is an answer, and a saved memory counts

**No database migration** (harness schema stays at 99). The Mac build comes
from the release workflow (signed and notarized). The Windows x64 build of
the same commit is qualified by the private Windows pipeline from this tag,
**unsigned** until a code-signing certificate exists.

## Handing work to one of your agents, end to end

- **Say "have Design Studio build a quick landing page" and follow it.** Clem
  hands the job off in about twenty seconds, the agent runs as itself with
  its own model and the tools you listed on it, and the result lands back in
  the same chat. "How is it going?" mid-run is answered from what the agent
  has saved so far. "Ask Design Studio to change the headline" becomes a
  follow-up task for the same agent, with its own report back.
- **The tools you list on an agent now reach its turns.** A file written by
  the team tools names them as `allowedTools`; the product read a different
  field and pinned neither, so an agent with nine listed tools ran on the
  default surface.

## One card for background work, on Home and in the chat

- **Home shows a Working now card for every job still moving**: who is on
  it, the phase, its check-ins, and Steer and Stop. It is the same card the
  chat draws, so there is one job card everywhere. The pane retired to the
  Tasks board on 09-26 is back after Needs you.
- **In the chat, Background work stays open while it runs** instead of
  folded away under a header.
- **The header pill names the agent and the step** ("Design Studio · Running
  1 call") and opens the Working now cards when clicked, instead of the
  board. The entry behind it carries the agent's name and the step; before,
  it showed a bare title for the whole run.

## A hand-off is judged as a hand-off

- **"Design Studio is on it, I'll report back" is no longer corrected after
  delivery.** The check that runs after an answer read the deferred result as
  a promise and rejected the reply; Clem then offered to build the page in
  the chat instead. The host record of the jobs a request started now rides
  with the review rules, the fast check's own criteria count a recorded
  hand-off as delivered, the hand-off's receipt counts as the turn's outcome,
  and the reviewer sees the hand-off's own contract.
- **A review that runs after delivery waits longer for Jev** (up to six
  seconds). Nothing waits on it, and it timed out at its old cap twice while
  a just-dispatched agent's own calls were in flight.

## A tapped option is the answer

- **Picking one of the options Clem offered settles the question without a
  model call.** On a loaded machine the completeness check failed and the
  tap was held three times with "Your reply is recorded. I couldn't verify
  how it changes the pending question." The host wrote those options; the
  person picking one is a complete answer by construction. Another wording
  still goes through the check.

## A saved memory counts

- **"Commit this to memory …" ends done when the save landed.** The explicit
  save superseded the older rule and the next turn found it, yet three
  reviews returned no memory packet and the turn ended "I could not confirm
  that your correction replaced what I had saved before." The memory tool
  now heads its result with a host receipt naming what it did and the fact
  it left active, and the completion check reads that receipt as storage
  evidence. An exact correction keeps its bound proof.
