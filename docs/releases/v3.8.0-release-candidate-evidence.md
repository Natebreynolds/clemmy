# v3.8.0 release candidate — closeout evidence

Branch `codex/v3.8.0-release-candidate`. This document covers TWO review
rounds: the first closeout (base `0c088733`, candidate `828b2680`) and the
second review's NO TAG findings (base `ec9b73ca`), all closed in the commits
listed at the end. Sections below describe the CURRENT tree; superseded
first-round claims have been corrected in place. Verdict and frozen SHA are
at the end — nothing above them claims release readiness.

## A. Verified procedural memory

**There is exactly one learning path, and it is a pipeline.** Governed
settlement (after `detectComposioFailure` and async job-receipt resolution)
verifies the FINAL payload through the one settled-read verifier — which also
rejects nested error envelopes (`data.error`, `result.error`, `data.errors`)
— captures the accepted source/attempt/account/evidence digest while they are
live, and appends ONE durable pending-learning row. The bounded worker
(`src/memory/learning-worker.ts`, armed post-settlement and by the daemon
heartbeat) owns everything after that: catalog acquisition, the typed
`read_receipt` (re-resolved BY ID with EVERY binding validated), procedure
and alias materialization, the exactly-once claim (consumed only after all
writes commit — a transient failure retries after restart), and embedding.
Nothing expensive runs on the user-visible tool return.
`maybeAutoRememberComposioChoice` no longer writes memory at all — the legacy
path that persisted historical invocation arguments is retired, with its
outcome accounting preserved.

**Typed receipt only.** A 4xx/5xx payload, a thrown dispatch, a
queued-but-unresolved handle, and an unverified body all decline — each pinned
black-box through the real gateway in
`src/runtime/read-path/verified-memory-closeout.test.ts`.

**Identity.** Receipt identity IS its bindings — owner (machine+home),
session, accepted source, attempt, identifier, stable account, schema
fingerprint, evidence digest — so identical payloads from two accounts are
two receipts, and the learner validates every binding against what it
settled. The exactly-once claim keys on
`{sessionId, sourceUserSeq, identifier, account}`. Alias rows key on
`(phrase, scope, identifier, account)`; candidate identity is
`(identifier, account)` end to end, both brains' cards name every distinct
provenance, and candidates survive brain fallover.
Deliberate design call: `userId` is NOT a retrieval partition — a daemon is
one human across surfaces (desktop↔Discord parity), and partitioning by
per-surface user ids would break exactly the cross-surface reuse this feature
exists for. The install (machine + home) is the privacy boundary.

**Live schema contract, fail-closed both ways.** Learning binds the live
per-identifier contract (fetched by exact slug in the worker when the cache
is cold) and declines without one. Retrieval requires LIVE catalog authority
for every schema-bound candidate: an empty or expired process cache DECLINES
the candidate until the catalog reloads — validation that cannot run never
reads as validation that passed — and a moved contract declines until a
fresh settlement re-proves it.

**Turn-bound delivery.** The phrase-keyed global cache is deleted. The bridge
resolves candidates once per accepted turn and binds them ON THE REQUEST;
the Codex lane threads them through the agent build options and the Claude
lane reads the request directly. The predecessor-red proof is an ESTABLISHED
session (prior turns recorded): both brains rank tools against the joined
conversation query there, so the phrase-keyed side channel silently missed —
red at 0c088733, green now
(`src/runtime/read-path/capability-routing-production.test.ts`).

**Candidate card.** Both brains receive a bounded (≤5 line, ~289 byte)
advisory card: kind, exact identifier, intent, provenance (how it matched,
which account proved it) — never prior invocation arguments. Pinned in both
lanes, including the no-argument-leak assertion.

**Aliases one-to-many.** PK `(alias_digest, scope_digest, identifier,
account_identity)`; exact lookup returns every row; the store-level class
CHECK, tamper digest, and scope isolation pins all still hold
(`src/memory/capability-alias-index.test.ts`, 11 tests).

**Durable embedding backfill.** Rows missing a vector ARE the queue (they
persist in SQLite until embedded); settlement arms a debounced drain, boot
warm is the backstop. A paraphrase learned mid-life retrieves on the next
turn with no restart — pinned with a unique-slug isolation so nothing
pre-warmed can fake the pass.

**Measured retrieval cost** (this machine, local `bge-small-en-v1.5`):

| mode | p50 | p95 | hits |
| --- | --- | --- | --- |
| cold (nothing learned) | 0.0 ms | 0.2 ms | — (no candidates, no cost) |
| assisted paraphrase | 3.0 ms | 5.1 ms | 40/40 |
| exact repeat | 2.7 ms | 4.4 ms | 40/40 |

Model load 381 ms warm-cache (machine-level weight cache; first-ever download
~6.9 s measured previously). Candidate card 289 bytes. The deadline cap on the
semantic tier is 120 ms; a cold model degrades to the lexical tier and warms
in the background.

## C. Production durable fan-out

**The seam.** `dispatch_background_task` gained an optional typed `manifest`
(canonical item ids, phases, missing-required-inputs) — the brain's own plan
carries the disposition; there is no second classifier call and no phrase
heuristic. Missing inputs return ONE typed clarification. Placeholder item
ids, duplicate phases, and cycles are refused at admission (pre-existing
pins in `work-disposition-integrity.test.ts`).

**The journal.** `src/execution/durable-fanout.ts`: an immutable plan
contract (full normalized disposition JSON) plus one SQLite row per
item×phase, written in one transaction. Identities are digest tuples.
Settlement is a CAS — a terminal `done` cannot regress, a retry observes
`alreadySettled`, and a settlement for an item the plan never named is
refused.

**The scheduler is the mature one, and windows are claimed authority.**
Windows are claimed atomically (status CAS + generation bump) BEFORE task
creation and compile into real durable `BackgroundTaskRecord`s marked
INTERNAL — no per-window chat report-back, notification, or focus flip; the
user's contract is plan-level (one kickoff, aggregate progress, one reducer
terminal on the route persisted with the plan). The settle/list tools
authenticate the calling worker's run session against its claimed window:
one worker cannot settle another's items, and a dead generation's authority
cannot settle into the re-claimed window — proven across a real
child-process death. Plan identity is the complete normalized contract plus
the accepted activation (two manifests in one turn are two plans; a
byte-identical retry rejoins); ledger identity is encoded tuples (the
delimiter forgery is pinned dead); phase dependencies are enforced AT
settlement.

**Reducer.** Readiness is a query over the journal, never a caller array.
The lifecycle is ready→leased→admitted→running→completed/failed, driven by
the reducer task's REAL scheduler terminal: admission is never recorded as
completion, a failed reduction retries under a bounded recoverable lease
(then fails the plan honestly, settling the plan-level focus action to
needs-attention), and the reducer pages the FULL settlement journal through
`fanout_list_settlements`. Reconciliation runs on the drain cadence, not
only at boot.

**Concurrency.** The drain's process-wide boolean guard became durable
capacity: a drain tick claims `policyCap − running` tasks, measured against
the durable running count. Two ticks landing while work is pending drive two
workers that genuinely overlap; the cap still bounds thrash.

**Proven at scale** (`durable-fanout-production.test.ts` — the replaced-model
worker has NO journal powers: it reads its own window through the authority
API and settles item by item through the authenticated path): 40, 120, and
514 items execute through claimed bounded windows, overlap where >1 window,
and reduce exactly once with the reducer riding the origin route. The crash
test settles 17 of 40, dies mid-window, reconciles, completes the remainder
with byte-identical timestamps on pre-crash settlements. A REAL child
process settles part of a window, dies, and the parent process re-claims at
a higher generation, refuses the dead generation's authority, completes, and
reduces exactly once.

**Explicit background without a manifest** compiles to the canonical one-item
durable contract — one item and five hundred ride the same machinery.

## B. Exactly-once continuation

**Transactional CAS, mandatory and adjacent.** Handoff records live in
`src/execution/handoff-store.ts`: ladder check, revision CAS, and write are
ONE immediate SQLite transaction. `expectedRevision` is MANDATORY on every
production transition; transitions move exactly one rung; same-rung rewrites
are refused; `terminal` is the one abort edge reachable from any rung.
Worker ownership is deliberately NOT a rung — the worker starting and the
foreground committing are concurrent and unordered, so it is a separate
idempotent durable fact (`owner_active_at`) with the derived state preserved
for readers. The background task id is RESERVED inside the handoff
transaction (derived from the accepted attempt) and materialized
claim-or-rejoin, so two processes admitting one transfer contend for one
durable task. Every refused write is handled; a bare `requested` row
recovers from its accepted event and durable goal. Proven under 8-way
single-revision contention and two OS processes contending rung by rung,
plus the rung-by-rung child-process crash matrix
(`handoff-exactly-once.test.ts`).

**Order is the invariant, and readiness is honest.** Detach writes the
durable transfer intent and capsule BEFORE the fence; the COMMIT FENCE
itself is written where the foreground actually stops — inside the single
terminal-commit authority, for both brains, after the final model/tool
boundary. Boot AWAITS handoff reconciliation before interrupted-chat
recovery and before readiness, and a handoff-store failure fails readiness
closed.

**Capsules are interval-scoped, revisioned, and re-checkpointed.** Capsules
project from the exact accepted ACTIVATION INTERVAL (an earlier unrelated
exchange's receipts stay out), carry a monotonic revision with self-digest
integrity, and re-checkpoint at every durable lifecycle boundary — item
settlement, effect settlement (the learning worker's committed receipt),
park/correction, terminal. The worker binds on capsule identity + revision:
it follows a legitimately evolved capsule, parks on tamper, and parks on
rollback (`capsule-lifecycle.test.ts`).

**Transferred is structural.** `transferred` is a first-class terminal
status in the outcome taxonomy, committed by both brain reducers, naming the
background task — and a handoff that never produced an owner is NOT reported
as a transfer.

Suites: `handoff-store.test.ts` (6), `handoff-production.test.ts` (extended),
`continuation-integrity.test.ts` (kept green through the store swap).

## D. Unified activity

**The senders consume the reducer.** Both channel transports
(`runDiscordHarnessConversation`, which Slack also rides) drive their
placeholder/edit/final lifecycle through `createChannelProgressLane`: the
shared `reduceTransportProgress`/`applyTransportProgress` decide kickoff, the
20-second rate-limited milestone edits, and the single final replacement, fed
by `projectRunSnapshot` over display-state phase + the durable attempt row's
lease. The caller-less `nextSlackProgressAction`/`nextDiscordProgressAction`
wrappers are DELETED. Labels carry bounded phases, never tool names or
arguments.

**One server projection.** `projectActivitySnapshot`
(`src/dashboard/activity-projection.ts`) returns workflow runs, background
tasks, and live chat attempts in one typed list (schema version + per-entry
monotonic revisions derived from durable seq/updatedAt). The console route
serves it; `?workingNow=1` applies the server-side gate so ordinary
foreground chat stays inline and only detached/scheduled/long work surfaces.
Liveness derives from leases (`deriveRunLiveness`): a 90-second-quiet call
with a live lease stays live; an expired lease renders needs-attention; no
served field combination turns an unresolved terminal green (pinned).

Suites: `activity-projection.test.ts` (incl. restart reconstruction),
`channel-progress-lane.test.ts` (kickoff/rate-limit/final through a fake
handle), `activity-parity.test.ts`, full discord/slack harness suites.

PROSE (not via ask_user_question), the ask turn commits as an ordinary
answer, the structural continuity predicate correctly sees no clarification,
and the alias learned from the answer turn ("use the first one") is weak.
The structural fix works when the ask is structurally marked; classifying
prose questions is deliberately out of bounds.
