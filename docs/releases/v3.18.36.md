# v3.18.36 — a Windows daemon that stays up, live voice, and Clem in her own words

Harness schema stays at 93; no database migration. The Mac build comes from
the release workflow (signed and notarized). The Windows x64 build of the same
commit is qualified by the private Windows pipeline from this tag and attached
to this release, **unsigned** until a code-signing certificate exists: a fresh
Windows install shows SmartScreen's "Run anyway"; updates install normally.

Three things drove this release: the Windows tester's daemon, which had been
exiting at every boot since the last update; the owner's rule that the
harness never speaks for Clem (everything Clem says is now hers; everything
else is app chrome); and an afternoon in the owner's audit project where five
finished, correct replies ended "blocked". Every cause of that last one found
in the trace and in a live battery of named fixtures is a class rule now.

## Windows

- **The daemon stays up.** Since the last update the tester's daemon exited at
  every boot. Windows refuses to flush a file that was opened read-only, and
  the scheduler did exactly that on every tick to check a workflow's receipt,
  so scheduled workflows first stopped silently and then the whole daemon went
  down and was restarted into the same error. One helper now owns the rule,
  and the same mistake in Spaces lineage receipts, the cloud browser's store,
  workflow cancellation and a boot step is gone. Mac behaviour is unchanged.
- **No single step can end the daemon.** Every step of the daemon's main loop
  and its boot now runs contained: a failure is logged and the next step runs.
  Only the lock claim, the port and the boot migrations are allowed to be
  fatal. A request whose handler throws (on Windows, reading a saved credential
  whose privacy cannot be verified) answers that one request with an error and
  the daemon keeps serving; read-aloud with an unreadable key uses the
  computer's own voice. One workflow's unreadable receipt is unknown, not
  refused: that workflow is retried next tick and every other one is still
  scheduled, on both platforms.
- **It starts after an update.** Windows ends the daemon with a hard kill and
  reuses process ids quickly, so after an update the old lock often named an
  unrelated process and every new daemon refused to start until the lock file
  was deleted by hand. A lock is now taken over only when the process it names
  started after the lock was written and is not a daemon; a live daemon is
  never evicted, whatever the clock does.
- **The side menu comes back.** A window opened while minimized, hidden or
  snapped small read as narrow, and the menu collapsed to the icon rail with no
  labels until you found the toggle. The collapse now lasts only while the
  window is narrow; once it widens, your own last choice returns.
- **Live voice never takes the daemon down** when a saved key cannot be read
  safely: the settings answer "could not be read safely" and the turn-by-turn
  voice carries on.
- The Windows beta check now also runs the scheduler, lineage, cloud browser
  store and route-containment suites.

## Live voice (Mac, Windows and phone)

- **A real conversation.** With an OpenAI key saved, the voice toggle on
  desktop and phone opens a full-duplex conversation instead of transcribing
  and reading aloud turn by turn. The voice listens and talks at the same time,
  and each thing you say (gathered until you pause) is sent as your spoken turn
  of the open conversation, so the same brain, tools, memory and approvals run.
  Clem's replies go back to the voice tied to the request they answer; her
  progress arrives silently; a spoken "yes" to a card is an ordinary approval.
  An unused session ends after a few quiet minutes; an unexpected drop
  reconnects once, then says why.
- **The key stays on your computer.** The daemon only exchanges the connection
  offer; the phone exchanges its offer through the Mac under the paired
  device's proof. Without a key, or when the connection cannot be made, the
  turn-by-turn voice carries the conversation. A request spoken while Clem is
  still working waits and goes as soon as she finishes.
- **Needs OpenAI credit.** Live voice runs on your OpenAI account and is
  billed by OpenAI per minute of conversation. An account out of credit now
  reads as out of credit, with where to add it (it used to say "HTTP 429"); a
  momentary rate limit reads as busy; read-aloud falls back to the computer's
  own voice on an exhausted account instead of failing.
- **Voice reads only Clem's words.** A stop, a provider refusal or a missing
  model is the app's status line and is never spoken. A draft Clem wrote that
  the host held for its format is hers and is read. When a spoken request ends
  on a notice, the voice is told the fact and tells you in its own words.

## Clem's own words

- **No harness-written sentences in her reply.** Her text publishes exactly as
  she wrote it. The appended review notes ("Verification note: …"), the
  checkpoint sentences after a stop and the fixed Stop and quota lines are
  gone from the reply, on desktop and phone. The host never writes a
  first-person sentence in her place; when she had no words, the app says
  what happened.
- **Review is a chip.** Each reply carries the review's ruling (checked,
  unchecked, rejected, needs a fresh check) as a chip that opens to the
  reviewer's own finding, labelled as the review, never as Clem.
- **App facts are status lines.** A turn no model spoke for (a stop, an
  account out of credit, a sign-in that expired, no model connected, a model
  that stalled, a failed run) is an app status line with the one action that
  resolves it: Change model, Sign in, Add credit, Try again. A stop you asked
  for is a pill with what was kept ("Stopped here — 3 results kept"), and a
  change that settled in another app gets its own chip. A turn stopped before
  any tool ran says so in facts ("No provider call was made. No external change
  was made.") instead of telling you what to ask for.
- **Reopened conversations look the way they ended.** A reopened turn carries
  how it ended, the review ruling, what was kept and any notice; a stopped turn
  no longer reopens as a finished bubble, and a format-held draft keeps her
  words.
- **Receipts in words.** A finished turn says how the turn ended, how long it
  took and what it did ("Worked 18s · read calendar view · created draft"). A
  step that failed and was worked around keeps its own mark without turning the
  whole turn into "Ran into trouble"; a built-in tool reads as the action on
  its noun ("Searched file"), not as an app called File. On the phone, while
  Clem works, you see her own sentence and the step in hand, as desktop does.
- **What you type while she is finishing.** A message sent while Clem is
  writing her final answer is taken into that answer, or refused without a
  second turn competing with it. Only the conversation you are in can steer
  it; delegated workers cannot. A write whose outcome crossed a stop stays
  shown as uncertain until it is reconciled, never as done.

## Clem finishes what she started

- **Finished work ends done.** Five correct replies in the audit project were
  held as "blocked" because the parallel lane's review required an assessment
  the reviewer had not written. The reviewer's verdict stands on its own
  (below); a reviewer that could not run, or answered but could not vouch for
  its own reading (its check failed, or it called itself partial or
  uncertain), is the same absence of a check: the turn ends done with an
  "unchecked" chip and the reviewer's diagnostic kept beside it, never held.
  A reviewer that says no still rejects.
- **Clem's draft is always the reply.** A reviewer that answered no used to
  have its own sentence published in her place ("The three revenue figures
  could not be extracted because…"). Her draft stands, revised in her own
  words when the review found something, and the review's ruling is the chip.
- **A missing file is the read's answer, not an argument error.** Asked for
  figures from a PDF that does not exist, Clem reads the absence, says so and
  declines to guess; the turn ends done. It used to end blocked, with the
  reviewer's sentence as the reply.
- **Continue after Stop inherits every landed write as a fact.** Each line
  appended before the stop is carried as done and never repeated; the rest
  run once each, in order. The previous build repeated the landed write.
- **The review deadline follows what the turn did.** A turn whose only writes
  were restorable local ones is reviewed at the read effort, but its reviewer
  reads every write's receipt and now waits the write deadline. A five-append
  Continue used to hit the 30 s read deadline and ship unchecked.
- **A read-only workflow stays on the light check.** A surface that leaves
  the review to its caller is not the owner switching review off; the depth
  follows what the step did, so a scheduled read gets no second-model review.

## Workflows, tools and models

- **The reviewer's verdict stands.** A completion reviewer that answered with
  a readable verdict but left its assessment out, or garbled it, was treated as
  "could not verify" and about one in three reviewed turns was held with a
  note. Its verdict now stands, as it did before the assessment existed; a
  copied, unbound or foreign answer still cannot authorize work or invent a
  blocker.
- **The lean prompt is back on budget.** The action prompt sent on every turn
  had grown by about 1.1 KB of Stop/Continue rules without a measured benefit;
  it returns to its ceiling, and continuing stopped work still brings the full
  reasoning. A warm read measures warm again, and the Worker role line rides
  only when it changes what a worker would do.
- **Continue on a stopped workflow run picks up where it stopped.** It used to
  call the whole-run rerun, which must refuse once a write landed, so Continue
  could never do anything. Every step whose write landed or that sent is
  carried with its recorded output and never runs again; the rest run. It
  refuses in plain words when a write's outcome is unsettled.
- **A workflow step can only call a tool that can be called.** The builder
  saved exact call steps against tools that have no call carrier, reported
  them "set up and verified", and the run parked on "connect run" forever. Such
  a step is refused at save with the repair, shown as broken in health, and
  the check runs for every call step, prompt or not. A workflow saved with no
  read-only trial now says it was validated but not run.
- **Fewer wrong first calls.** A proven operation is handed to Clem with every
  field, its limits and defaults instead of a schema clipped at 1,800
  characters (the page-size limit used to sit behind the cut, so she asked for
  50 against a maximum of 25). Nullable choices, nested limits, element rules
  and free-form objects are stated or the full schema is attached. Over the
  2,000 contracts saved in a live home, 1,826 now read complete (was 1,771).
  A refused call names the field and the limit it broke.
- **Customize the plan works.** Choosing "Customize" on a strategy question
  used to end in "could not safely load the current capability catalog";
  after that, the details reply failed the same way. The choice now runs its
  turn, Clem asks for only what this task depends on in the task's own terms
  (not a fixed marketing checklist), "use your judgment for anything else"
  answers the remaining choices, and the details resume the original task.
- **A bare yes to a counted proposal carries that batch.** "Should I send this
  to all 18 contacts?" answered "Yes." keeps its 18; a range in prose still
  never fans out.
- **A plain read is never held as an unverified correction.** A read request
  that the capture pattern took for a stated fact no longer ends "I could not
  confirm that your correction replaced what I had saved before."
- **Background memory runs on the models you selected.** Skills, identity and
  import jobs take exactly the memory model you chose (under Automatic they
  followed whichever subscription was signed in), and wait with the reason when
  a saved brain cannot run instead of following a stand-in. The token meter
  names the same model.
- **Settings › Models says what each model did this week.** One line under
  each role ("This week: 430 calls · 9 of 10 passed review · 2.1 s typical ·
  81% cached"), for 7 or 30 days, from the usage ledger and the route
  records; a fact the ledgers lack is left out, never shown as zero. The
  review verdict and tool success now land on the model that wrote the reply,
  bound to that attempt. A provider's cost figure is never called "billed",
  and a partial cache figure says how many calls it measured.
- **After a connected tool is gone or renamed, the next search relists**
  instead of advertising the retired tool for another minute.
- **A tool's own proof that it never ran** (the local and cloud browser today)
  settles the step as repairable, so Clem fixes the call and retries instead of
  the turn holding.
- **Files and projects.** Chat, Made and project results open files in one
  workspace with the same reader (HTML, PDF, images, Markdown, text). Made
  gains search by title or filename, recent work and direct Open. A project
  overview on desktop and phone leads with the latest conversation, recent
  results, linked Spaces and what needs you. Desktop remembers the selected
  panel, PDF page, zoom and scroll while the window is open.

## The harness candidate from the parallel lane

The other agent's release handoff, a frozen additive patch, is applied as one
commit and then adjusted where the release audit found it slower or against
standing rules; each adjustment is its own revertible commit.

- **Truthful completion review.** The completion review records a reasoned
  assessment and covers more of the objective; a same-output format repair is
  bounded instead of retried without end.
- **Retained evidence stays evidence.** Results kept from earlier in the turn
  are preserved without being treated as a fresh observation (a fresh read of
  the target never proves an earlier operation's outcome), and an uncertain
  outcome is kept apart from a retry a guarantee covers.
- **Usage attribution.** Auxiliary and failed calls are attributed to their
  model and role instead of reported as zero; memory jobs record their causal
  accounting; the transport each call used is observed per call.
- **A stored quota refusal is explained as quota**, not as "reconnect".
- **Steering ownership.** Late input is adopted before the final answer or
  refused without a competing turn; delegated workers are kept outside chat
  steering; a plain conversation no longer sets up the worker tool it will not
  use.
- **Adjusted after audit:** the reviewer's verdict stands without its
  assessment (above); the lean prompt returns to budget (above); two size and
  wording pins follow the new Stop/Continue guidance; a lock is taken over
  only when two readings agree.

## Phone

- **Live voice on the phone**, with the same conversation protocol as desktop;
  the tap starts a live conversation when the Mac can hold one, and a failed
  start says why and talks turn by turn.
- **Status lines, pills and the review chip**, from the same wording as
  desktop: Change model opens this conversation's model sheet, Add credit
  opens Settings, Try again sends those words; signing in points to the
  computer.
- **Simpler navigation.** One drawer reachable from Chat, Project, Space,
  Agent, run and Flow screens; Chat keeps Back, title, options and navigation
  in one row, with agent, project, model and Plan mode in a dismissible sheet.
  Switching sections keeps the unsent draft, its uploads, selected file
  context, agent or project choice and Plan mode. Floating sheets fit the
  visible viewport in portrait and landscape. The composer is one rounded
  surface.
- **Dictation and Talk to Clem.** Tap to start, tap to finish, with visible
  listening and transcribing states and useful permission errors; Talk to Clem
  transcribes, sends through the same rules as typing, reads the reply and
  listens again.
- **Widget voice from the Mac side.** The paired app's widget voice setup
  reached a route the Mac refused for every phone, so it could never be set
  up; it now completes. The iPhone widgets themselves (Talk, Dictate, Your
  Space) ship with the phone app build.
- **Project files** open in the existing file sheet; closing keeps the project
  and returns to the selected result.
