# v3.18.1 — a review runs on the model you actually have

Release type: correctness fix on top of v3.18.0.

Two defects with one symptom: real, finished work reported back as blocked or
left unreviewed.

## A self-judge gets the deadline of the model doing the judging

A same-family judge carried no deadline of its own, so it inherited the
cheap-checker budget (25s) instead of the deliberate one (90s). On an install
with a single BYO model, routing was already correct — the review went to the
brain as a self-judge — and then timed out on every turn, because that model
answers in roughly fifty seconds. Every turn on such an install was unreviewed.

The short budget exists to stop a heavyweight pinned model riding every hot-path
boundary call, which assumes there is a faster alternative to protect. A
self-judge is the only model configured, so cutting it off buys nothing and
costs the review. This is the same failure the 12s to 25s raise addressed for a
faster model.

## A reviewer that cannot fire no longer holds finished work

A completion review that could not run downgraded a completed turn to blocked.
Measured: a sheet created, twelve cells written and read back, reported
accurately, and handed over as blocked and undelivered because the configured
judge had no reachable credential.

The terminal now follows the brain, and the disclosure is unchanged: the reply
still says the result is unreviewed, and the verdict record still carries
`verified: false` with `disposition: enabled_unavailable`. A review that RAN and
did not stand still blocks. When such a turn cannot close its accepted-task
authority, it falls back to the unverified terminal it replaced — note and
verdict reference intact — rather than to the generic state-machine hold, which
drops the verdict reference by design.

## Unchanged: an explicit judge pin stays authoritative

A judge the owner pinned that cannot run still means no judge runs, rather than
a silent downgrade to the brain grading its own work.
`objective-judge-pin.integration.test.ts` passes 26/26. Substituting the brain
for an unavailable pin was implemented, verified live, broke eight tests, and was
reverted: it is a policy change requiring those pins to be rewritten
deliberately, not a fix.
