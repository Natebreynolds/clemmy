# v3.18.39 — Backup brains, conversations that fold into memory, and the Connect card when you ask for an app

**Database migration:** harness schema 93 → 94. Conversation state moves out
of the session rows into its own table, once, at the first start (about five
seconds on a large home). An older version opened on this database ignores
the new table, so old chats lose their stored context there; update forward,
not back. The Mac build comes from the release workflow (signed and
notarized). The Windows x64 build of the same commit is qualified by the
private Windows pipeline from this tag, **unsigned** until a code-signing
certificate exists: a fresh Windows install shows SmartScreen's "Run anyway".

## When the brain stops answering

- **Backup brains are the models you list.** Settings → Models has "If it
  stops answering" on the desktop and the phone: up to three connected
  models, tried in your order. With no list, the model you chose is the only
  one asked; the built-in rescue chain and the Codex rescue setting are gone.
- **Switch, then tell.** Two answers that never come (an overloaded or
  failing provider, a timeout) within ten minutes move every conversation,
  older ones included, to your first backup that answers. Clem says so on
  Home. She checks the chosen model in the background, and when it answers
  again she asks whether to switch back: yes switches back, no makes the
  backup your brain for every chat.
- **Memory waits for its own model.** A memory model that stops answering
  pauses every memory job together, and the Memory tab says learning is
  waiting and why.
- **A provider that keeps failing leaves the turn resumable** instead of
  ending it in the harness's words.

## Conversations fold into memory

- **Conversation state lives in its own table**, so starting the app, the
  conversation list and recovery no longer read every conversation's history
  (boot steps 3.8 s → 0.6 s and 4.6 s → 1.5 s on a large home).
- **An idle conversation becomes memory.** After seven quiet days Clem keeps
  a memory of what was asked, done, decided and left open, written by your
  memory model from what you saw, and the stored working state shrinks;
  after thirty days only the memory and the last messages remain. Transcripts
  are kept. A new message makes the conversation whole again.
- **A turn marked not to learn from never becomes memory**, and memory an
  earlier version made from one is set aside.

## Connecting apps

- **Ask for an app that is not connected and you get the card that connects
  it.** Tool search names the app on its first page, and Clem's question
  carries the Connect card, with the app's own name.
- **Composio SDK 0.24**: the connect flow, toolkit auth details and OAuth
  payload fixes.
- **Local MCP and CLI setup are agent-led with verified states**; saved MCP
  access details can be replaced; a discovered MCP tool is usable again with
  or without a working directory.
- New chats start from examples, and connection setup keeps its draft.
- **Drag a chat onto Pinned to pin it**, or out of Pinned to unpin it; with
  nothing pinned yet, a drop zone appears while you drag.

## Lighter checks, faster screens

- **A read-only answer is checked by Jev alone**; the full review is kept
  for answers that write or create something. A browser page visit is
  reviewed at read depth.
- **One action of a multi-action tool that only reads runs without a card**,
  after a quick screen and a judge confirm it reads.
- Workflow screens stop recertifying every workflow on each visit; Space
  loops lock only the Spaces they have work for; boot and workflow
  publication steps that hold the main thread name themselves.
- The other agent's rounds: steering adopted mid-run, retained model
  authors, evidence-bound wording repairs, workflow transform guidance,
  retrieval bound to its embedding producer, and exact-worker embedding
  qualification.
