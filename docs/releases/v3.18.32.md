# v3.18.32 — The refinement batch: cards, control and workflows that keep their word

Mac-only release. Harness schema stays at 93 and memory schema at 37; no
database migration. This is the largest change since 3.18.28: a batch of
twelve corrections from a review of recent backend and frontend work, plus
two fixes for regressions the 3.18.30 batch suite and the live proof found
on 2026-10-07. The Windows x64 beta groundwork rides along inert on macOS.

## What changed

The refinement batch (its own record: docs/checkpoints/2026-10-07-assistant-refinement-handoff.md):

- A provider's failure envelope alone no longer proves a mutation did not
  commit, so no write is ever replayed on the strength of provider prose;
  only an adapter's exact pre-effect proof closes a write as failed.
- Hand edits and the approval that follows settle as one exact decision:
  the edited snapshot is bound by hash into the queued action, so what runs
  is exactly what the card showed, edited.
- Once-only confirmation belongs to the exact approval id; a later card in
  the same words gets its own chance.
- The delivery-review resume allowance survives more than 200 later
  heartbeats and a restart.
- A reopened live chat recovers the authoritative attempt identity before
  Stop or Background can act on it; a missing identity stays visible.
- Edited and cross-device card decisions update the existing card and
  observe its execution; drafts survive a refusal; a reopened chat keeps
  editing.
- Independent tool sources are prepared together under one broker
  deadline; shared namespaces stay serialized.
- A saved background specialist keeps its model pin; an inactive saved role
  refuses before it is enqueued.
- A corrupted, unreadable or linked recurring-workflow ledger never becomes
  empty state; it stays unavailable with its bytes intact until restored.
- Desktop and phone workflow Run show the actual queued, held, duplicate or
  readiness-refused receipt; the phone reuses the core dedupe.
- Workflow graph and step mutations share synchronous save admission;
  space creation and assignment forms fence the exact mounted request.
- Static Space export refuses linked, outside and non-regular sources and
  corrupt present datasets.

On top of the batch:

- A guard inside a tool that refuses an approved command in words is heard:
  "I didn't run the command — the tool refused it: …", with the outcome kept
  uncertain and never retried on its own. 3.18.30 had reported it as "the
  provider reported a terminal failure" and dropped the reason (found by the
  3.18.30 batch suite, file 844).
- A provider that answers a write with its own refusal — a Slack reminder
  already gone, answered `not_found` — is read back, not parked. The batch's
  stricter proof had hard-blocked such turns with "its effect must be
  reconciled before continuing"; the classification now tells an answered
  refusal apart from a dropped acknowledgement, both uncertain writes without
  replay, and only the dropped one stops the turn. The settlement no longer
  forces a returned failure to unacknowledged, and the durable checkpoint
  projects an answered refusal as ready, so the model reads the target and
  answers in words.
- A provider's request-level rejection (a structured 4xx) keeps its reading
  as the provider rejecting the request, closed as a failed write, so a
  corrected call still recovers it (the batch had widened "uncertain" to
  every failed mutation; main's 10-06 reading is restored). The settlement
  audit no longer holds an answered refusal as an irreversible write.
- A card whose question the model left out no longer falls back to operator
  text with an approval id; it asks in Clem's words.
- The desktop's setup state, log, setup crash log and setup bridge resolve
  the home exactly as the credentials bridge and daemon do, so a user with a
  selected CLEMENTINE_HOME is no longer asked to set up on every launch.
- The only trusted no-commit proof is the adapter's structural reading of a
  provider's exact rejection shape; it is no longer gated on one compiled-in
  operation name.

## Live evidence (installed app, live home, 2026-10-07)

Candidate hotpatched over the signed 3.18.29 shell and proven with the wave
runner, live models, named fixtures:

  command; Stop mid-work ends cancelled with "Stopped as requested" and an
  honest follow-up; two tool sources (Outlook calendar and the shell) answer

  change in words, revise then edit): every turn done or asked, as before.

  provider answers `not_found`): ten live runs of the candidate drove the

  binding of a same-worded reply, the same class the 3.18.30 notes record
  for this scenario on 3.18.29.

## Known limits

- The hard reconciliation block, when it is right (a dropped
  acknowledgement on an external write), still speaks in machine text:
  "The tool stopped after execution may have begun…". It needs Clem's words
  and a next edge.
- A Windows user whose selected home sits on a non-private folder gets a
  silent boot failure (the credential policy's refusal with no window).
- A two-source turn can take two minutes on a loaded machine.
