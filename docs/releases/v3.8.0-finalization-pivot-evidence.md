## The architectural decision this branch implements

Retrieval is not authority. The earlier attempt stalled trying to make a
pre-brain matcher resolve a paraphrase well enough to dispatch on; there is no
honest version of that. Instead:

- **exact/lexical retrieval** answers "has a phrase like this settled before?"
- **local semantic retrieval** answers "does this mean what an earlier proven
  request meant?"
- both produce **candidates**, which are pinned into the brain's existing
  JIT/MCP surface. The brain still chooses the effect, arguments, and account;
  the governed dispatch boundary still gates.

A wrong candidate costs one ordinary cold turn. That is the whole risk budget,
and it is why the retrieval side never needed to be certain.

## What shipped

### F0 — causal black-box matrix

`src/runtime/read-path/learned-read-loop.test.ts` drives the real governed
Composio gateway (only the final network function replaced), the real event-log
acceptance path, and the real JIT/MCP recall seams. Six behaviors, no source
scans, no export-existence checks.

At `d5093cd8` the first three failed for the audited reason — a cold turn where
the brain already knew the slug taught nothing, so a later paraphrase retrieved
nothing.

### F1 — procedure/alias integrity

`src/memory/capability-alias-index.ts`: a separate, transactional, scope-
partitioned store whose rows are `capability_only` for life, carry bounded
filtered terms instead of the accepted phrase, and verify their own digest on
every read. Ten properties pinned in `capability-alias-index.test.ts`
(immutable class, store-level class CHECK, write contention, exactly-once
accepted-source claim, tamper, stale schema, scope isolation, phrase
non-recoverability, no column for execution state, semantic floor/space/scope).

The privacy pin found a live leak: normalization split an address, host, key,
or order number into ordinary words and kept each one as a retrievable feature.
Structured spans are now removed while their structure still exists to read.

### F2 — candidate-assisted production routing

`resolveTurnCapabilityCandidates` runs once per accepted turn at the shared
bridge — the same seam the accepted-turn read resolver already uses, which every
surface routes through — and leaves advisory candidates where both brains'
synchronous tool-surface seams already look.

`src/runtime/read-path/capability-routing-production.test.ts` drives a real chat
turn through `respondPreferHarness` with only the model runtime replaced, and
asserts from inside the turn, at the moment the agent is built, that the proven
capability's carrier survives JIT pruning and that the connector surface is not
narrowed.

Local model measured on this machine: 6.9 s one-time load (weights download
included), 3 ms warm per embed. Paraphrase similarity 0.73–0.76 against
unrelated text at 0.57, so the 0.70 floor sits above the unrelated band with
margin. Weights moved to a machine-level cache — as home-scoped vendor bytes,
every fresh install, workspace, and test run re-downloaded ~130 MB.

### F3 — verified learning and exactly-once ownership

One canonical successful top-level READ settlement learns the capability and an
accepted-source alias. Effect class comes from the sealed taxonomies (Composio
slug evidence for connected apps, the runtime classifier otherwise) — there is
no verb list. The alias binds to the exact `{sessionId, sourceUserSeq}` and is
claimed exactly once, so a retry, a replayed frame, or a newer foreground
message cannot be credited for an older or background dispatch. No
`invocationTemplate` is stored, so no resolved date can be replayed.

### F4 — structural continuation and one-owner handoff

`detachRunningTurnToBackground` now checkpoints a capsule bound to the accepted
attempt and advances the durable handoff record before acknowledging; the
background task carries both identities, and the consumer that was already
built for them finally receives them. Capsules verify their own digest on load.
Handoff state is monotonic with an expected-revision CAS.

Pinned by `continuation-integrity.test.ts` (7) and `handoff-production.test.ts`
(2). The existing assertion that the worker is told to read `session_history`
first was replaced by the structural facts it stood in for.

### F5 — substrate correctness only

Reducer readiness compared a caller-supplied total against a set size, so
settlements carrying ids belonging to no item satisfied the plan — a reducer
could summarize work that never happened. Readiness now derives from the plan's
own item × phase ledger. Duplicate phase ids and dependency cycles are refused
at admission. An explicit background request is no longer demoted to foreground
when it has no manifest to fan out.

Pinned by `work-disposition-integrity.test.ts` (10) plus the updated
`continuation-fanout.test.ts`.

## What did NOT ship, and why it blocks the tag

**F5 production activation.** `reducerReady`, `dispositionToDurableWork`, and
`expectedLedger` still have no production caller: the typed disposition never
reaches the mature scheduler, windows are arrays rather than durable tasks, and
there is no once-only reducer lease. The 40/120/514 proof exercises planning and
readiness, not real durable execution across a restart.

**F6 activity projection.** `nextSlackProgressAction` and
`nextDiscordProgressAction` are exported wrappers with zero callers; both
senders still run their own flush logic, and there is no console activity
projection wired to durable lease truth. None of the required interaction
behaviors (inline collapsible activity, background-only Working Now, quiet-live
vs stale lease, cross-surface parity, restart reconstruction) are proven.

**Not claimed anywhere:** live latency/token cohorts, graph-native fan-out
siblings, admitted-graph activation (`admitGraph` still has zero effectful
production callers), and visual QA.
