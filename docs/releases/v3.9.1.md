# v3.9.1 — hints are the schema, windows are live facts, and long runs get the room they pay for

Release type: reliability + capacity release. Every fix ships a
deterministic regression pin. Root causes traced from live traces and live
provider calls during the release session; suite at the cut: 9,300+ tests,
0 failures, both typecheck roots clean.

## The failure class this kills

`tool_output_query` was rejected pre-dispatch with `InputValidationError`
— the model sent `"fields": subject,start,end,…` (bare tokens, invalid
JSON). All four recorded occurrences of this error class were the same
tool, same parameter, same taught syntax. The teacher was us: every prose
hint the harness emits (digest footers, clip stubs, fan-out shard headers,
subagent/worker/orchestrator prompts, the continuation ledger, the rubric)
demonstrated the reader tools as pseudo-code — positional call signatures,
bare comma field lists, even Python-style kwargs. Under schema-on-demand
and after compaction those hints are frequently the only documentation in
context: the hint IS the de facto schema.

Lane exposure is asymmetric. The OpenAI lane is immune (`@openai/agents`
defaults `strict: true` — constrained decoding guarantees schema-valid
args). The Claude SDK lane streams tool input unvalidated, and the BYO
lane strips `strict` at the wire because compatible backends reject it —
both lanes emit exactly what the hints teach.

## Fix 1 — every tool-call example is generated, valid JSON

New `toolCallHint(tool, args)` renders literal copy-pasteable examples —
`tool_output_query {"call_id":"…","fields":["subject","start"],"limit":50}`
— and every emit site routes through it. Digest field lists render as JSON
arrays (both the array path and the object/dominant-array path the Graph
calendar shape hits), and the recovery example carries the real field
names of the parked records. Pin has two teeth: every rendered hint must
parse as JSON AND zod-validate against the exported registered shapes, and
a source lint forbids paren-form reader-tool signatures anywhere in src —
a future hint site cannot reintroduce the prose form.

## Fix 2 — `fields` accepts the one remaining near-miss

`fields` is widened to `string[] | string` (comma-separated), normalized
to one canonical array at the boundary. Both spellings produce
byte-identical projections (pinned). Branches are typed, so the OpenAI
lane's strict conversion is unaffected. No repair heuristics — an
unambiguous alternate type only.

## Fix 3 — context windows are live facts, not table entries

The registry's windows were audited against the serving providers and were
light almost everywhere: gpt-5.6 is a ~880K-input model (live-probed:
accepted 880,007 tokens, rejected 882,007), Claude Opus 4.8 / Sonnet 5 are
1M (platform docs), GLM-5.2 as served by Together is 512K, kimi-k3 is
1,048,576 (both providers publish context_length on /v1/models) — while
we budgeted 272K/200K/128K/128K. The registry now carries the verified
numbers with their evidence sources, exact-id where backends differ
(`zai-org/GLM-5.2` ≠ bare `glm-5.2`), and — the part that keeps it true —
a window-observation layer makes the registry a SEED, not the authority:

- provider catalog listings record the published window per exact model id
  (BYO discovery now keeps the context_length it previously discarded);
- a live context-overflow rejection ratchets the effective window DOWN
  after one failure (Codex + BYO lanes both detect the provider phrasings);
- a Codex SSE truncation with a >1MB request body feeds the same ratchet
  (the OAuth transport's ~1.4MB body cliff truncates WITHOUT a clean 4xx);
- a live acceptance above belief raises the floor from real usage.

A brand-new Anthropic/OpenAI model on release day rides a conservative
family fallback (early compaction — waste, never overflow) until its
first catalog listing or live acceptance teaches its real size. No code
release required to track a model change in either direction.

## Fix 4 — compaction budgets track the routed model

The ladder assumed a fixed 200K budget for every model — wrong both ways:
a 128K-window BYO model hit provider overflow BEFORE the Layer 3 fork
(90% of 200K = 180K > the real window), while Codex (272K+) and 1M-window
models clipped verbatim history with real headroom left. Budgets now
derive from the evidence-adjusted window; fractions are unchanged — an
honest denominator, not a retune. The Layer-2 summarizer's own input is
capped to a fraction of the summarizer model's window (a latent overflow
this raise would otherwise have activated — caught in review, pinned).

## Loosening, deliberate and bounded

- Write-time digest clip: 12K → 20K chars, so a typical single-screen
  result (the 39KB calendar day) needs no follow-up read.
- Layer 1 retain turns: 4 → 6 — more verbatim recent history, fewer
  recall round-trips (a live scrape run recalled 44×).
- In-flight tool-context thresholds scale with the window (never below
  the tuned defaults; env overrides stay absolute).

## Long runs and fan-outs get the room they pay for

Every fixed surface size tuned for the 200K era now scales with the
ROUTED model's real window (clamped [1×, 4×]; env overrides absolute):

- Fan-out return path: verbatim exemplars 8 → up to 32, per-item envelope
  digests 700 → up to 2,800 chars. A 100-item fan-out on a 1M parent
  stops paying a drill-in round-trip per exact figure.
- `recall_tool_result` budget: 5 calls / 150KB → up to 20 / 600KB.
- The lossless tool-output store's per-call ceiling rises 2MB → 16MB. The
  win is NOT bigger context (the event-log clip, digest, and recall budget
  still gate that): `tool_output_query` filters/projects/paginates IN CODE
  against this store, so a 10MB record set stays fully queryable and only
  matching rows ever reach the model. The 14-day session reap bounds
  aggregate disk; the truncated-at-write warning remains for the
  pathological >16MB case.

## Compatibility

Clip stubs persisted by older versions replay fine — marker detection
stays lenient (matches both generations); only emission changed. Workflow
steps inherit everything through the shared turn path; zero workspace,
space, or workflow files were touched. No flags, no new env knobs, no
behavior bundled with plumbing.

## Known-not-fixed

The residual mechanism — a model occasionally streaming malformed JSON on
the Claude SDK lane — is SDK-owned (fine-grained tool streaming without
buffering). Anthropic's strict tool use (structured outputs GA) is the
upstream fix; the Agent SDK does not yet expose it for MCP tools. Watch
item, not code. Also open, by design: single tool results >16MB and
in-context data joins still require the model to pivot to files/code-mode;
a deterministic truncation advisory is the named next step.
