# v3.18.33 — Clem drives: the harness carries facts, Clem speaks

Mac-only release. Harness schema stays at 93 and memory schema at 37; no
database migration. The Windows x64 beta ships separately as an unsigned
installer from the private beta workflow on this same commit.

The owner's rule for this release: the harness never speaks for Clem. Clem
drives; the harness is the vehicle she works in. Every place where the
harness wrote the owner's reply itself, or decided what the owner's words
meant before the model read them, now hands Clem the facts instead.

## What changed

- **A decline in words reaches Clem.** "No, don't run that." used to be
  answered by the chat route with "Rejected apr-827o — continuing." The card
  still closes and nothing runs; Clem answers in her own words.
- **A stray "yes" with nothing pending.** Clem is told nothing is waiting on
  the owner and answers as conversation. Before, a "Yes, go ahead." after
  finished work became invented work (a rewritten file, a re-run command).
- **"You choose, just go."** Any go-ahead reading of a reply to Clem's
  question, sure or not, settles it: Clem picks a sensible default, does the
  work and says what she assumed, instead of arguing for her question.
- **Stop really stops.** A running shell command now watches the durable
  Stop latch and ends its process group; before, a stopped 90-second loop
  was still alive afterwards. The next turn reads the Stop as the owner's
  decision, never as an unknown effect to reconcile.
- **When the host has to stop a turn, Clem says why.** A blocked turn's
  fixed sentence ("The tool stopped after execution may have begun…") is
  handed to one tool-less call on the turn's own model as a fact, and the
  owner reads Clem's reply. The fixed sentence stays only when the model
  itself failed, the owner pressed Stop, or the model cannot answer.
- **A failed local command keeps going.** A command that wrote a file on
  this Mac and then exited non-zero no longer ends the turn as an
  unknown outside write; Clem looks at the state and finishes. Writes that
  may have left the machine keep the stop.
- **Background work is Clem's choice.** The chat route, both Home endpoints
  and the phone gateway no longer read the owner's words with patterns
  ("in the background", "keep working", "overnight") to queue a generic
  background task. Only an explicit `/background <instruction>` command
  routes directly; words reach Clem, who can start background work herself
  and hand it to the right specialist.
- **A background task's decision and a stale card** are answered by Clem
  from facts, without card ids.

## Live evidence (installed app, live home, 2026-10-08)

Every change was hotpatched over the installed app and driven with the live
wave runner (named fixtures, live models), each against the receipts of the
build before it:

- Decline in words: "Understood — nothing ran." Stray yes: "The write
  already landed — nothing left to approve." Delegated choice: Clem picked
  the greeting and said so.
- Stop: after the owner's Stop, Clem checked the machine; no counting loop
  was running.
- A failed `cat -A` after a local write: Clem continued with `cat -vet` and
  finished.
- The Slack reminder scenario (set, delete, delete again; Slack answers
  `not_found`): every turn ends in Clem's words, with no host stop text and
  no reviewer block, on three consecutive builds.
- The regression waves (approve in words, Outlook card voice, change in
  words, revise then edit) unchanged.

## Known limits

- With several cards open, a bare "yes" or "no" in words still moves to a
  fresh conversation that cannot see the cards, because a conversation with
  open cards is held until they settle. Tap the card itself instead. A fix
  that lets Clem ask which card from inside the held conversation was built
  and tested live, but it left the reply unanswered, so it is held back.

- The Stop acknowledgement and workflow/workspace approval replies are
  still fixed text; they need a quiet on-screen status (desktop and phone).
- An explicit `/background` command is still acknowledged with a fixed line.
- Building a phone layout for a data-fed Space is slow: the transform
  language has no reference Clem can reach, and large transforms are typed
  as JSON inside a string. Tabled for the work on Clem's own skills.
