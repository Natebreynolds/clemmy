# v3.18.58 — Clem drives your computer, owns her tools, and runs headless

**No database migration.** The harness schema stays at 102, so this build
opens a v3.18.57 database as it is, and a Mac on this build can still go back
to v3.18.57. The Mac build comes from the release workflow (signed and
notarized). The Windows x64 build of the same commit is qualified by the
private Windows pipeline from this tag, unsigned until a code-signing
certificate exists. A Linux AppImage now packages on demand in CI from the
same build configuration; it is proven to start and answer, not yet published.

Proven on the installed app: every step below but the credit fallover was
hotpatched onto the owner's running Mac and driven live, including seven computer tasks in a native app
that went from a card on every action to no card at all once the kinds were
learned.

## Your computer, as one of Clem's tools

Connect gains **Your computer**. One tap downloads Clem's own copy of the
computer driver, checks it against the vendor's published checksum, and runs
it embedded under the app's own identity, so the screen-recording and
accessibility grants attach to Clementine and are asked for once. No
administrator, no package manager, no terminal.

- **One contract.** Looking at the screen is free. Acting is a local write:
  the first action in an app asks once, in Clem's words, and the approval
  teaches the kind. The driver's input primitives count as one kind, so a
  click, a key and a batch of steps are not three lessons.
- **Clem's own knowledge decides over the vendor's blanket mark.** The
  driver marks every action destructive; Clem's knowledge of which actions
  are ordinary decides the card, so the second task in the same app runs
  without one.
- **A connected driver is the one browser.** While the driver is on, the
  cloud browser is not offered; Connect tells one computer story instead of
  two.
- **The chat shows your computer live.** A strip above the composer follows
  the window Clem is working in, even behind yours, refreshed from the
  smallest read the driver answers in about a second.
- **Windows preview.** The same card downloads the vendor's Windows build into
  Clem's tools folder and serves it on its own; qualified by the Windows
  tester, not yet by the owner.

## Clem owns her tools

- **A tools folder of her own.** Vendor downloads and npm packages install
  into Clementine's own folder, on her bundled runtime, first on the path for
  everything she runs. Nothing is written into the system or a package
  manager's prefix.
- **An install reads where this account may write before it runs.** A tool
  that insists on a system place is redirected into the owner's folders when
  it can be, and otherwise handed to the operating system's own
  administrator dialog, with the card saying beforehand what that window
  will say. An administrator's install hands back what it left in the
  owner's home.

## Run Clem without the app in front

- **`clementine run "<task>"`** sends one task through the running app and
  returns the reply with an exit code, so a script or another tool can ask
  Clem something. A task that stops on a card says so, and
  **`--approve`** / **`--reject`** answer that card through the app's own
  button route, resuming the same run.
- **One Triggers screen** lists what fires on its own, soonest first, with
  each kind's controls.
- **Each workflow webhook has an address of its own.** A service holding one
  address starts that one workflow and nothing else.
- **App events reach workflows.** A connected app's trigger fires the
  workflow event named by its slug, capped per day.

## What a tool saw shows in the chat

A tool's pictures are kept for the conversation and drawn under its row,
including pictures a direct call or a tool adapter hands on inside its text.
They are swept after a week; a request copy never outlives a month, which on
the owner's install freed five gigabytes of month-old copies.

## Nothing waits behind the daemon's loop

- A week-idle conversation's stored state is compacted by the storage decay
  worker, off the loop; the hourly route-policy rebuild runs in a worker on
  its own connection.
- The Space schedule tick lists from the committed manifests; a
  finished-blocked workflow run ages out like any finished run, and a reap
  pass deletes a bounded number; day-old empty origin groups are swept.
- The hold journal names its parts, so a long hold says which phase held.

## A model account out of credit does not fail the run

A workflow step whose model account refuses for lack of credit re-runs on
the backups you listed, the way an expired sign-in already did. The gate had
read that refusal as a deterministic error and failed the run with the
provider's words; found on the owner's own daily report, which runs on a
model pinned to a prepaid account. The switch is recorded in the run's
events; saying so in the run's result is next.

## Smaller things

- Each of Clem's replies can be read aloud from a speaker button, in voice
  mode's voice.
- Share what Clem built as one cartridge: workflows, skills, tool servers and
  Spaces, definitions only.
- Clem can archive a Workspace, reversibly, when asked to delete one.
- A one-time reminder reaches thirty days out; a recall of an unknown result
  id is a repairable argument; a question asked through the question tool is
  a question by construction; a consent refusal's recovery surface admits
  the move its own edge names.

## Not in this release

- The cloud browser tools are still defined while no driver is connected;
  full removal waits on the owner's call.
- The Windows driver is a preview until the Windows tester drives it.
- A signed privileged helper for managed Macs, so an administrator install
  needs no OS dialog, is a release-side change for a later cycle.
- Taking over the live view with your own mouse, and phone calls, are not
  started.
