# v3.18.28 — Clem acts like an assistant: no dead ends, cards in plain English, workflows run end to end

Mac-only release. Harness schema stays at 93 and memory schema at 37; no
database migration. Everything below was found by running the installed app
against live models in scenario waves on 2026-10-05 and 2026-10-06 (about 200
live turns), fixed, hotpatched into the installed app and re-run live; the
suite results are recorded as measured.

## What changed

### No dead ends when you answer or change a question

- When Clem asks something and you answer part of it, change the plan, or
  say "go", she carries on. Until now the harness could stop on "Your reply is
  recorded. I couldn't verify how it changes the pending question" whenever
  its quick revision check timed out or disagreed with itself — live, that
  was every partial answer to a compound question and every "change the plan
  … then go". The brain now takes the reply directly (settle, carry on under
  whatever hold the task set, apply the change exactly as stated, ask only if
  something truly blocks) and a plain go-ahead settles what is left with
  sensible defaults, said out loud.
- An amendment to a plan is accepted as the new goal; the harness no longer
  demands a full work replacement with it. The quick check's review gets
  12 s instead of 4 s, which was turning good readings into timeouts under
  load.
- A reply that stops a task ("stop") keeps the task in the conversation:
  "continue where you left off" works — including a stop in the middle of a
  fan-out, which used to leave the conversation with no ending at all (the
  stop now settles the calls that never started, then publishes).

### Approvals: one plain-English card, answered in words

- Any first-time change in a connected app asks once, in Auto as well as Ask,
  with Clem's own question and why; approving once teaches that kind of
  change. A learned kind skips the card only for the change you asked for: a
  write Clem adds on her own still asks.
- Published workflows carry their approval end to end: a sheet update, a send,
  a delete inside an approved workflow runs without a card. Human-in-the-loop
  steps remain the only pauses.
- Plan mode names the tools it would use and commits nothing; it no longer
  runs a connected-app call "once, as preparation".
- Answering a card in words works: "Yes, delete it" approves, "No, skip it"
  declines, and when Jev is not sure which you meant Clem asks the card's own
  question back in one line instead of starting a fresh turn (which used to
  mint a duplicate card). Jev reads the card's plain-English question, not
  only its fields. A queued shell command or send can be declined in words.
- Commands that reach another machine through the shell (`ssh`, `railway
  ssh/run/up/deploy`, `fly`, `heroku run`, `kubectl exec`, `gcloud compute
  ssh`, `aws ssm/lambda/ecs`) are treated as sends and get the one card.

### Results that read as done when they are done

- A delete that returns nothing (a 204, an empty `{}`) settles as done, not
  as "empty result, try another tool"; a delete of something already gone no
  longer ends the turn as "uncertain" when the read-back proves it absent.
- A plan that shows the exact JSON it would send is delivered in full; the
  tool-call guard no longer mistakes a fenced payload for a leaked tool call
  and hand you the first line only.
- "Run this failing command and tell me what happened" delivers the account
  of the failure when the completion reviewer passed it; the host no longer
  holds the turn as "a business call failed and nothing succeeded".
- A file create that would overwrite an existing file is a typed conflict,
  not prose, so the turn is not blocked as artifact drift when the final file
  is right.
- Read-only completion reviews are time-boxed to 30 s (was 90 s).

### Reminders and jobs

- Set a reminder in plain words, cancel it in plain words (`cancel_timer`).
  A reminder that needs a delivery the tool does not have gets one clear
  refusal instead of a loop.
- Receipts and replies drop internal ids: no reminder ids, record numbers or
  approval ids in Clem's words.

## Live evidence (installed app, live home)

18 guarded daemon-only hotpatches on 2026-10-05/06, 20 scenario waves, ~200
live turns against DeepSeek-V4.1-Flash (brain), claude-sonnet-5 (reviewer)
and Jev 1.13.0, all recorded under `~/clem-worktrees/takeover-kit/live/`.
Representative proofs on the final code or its direct predecessors:

- Plan → "change the plan: merge intro and outro" → "Go.": files written
  (was a canned stop twice).
- Twelve-file fan-out stopped at 14 s → "Stopped — this turn was cancelled" →
  "continue where you left off" → all twelve files (was: no ending, dead run).
- Draft a note → amend it → "Looks right, go.": written and verified, no
  residual question (was "same wording or fresh?").
- Outlook: draft created on a learned kind with no card; "Now delete that
  draft" → one card → "Yes, delete the draft." → deleted and read back
  "Done — verified" (was four duplicate cards, then "uncertain write").
- Slack reminder under Auto: one plain-English card before anything happens;
  "No, don't set it." declines it.
- `ssh localhost uptime`: one card, nothing ran; "No, skip it." declines.
- A workflow's sheet update sat on a first-time card the hour the rule went
  in; the workflow rule is pinned, and its next live run was not yet due at
  release time.
- Compound question answered in two replies → CSV written; chained
  CSV → totals → rename; change of mind mid-work; failing shell → fix →
  rerun; memory remember → use → forget; plain chat without a project.

## Known limits

- Approving a queued shell command or send in words is not routed yet: the
  executor that runs a chat-queued action fails on a question turn (the card
  button depends on the same path). Declining in words works.
- Deleting something that a provider reports as not found still ends the
  turn as "uncertain" on some providers (Slack reminders); the read-back
  reconciliation is next.
- Pre-existing test failures not fixed in this release: the frozen Claude SDK
  brain lane's three memory tests; the respond-bridge "ownerless stalled
  terminal" pair; the connected-subscription model-route lane (four pins);
  the orchestrator batch-line pin; three pins of the old blocked/structured
  wording that the clarification snapshot changed.
- Approval cards still show some machine text (operation names, ids) under
  Clem's plain-English question; a rewrite of the card body is next.
- Replies can still quote record or message ids from tool results.
- Calendar reads and memory saves can take a minute under load.
