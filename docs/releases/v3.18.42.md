# v3.18.42 — Workflows rehearse and run through one path, Stop always stops, and any tool connects to a Space

v3.18.41 was tagged but never published (its release stopped at a packaging
gate); this release carries everything it was going to, plus that fix.

**Database migration: harness schema 94 → 95.** One additive table
(`outcome_reports_pending_v1`, the background-result outbox); no existing row
changes. An older build refuses to start on a v95 database, so going back to
3.18.40 or earlier after updating is not supported. The Mac build comes from
the release workflow (signed and notarized). The Windows x64 build of the
same commit is qualified by the private Windows pipeline from this tag,
**unsigned** until a code-signing certificate exists.

## A rehearsal and a run prepare a step the same way

- **One reading of `{{ … }}` references.** A field of an earlier step's
  output (`{{ steps.gather.output.title }}`, with or without spaces) fills in
  the same way whether it is the whole argument, text inside one, or part of
  a step's instructions. Before, it stayed as literal braces inside text, and
  a saved note could contain the template instead of the data.
- **Clear outcomes before anything is written.** A structured call's
  arguments come out as ready; missing data (a step output never produced, a
  field it doesn't have, an input the workflow never declares); data only a
  real run produces (a change the rehearsal only previewed); or refused by
  the tool, with the exact reason. A declared input left empty is data, not
  missing. A run refuses missing data instead of writing an empty value.
- **A rehearsal checks a write the way the run will.** It fills in the
  previewed step's arguments from real upstream data and compiles the call
  against what is connected here, so a missing connection, an account to
  choose, or a bad argument shows in the test, not on the first run.
- **A step that never ran is not a pass.** It reads "did not run" (something
  above it is outstanding); a check deferred until after a previewed write
  reads "checked on the first real run" and still passes.
- **A passed rehearsal counts.** The Workflows page shows a tested version as
  ready to turn on, and turning it on doesn't test it again; any edit other
  than on/off needs a new test.
- **Unmarked steps are read once.** A prompt step that doesn't say whether it
  writes is read once by the quick-check model, and the answer is saved
  against its prompt, skill and tools; a change reads it again, an unchanged
  rerun reads nothing. It decides what the step is, never what a call may do.

## Turned-on workflows don't stop for ordinary writes

- A workflow you saved and turned on makes its ordinary writes (drafts, rows,
  records) without a card, including a step that finds the exact operation
  while it works. Each call is still checked against the current connected
  account, definition and arguments. Sends must be named by the step; delete
  and admin operations are never covered this way.
- A run resumed after a stop carries the authority of the run it continues.

## Stop always stops

- A turn you stop while it is held for recovery ends stopped: one result, the
  attempt finished, no further model work. This holds across a restart, an
  expired run lease, and a first failed attempt to publish the result.
- A recovery that cannot start (its owner, source or evidence is gone) stops
  at once instead of retrying. A workflow parent's held turn is re-driven by
  its own owner, never by a timer holding a lease it already released.

## Background results arrive without interrupting you

- A finished background result (a workflow run, a background task) is
  committed with a durable publication intent and delivered from a retry
  outbox, so it reaches the chat once even across a failure or restart. It
  no longer waits for the chat to go idle, and it never takes over or steers
  the conversation you're in.

## Files, reports and history

- A relative file path lands in `~/.clementine-next/files/`, never inside the
  installed app (where it changed the signed app and was lost on update).
- Reports and replies no longer show a write tool's machine receipt.
- Clem can list a workflow's runs and read any step's full output; the
  Workflows page run view has "Ask Clementine about this run".
- Workflow status and history read one lightweight run inventory that
  re-reads only changed run files and notices a run finishing.
- A workflow edit that changes nothing settles as no write (it had caused a
  false "blocked" on a finished turn).
- A server's tool-sorting card asks only for a tool Clem chose, and names it.

## Any tool connects to a Space

- **A Space button can run a saved workflow**, and a workflow can feed a
  Space's data from any tool it uses: a command-line tool, an MCP server, a
  connected app. A new or redesigned Space is read against what you asked for,
  and Clem is told what it doesn't do yet before she says it's done.
- **A signed-in command-line tool reaches its app.** With `gh` or `railway`
  signed in, Clem uses it and never asks you to connect that app. Only a tool
  whose sign-in was confirmed in its latest check counts. Clem can read what a
  connected tool does from the tool itself (its own help).
- **Pointing a Railway project at a folder is local work** and asks nothing;
  deploying, `ssh`, `run` and other commands that act on the service still do.

## Long builds stay on track

- **A loop of refused calls ends.** A turn whose every call is refused before
  it runs stops after eight such steps in a row, in any phase, and Clem says
  why. A loop-guard stop ends the same way, never with a canned message.
- **Clem keeps her working set mid-turn.** Input schemas she found by search
  survive context condensing (with the exact reread when one is too large),
  and a result she fetched again stays in front of her.
- **A failed read that printed its answer counts as evidence**, so a command
  that exits with an error but returns data no longer stops a build early.
- **Re-reading a view after editing it is checking work**, not a loop.
- **Prompt caching per conversation.** Each chat keeps its own cache key and
  names it to the model service, as the service's own client does.
- **Only tools that worked ride along.** A tool is carried into the next
  request only if it succeeded this turn or last turn; a failed call drops it.
- **A tool definition the model service rejects** no longer breaks a chat, and
  a rejected request is never reported as a dropped connection. Only the
  unsupported keyword is left out; a tool's default and example values are
  sent exactly.

## Evidence, not assumption

- Facts about your world (where something runs, a URL, an account, project
  or record, a file location, a status) come from a tool in that task or a
  verified memory, never from a name. A tool that needs a project selected
  lists its own projects.

## Workflows

- **A send step is done only when a send was made.** A step that gathered
  everything and didn't send now reports blocked with the reason, instead of
  completed.
- **A refused connected-app write can be retried** through the service that
  runs it, after the fix the refusal asked for.
- **Run trace:** `GET /api/console/workflows/:name/runs/:runId/trace` returns
  what Clem did in a run, step by step: each attempt's prompt, model, tokens,
  every tool call with arguments, result and outcome (including calls refused
  before they ran), and how it ended. It answers only for the exact run it
  names.
- **Workflow conversations:** edit a selected workflow in a conversation that
  persists; chat controls and Space panes stay responsive.
- **A workflow's final summary runs again.** The summary pass after the steps
  was refused by the new pre-run check and every report fell back to the raw
  list of step outputs; it is the runner's own read and now runs.

## The write review works with one model

- **The reviewer sees what a step read from your own data** (your task list,
  a saved workflow), not only its size, and **which account each call used**,
  including the account the write itself will run through.
- **A value the reviewer can fix comes back fixed.** When values alone make a
  write acceptable (a time zone stated, an address corrected, a claim the
  evidence doesn't support dropped), the refusal carries the corrected call,
  so any model, including a single small one, can resubmit it instead of
  guessing, and that exact resubmission is always reviewed once more.

## When Clem stops, she asks

- A turn that has to stop (a refusal it can't get past, a loop guard, a
  missing value) ends with **one specific question** you can answer: a value
  only you know, a choice between named ways forward, or whether to try again
  with a stated change. Never a bare statement.
- **A question about something else keeps its words.** When the app asks
  about a model connection that kept dropping, an approval or a check's
  verdict, it no longer swaps in a "connect an app" question because a search
  along the way found an app that isn't connected.

## Fixes

- A question you were asked about connecting an app is released once a
  signed-in tool reaches it.
- A queued outside action opens its approval card.
- A workflow's creation test is reported once.
- Clem's "ASK:" marker is never shown in a reply.
- A workflow's run history is found by its name whatever the case or
  spacing; it had answered "no runs yet" for a workflow with runs.

## Known issues

- A search that finds an app that isn't connected can still turn Clem's own
  question (asked in her words, with her options) into the app's "connect
  this app" question, even when the task doesn't need that app. The next
  release limits that question to the app the task needs.
- A connection check that times out on a slow network can park a scheduled
  workflow as a definition mismatch; the run can't be retried and holds later
  runs until it's dismissed.

- With two connections to one mailbox, a send's connected-app definition can
  switch between them mid-run, and a resubmitted send is then refused before
  it runs. The step stops and says so; nothing is sent twice.
