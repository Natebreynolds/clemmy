# v3.18.0 — long-horizon turns, an honest check-in, and a lighter fast path

Release type: long-horizon convergence and reliability release.

This release integrates the `integrate/long-horizon` work on top of v3.17.0. It
makes a long turn survive its own ceilings, makes a stalled turn talk to the
person instead of dying quietly, and takes measurable ceremony off the front of
every turn. It does not claim that delegated worker external writes work; see
Known boundaries.

## A long turn continues instead of ending at a ceiling

An activation boundary is a checkpoint, not a terminal. Untouched siblings settle
as stopped-before-dispatch under either admission digest, so the frame commits
and the limit propagates rather than stranding the work. Interactive lanes now
continue past the per-activation tool ceiling the way the workflow lane already
did, and a ceiling continuation runs where interactive turns actually run. A
continuation keeps the same accepted source, the same surface, and the same
history chain; it does not extend history.

## A stalled turn checks in, and incomplete is not failed

No progress is a conversation. An exhausted turn now checks in with the person
instead of returning silence, and that check-in is exempt from the pending-work
block precisely because the work is unfinished. The check-in is one request, and
only where a person is adjacent to answer it.

A heartbeat is something that happened, not a clock tick. Active-turn beats are
change-driven: they speak on the first beat, on real progress, and once every
sixth quiet tick with an explicit "no change for X" — 10 beats across 63
unchanged ticks instead of 63 identical lines.

## The fast path stopped rebuilding what cannot change

An immutable planning surface was being reconstructed on every observation. It is
now built once and reused, which measured ~3.9s off every turn (a 64-observation
loop went from 4,128ms to 210ms). Local tool schemas are memoized behind the same
rule.

## Reads are decided by the verb that leads, not by a noun anywhere in the slug

The soft write vocabulary graded a read as a mutation whenever a word like
SCHEDULE, RUN, BUILD or ORDER appeared as a NOUN. A calendar free/busy read, a
run/build status read, an order read and an open-issue list were all refused,
while the plural spelling of the same noun passed — singular versus plural of one
word flipped the effect. The leading verb now decides, and only the token
immediately after it is treated as its object. The irreversible send floor is
unchanged and still fails closed anywhere in the slug.

## An account choice you can actually answer

A blocked account choice now always carries labels, and identities are learned on
demand before asking rather than presenting opaque connection ids. The label
takes the first non-empty of alias, provider label, email, or account name, with
the raw id as the last resort. An unreachable provider never turns a choice into
a failed turn.

## The harness does not squeeze a model the owner sized

An explicit `CLEMMY_WORKER_MAX_CONCURRENCY` is an instruction and now wins. It
was previously min()'d down to the BYO default of 3, so a home configured for 12
still ran fan-outs 3 wide. The polite default still applies when nothing is
configured; the global ceiling and the provider's own limits are unchanged.

## Also in this release

- Plan turns end when the plan is published; a draft refusal names the field that
  disagrees, and a universe refusal names its repair.
- Expected work: an exact member id is authoritative for per-item binding; a
  contradicting selector is ignored rather than refusing the frame.
- A judge-only goal miss on delivered work is an advisory, not a blocked run.
- Workflow completion objectives include authored steps; judge evidence stays out
  of displayed goals.
- Memory retains complete explicit instructions and complete project checkpoints
  without short text caps.
- The v3.17 draft-batch incident patches: queued reservations are not running
  work, a response-window overflow retries a smaller piece, compaction keeps the
  inventory of completed writes, write batches yield to chat I/O, reads retain
  what they clip, and host CLI stdout decodes for every structured reader.

## Schema v81 records the per-item work a delegated worker discharged

- **v81** adds one immutable row per (accepted contract, per-item requirement,
  universe member) that a delegated worker child proved it completed, together
  with the child's session and the exact logical call that settled it. The
  migration is additive — a new empty table, its index, and an immutability
  trigger. No existing table is altered and nothing scans historical payloads.

The current harness schema version is **81**. These migrations do not invoke
models or providers.

## Known boundaries

- **Delegated worker external writes do not work, and must not be relied on.**
  A worker child holds no live capability attestation, so an external mutation it
  raises is refused inside logical admission — and that refusal poisons the
  parent's accepted-turn authority for the rest of the turn. Measured live
  2026-09-10: ten workers each raised one external write, the parent then died
  with `exact_checkpoint_admission_exhausted`, every fan-out item was still
  checkpointed `succeeded`, and the destination was never touched. The item
  credit derives from the worker's prose, which is why a refused call still read
  as done. Schema v81 ships as recorded above but its credit path has never been
  exercised live.

  The supported shape is unchanged and proven: workers COMPOSE exact per-item
  payloads and the PARENT commits them as one approved batch, and parent-serial
  external writes work normally. Closing the delegated case requires minting a
  host call attestation for a worker call so the refusal happens at the gateway
  with a normal settlement; four narrower placements were tried and each broke a
  different invariant.

- **A completion review that cannot fire still blocks finished work.** On a BYO
  brain whose judge has no reachable credential, the verdict fails open with
  `fulfills: true`, the work completes and its external writes cross, and the
  turn is still handed over as `blocked` with a verification note. Measured on
  this candidate: a GLM-5.3 brain created a sheet, wrote and read back 12 cells,
  and reported `blocked`. An implementation of "an unavailable reviewer follows
  the brain" was attempted and withdrawn in this cycle: keeping the terminal
  `done` forces it to close an accepted-task authority the state machine refuses
  to close, so the turn was held anyway and lost its verdict reference on the
  way out. The correct fix is its own change.

- Reasoning is captured by every brain adapter and displayed by none. On the
  Agent SDK brain lane it is filtered at the adapter, so there is nothing to
  surface; `stream_token` is declared and consumed end to end but has no
  producer, so token-level streaming remains off.

- The release tag must point to a clean commit whose tree, build stamp, and
  daemon fingerprints match, with packed-candidate green on those bytes.
