# Clementine 3.0.1

A patch release for one scheduling defect found within minutes of 3.0.0 going
out, on a real machine rather than in a test.

## Missed schedules no longer stampede

When Clementine has been closed or your Mac asleep, any scheduled workflow whose
time passed is caught up on the next start. Each schedule already collapsed a
long absence into a single run — a daily 8am report fires once, not thirty
times. What was missing was a limit ACROSS schedules: several different
workflows whose windows were all missed could start in the same instant.

With more than one heavy workflow that is enough to exhaust the machine. The
daemon is then killed under the combined load, restarts into the same backlog,
and repeats — so being closed for a while could leave the app pegged and
unresponsive, with scheduled work never finishing. Longer downtime made it
worse rather than better.

Catch-up runs are now started one at a time. A missed window is not urgent by
definition — its moment has already passed — so the remaining ones stay queued
and start in turn moments later. Nothing is skipped, nothing is lost, and the
order is preserved. Workflows scheduled for the current minute are never
delayed by this.

If you want faster draining on a powerful machine, raise
`CLEMENTINE_WORKFLOW_CATCHUP_PER_TICK`. It is capped, deliberately.

## If 3.0.0 left your app unresponsive

Quit and reopen Clementine. Any workflow left mid-run is reported as
interrupted rather than silently retried, and you can restart it from the run's
card. If several scheduled runs had piled up, they now drain in order instead of
all at once.
