# v3.9.2 — external writes tell the truth, plus day-one live-fire fixes

Release type: reliability release. Every fix was root-caused from a live
incident and ships with that incident replayed as its regression pin.
Suite at the cut: 9,318 tests passing, 0 failures. Design property shared
by every fix: each change activates ONLY in a state that was previously a
failure; every previously-healthy state has a pin asserting byte-identical
behavior.

## External writes: settlement tells the truth

The headline wave. 14.85 days of live ledger showed messaging-class writes
(Slack sends, emails, Outlook drafts) with a 0% recorded success rate ALL
TIME — while the writes themselves were landing. Wrong bookkeeping armed
the duplicate-safety hold against phantom risks: one live 10-draft run
burned 81 tool calls at 43% refusals and created nothing. Four fixes, each
an independently revertable commit, each pinned with the live payloads:

- **Typed refusals settle as failed, never orphaned.** A never-started
  refusal (ambiguous account, data-quality checkpoint, gateway block) used
  to be flattened to prose by the SDK's error wrapper and settle "may have
  landed" — blocking its own corrected retry. Refusals now RETURN a typed
  no-dispatch result that survives to settlement: stamped failed,
  dispatch:not_started, freely retryable. Certified batches convert the
  instance back to a typed per-item failure so a refusal can never read as
  item success.
- **Acknowledgment detection recognizes real success payloads.** Slack's
  echoed message carries `bot_profile.deleted:false` — an attribute of the
  echoed ENTITY, not the operation — and it vetoed every Slack success.
  Outlook's success JSON was followed by an appended advisory banner that
  broke parsing. The failure walker now distinguishes envelope outcome
  fields (full authority) from echoed-entity attributes (never the
  outcome), and wrapped JSON parses through trailing banners. The three
  live orphaned-success payloads are pinned VERBATIM as fixtures with
  negative twins.
- **The account question is asked at most once per run.** Two connected
  Outlook accounts re-triggered "which account?" on every call. One
  positively resolved account per toolkit now holds for the rest of the
  run; an explicit pin always wins; two distinct accounts used in one run
  re-arms the ask (never guess between proven alternatives); the memo dies
  with the run.
- **Subtraction and honesty.** Dead prose marker parsers deleted (doctrine:
  provider-echoable text never authorizes replay — only the local typed
  instance proves no-dispatch). The gated MCP lane parks tool output ONCE,
  inside the bracket, so the exact-output receipt keeps its invocation
  nonce. ORPHANED_WRITE_RETRY now states the RECORDED settlement reason
  instead of always claiming "TIMED OUT".

True ambiguity (real timeouts, crashes mid-send, unprovable third-party
text) still settles ambiguous with the duplicate hold intact — that
protection is the point; it is now reserved for genuine uncertainty.

## BYO finals: a kimi answer in the reasoning channel IS the reply

kimi-k3 can finish a turn with finish_reason=stop, empty content, and its
entire user-facing answer in the reasoning channel. finalOutput is
assembled from content, so honest correct replies became empty finals,
fired the D_decision_unparsed retry ladder, and the harness discarded the
model's own words for the "reliable written summary was not available"
fallback — while the underlying work completed fine (two users, same
signature, same day). The BYO wrapper now promotes reasoning to content on
a stop-final with no tool calls and no content. Tool-call finals never
promote; content-bearing finals are untouched. Pinned with the live
payload verbatim. (Open follow-up, tracked: whether request shaping can
prevent the malformed shape at the source.)

## Workflow authoring: stale-version creation tests self-heal

Rapid iteration drifts a workflow definition while its creation test runs;
the activation guard rightly refuses to enable an untested version, but
handed the AUTHOR "run a fresh creation test" — after promising
auto-enable. Proven cost, same day: the race left a workflow disabled and
its 9am schedule skipped silently. When the only blocker is drift (never
deletion), the runner now queues a fresh test against the latest version
automatically — "re-testing the newer version now (run X)" — depth-bounded
at 2 so edits outpacing tests still terminate honestly. Six-case decision
pin; retest lineage rides the durable run record.

## Goals: required-keys criteria are checked in code, never judged

A live run's LLM goal-judge marked "output includes required keys: …"
unmet while its own note admitted all four keys were present — an 86%
verdict, an escalate advisory, and self-contradicting advice on a run that
was actually 7/7. The goal validator's deterministic tier gains its second
class: the workflow runner passes real structured step outputs, and
key-presence criteria resolve by literal lookup — authoritative both
directions, missing keys named exactly. Pinned with a hostile judge that
throws if consulted. This is the tactical backstop; the strategic fix
(pinned-goal provenance: goals carry only user-confirmed meaning) is the
named next wave.

## Workspaces: surfaces self-diagnose their wiring

A workspace's "Refresh from Salesforce" ran its runner for real (approval
→ execution → "ran ✓") and the output went nowhere — no data source
attached, the view a static snapshot. Every workspace view now gets a
wiring-health check at serve time: a runner-backed action with no data
source renders a dismissible advisory banner naming the problem and the
copy-ready "Ask Clem" repair line. Works on every EXISTING workspace with
zero re-authoring; advisory always — informs, never blocks; authored
labels escaped; the head bridge-ordering invariant untouched.

## Model windows: provider catalogs feed the evidence layer at boot

v3.9.1's window-observation layer had one feed (the console models page) —
a daemon whose models UI was never opened ran on registry seeds forever.
Startup now lists every configured BYO provider's catalog (fire-and-forget,
8s timeout, dead-provider safe) and records published context_length
values as durable observations.

## Compatibility

No flags, no new env knobs, no schema migrations. All commits are
independently revertable slices. Deliberately deferred from the
external-write wave (build only if the one-week ledger re-measure demands
it): reconcile id-bridge, harness-driven auto read-backs, batch resume. Known-open items tracked for the next
wave: single-owner outcome delivery (double-post dedupe), judge
thinking-off on the claude_subscription transport, cross-step grounding
