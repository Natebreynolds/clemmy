# v3.18.21 — Jev as the router, a chat that reads as a page, model accounts and coding runs

Release type: integration of four lines of work made after v3.18.20, on one
release branch from `main`: harness efficiency and the phone's model
settings; model accounts and provider credit; coding runs; answer streaming
and the chat redesign. The gates below ran on the release commit.

## What a user notices

**The chat reads as a page, and the answer streams in as it is written.**
- Replies render as a page on desktop and phone, with tables and links and
  no box around them; the chat column is a reading measure.
- A turn's work is one live line (what Clem is doing now, and the clock)
  that folds to "Worked 58s · 4 steps" and reopens to the steps.
- A question's suggested answers are one-tap replies, only while the
  question is the newest message.
- Under an answer: the file Clem saved, "Checked" only when a review passed
  ("Not checked" when none ran), what the turn touched, and the model that
  did the work.
- The answer streams into the chat as it is written. A draft is provisional:
  a draft that review rejects is taken back before the next one, and the
  delivered reply always replaces it. OpenAI-compatible backends that used
  to deliver a reply all at once now stream it.

**One place for model accounts.** Settings shows each provider account,
whether it is refusing work for lack of credit, and where to add more. A
prepaid account that runs out is marked until its next successful answer.
Connecting an app says what went wrong in plain words, and a Connect link
arrives with the account details already filled in.

**Clem runs Claude Code in its own worktree.** A coding task agreed in chat
becomes a durable run on its own branch: its activity streams into the chat
and a Coding card on desktop and phone, it can be stopped, and it reports
back. Pushes, pull requests, publishing, writes outside the worktree and
credentials are refused at the hook with a reason the agent can act on, and
Clem runs the tests herself before a turn counts.

**Who does each part of a request, on the phone too.** Settings on the
phone has one Models card: does the work, writes the final answer, checks
the work, helps in parallel. Each row names the model that will run and
picks from the connected catalog. A chosen writer writes the evidence-heavy
final answer and is reviewed by a model from another family. Desktop,
phone and chat save role choices through one owner.

**Jev works as the fast router and simple reviewer it is built to be.**
- At the start of a request, one Jev request decides whether a remembered
  run fits and which single operation the request needs, so the brain calls
  it directly instead of paying a search round. The wait is bounded at
  1.5 s, and a remembered run that only shares words with a request is
  checked instead of taken on sight.
- The final-answer check asks five typed yes/no questions over compact
  state inside Jev's documented budget, where one broad verdict over the
  whole evidence dump used to fail on research turns. A NOT-DONE from Jev
  is never final; the reviewer decides it.
- Every Jev call names a pinned model (`jev-1.13.0`) and leaves a decision
  record, so its thresholds can be measured against outcomes.

**A scheduled workflow's checker sees what the run did.** The calls a
scheduled step made reached the run's goal and target reviews as "0 logical
settlements, no retained execution evidence", so a strict checker failed
runs whose work had landed: a scheduled refresh that read six record sets and
saved one dataset was reported as failed on two mornings. The reviewers now
see each step's authenticated result, a write step's receipt, and the write
contract the tool registry declares for it ("an exact replay of the same
content adds no write").

**A request for two operations keeps both on the first discovery page**,
the regression named under Known limitations in v3.18.20.

## Known limitations, named honestly

- Jev's confidence thresholds are not yet calibrated; the decision log
  started collecting the data for that with this release.
- Turn-start routing offers only operations the request names by a
  distinctive word; an operation never used before still costs a search.
- The model that checks the work is the owner's choice. A flagship checker
  makes completion reviews and escalated watcher windows the slowest and
  most expensive part of a turn.
- The model accounts work was committed from its agent's worktree for this
  release; its own tests pass and the installed-app acceptance below covers
  it.
- Coding runs: `project_run start` stays closed; runs start only through the
  chat dispatch.
- After a failed goal check, a workflow whose step wrote something is still
  escalated rather than re-run, even when that write is content-addressed.
- Windows: signing secrets remain absent; this tag is Mac-only.
