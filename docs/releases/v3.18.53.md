# v3.18.53 — every model you add to your API account can do any job, and a rule Clem already knows no longer ends blocked

**No database migration** (harness schema stays at 99). The Mac build comes
from the release workflow (signed and notarized). The Windows x64 build of
the same commit is qualified by the private Windows pipeline from this tag,
**unsigned** until a code-signing certificate exists.

## Choosing models on your own API account

- **Models you add stay added.** On the first API account you connected
  (for example Together AI), models you ticked under "Browse models" were
  dropped when you saved, so you could not pick them later.
- **Any listed model can take any job.** Picking one of that account's
  models as the brain, helper or checker was refused with "no longer
  connected" even though Settings listed it as available. Every model the
  account lists can now be picked under "Who does what", so you can move
  costly jobs onto cheaper models. A workflow that names its own model
  still uses that model; change it on the workflow's page.

## Clem's answers

- **Restating a rule she already remembers finishes normally.** Telling
  Clem a rule she had already saved could end the turn with "I can't
  confirm it was saved". When her memory already holds the rule, the turn
  now ends as done.
- **Your notes on a review are yours.** When you ask for changes on a
  workflow's review card, the facts in your note are treated as your own
  information to include, not as something Clem made up.

## Needs you

- Repeated failure notices from one workflow show as one "Stopped" row
  instead of one row each, and a workflow's notices fold into its open
  question. A finished draft no longer shows as stopped.

## Known gaps

- Rehearsal and cancelled workflow runs can leave "Approve" cards in Needs
  you that do nothing when tapped.
- A workflow that reviews a draft as its own step can stop after you
  approve the review.
