# v3.18.51 — a typed answer reaches Clem, retrying a stopped run continues it, and an API model in the brain picker can be chosen

**No database migration** (harness schema stays at 99). The Mac build comes
from the release workflow (signed and notarized). The Windows x64 build of
the same commit is qualified by the private Windows pipeline from this tag,
**unsigned** until a code-signing certificate exists.

## Clem answers what you type

- **A typed answer to Clem's question reaches Clem.** Tapping one of the
  question's options always worked. An answer in your own words ("I approve
  this copy and use the fresh 87") gets a quick check of whether it settles
  everything; when that check could not run, the app held the task and
  replied in its own voice: "Your reply is recorded. I couldn't verify how
  it changes the pending question…", with the question shown again. Clem
  now reads the reply herself against the exact question: she carries on
  when it answers, applies a change exactly as you stated it, and asks
  again in her own words only if it truly does not answer.

## Workflows that stop short

- **Retrying a stopped run continues it.** Saying "try again" after a run
  stopped one step short used to start the whole workflow over, repeating
  the drafts, records or messages the stopped run had already made. Clem
  now continues the run from where it stopped, the way the board's
  Continue does: steps whose changes landed are kept and not repeated, and
  only what is left runs. If the stopped step may already have changed
  something, she says so instead of risking a duplicate.
- **A fresh run that would repeat changes asks first.** Starting the same
  workflow with the same inputs as a run that stopped after making changes
  no longer starts silently: Clem is told which steps already made
  changes, and continues the run or, when you want everything again,
  starts over on purpose. A run with different inputs starts as usual.
- **A blocked step names the call that failed:** its tool, whether it was a
  read or a write, and how it ended, so Clem can tell you what broke
  instead of "1 business call failure".
- **No more `revert heal <id>` question.** When a workflow fails three runs
  in a row, its report named a placeholder Clem then asked you to fill in.
  It now names the workflow's latest automatic change by its real id, or
  says nothing about reverting when there is none.
- **A run waiting on a provider says so once.** A parked run's status tells
  Clem nothing changes before the retry or your answer, so she tells you
  what she is waiting for instead of re-checking it a dozen times.
- **A parked review is one card.** A review that parks a chat-started run
  shows its card in the chat without a second message in the app's voice
  carrying an internal approval id.

## Models

- **An API account's model in the brain picker can be chosen.** The picker
  listed every model of a connected API account (for example a Together AI
  DeepSeek model), but choosing the account's worker model while Clem's
  brain was a Codex or Claude subscription was refused with "The selected
  API model is no longer connected". It now switches, and stays routable.

## Memory screen

- **The memory graph stops using the CPU when it is still.** Its intro
  orbit turns for eight seconds; the graph then renders only while
  something moves or you touch it, and sleeps when the window is hidden.
  An open Memory screen had kept the renderer and GPU busy indefinitely.

## Release health

Tests that pinned the old behaviour were updated to the new behaviour. The
one CI-only failure carried since v3.18.44 ("durable memory completion
obligation holds pending intake") is unchanged; it passes locally.
