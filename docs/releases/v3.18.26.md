# v3.18.26 — Needs you you can scan, Clem in her own words, no freezes

Mac-only release. No schema change (88). Qualification and live evidence
below are recorded as measured; signed and notarized artifacts come from the
release workflow and are not claimed here.

## What changed

### Needs you, redesigned (desktop and phone)

- Every kind of waiting item (question, plan, approval, suggestion, Workspace
  choice, stopped workflow, update) reads as the same one-line row: what it
  is, for what work, how long ago. Ordinary questions and plans are quiet;
  the warning colour is kept for a workflow that actually stopped.
- On the desktop, the selected item opens in one pane: a short heading, what
  you need to decide, the reasons and identifiers behind "Why" and "Technical
  details", and the buttons in a footer that stays in reach however long the
  content is. A narrow window shows the list, or one item with Back.
- On the phone, the list opens one card at a time with Back; Back returns to
  where you were in the list, and a typed answer is kept. Long questions fold
  to their first lines so the answer box stays near.
- A long question leads with its own first line; the rest moves below it,
  nothing cut and nothing repeated. A reference id is never the line you read.
- An update that belongs to a conversation or a workflow links straight to it.
- "Clear all", which declines every decision, now lives in a Clean up menu
  that says exactly that, next to cancelling approvals older than an hour.

### Today

- From Clem reads as Clem's messages. Opening one shows what it is about, the
  reply box and the quick answers, one at a time; a typed reply survives
  closing it.
- The Needs you column no longer approves from a two-line preview: "Review"
  opens that exact item beside the content being approved. A question can
  still be answered right there once opened.
- A Space tile's view, size and refresh options live in one menu; Refresh
  appears on the tile only when its data is stale or a source failed.
- Chat says where you are ("Chat", not "Today"), and every composer control
  has a word: Project, the agent, the model. A stand-in model is labelled
  "stand-in" with the reason.
- The sidebar recedes so the page leads: smaller icons, a neutral current
  row, a little more space.

### Goals are yours

- The Goals page leads with your goals: what you are working toward, which
  Clem anchors her work to and reports against. With none set, it says what a
  good one looks like ("My team books 10 appointments a week").
- The objective each workflow run binds for its own completion check is no
  longer shown as a goal. Those fold into one "Work Clem is tracking" line,
  open by default only when one needs you, listing active runs; finished
  ones are kept a week as before.

### Clem in her own words

- Each From Clem item is said in Clem's own words, with when it happened
  taken from the item's date and the time now, and offers only what the item
  says can be done. Reply to any of them in yours.
- Clem has her own pinned conversation; a reply in it continues the same
  thread, from the desktop or the phone.
- A From Clem reply settles once: each post has a durable key, a reply is
  checked against the version you were reading, and a retry never acts twice.
- Newest first; "waiting on you" is a tag on the row, not a sort that buries
  a fresh finding.

### Reliability

- A lock this process failed to release no longer freezes the app. This was
  the cause of the 10-01 4 PM workflow failures (a full disk stranded a Space
  lock and every later write waited 10 s on it).
- One missed connected-account check no longer refuses a send; the re-check
  stays inside the caller's deadline.
- A run resumed after a long pause is no longer cancelled as "silent" for the
  length of the pause.
- A local command that exits non-zero returns its result instead of ending
  the turn; a configured local write carried through a tool call runs on its
  first try; a requirement id that names the operation itself runs it; a
  carried write's bad arguments are named instead of a bare refusal.
- Workflow input defaults are read one way everywhere: 0 and false are
  values, and a list default is named before the workflow is enabled.
- A greeting with a name or a pleasantry is still a greeting; "got it" is not
  a question to clarify. Questions keep their tools.
- Heartbeat and From Clem model usage is attributed to its own source, so a
  turn's cost receipt can be certified complete.
- Clem's own Claude sign-in survives a slow network. Anthropic replaces the
  refresh token on every refresh; a refresh abandoned after 15 s that the
  server completed threw the new token away (the grant died that way on
  10-02). Refreshes now run one at a time per token, outlive the request
  that started them, and save whatever they return; a token another refresh
  already replaced no longer marks the grant dead.
- No more 10–56 s freezes when scheduled workflows start: a synchronous lock
  request for a file held by async work on the same thread now fails fast
  (it could never succeed by waiting) instead of freezing the main thread to
  its timeout; any sync lock wait over a second is reported by file name.
- A "Run failed… run it again?" item retires once a later real run of the
  same workflow succeeds; a Noticing proposal whose question was closed
  stops asking.
- Command-line tools are found on the owner's default Node install, not the
  highest-numbered one (a stale install had left the Codex CLI reading as
  signed out since 09-01).
- The Agents SDK tracing exporter no longer runs without a key it can read,
  which removed a log line after every turn.

### Under the hood

- How a decision reads is one shared presenter for desktop and phone.
- The shared presenter package's tests now run in the ordinary suite (only a
  release-time subset ran before, and one rule had gone red unnoticed).
- The live A/B kit (`scripts/live-ab`) is in the repository and its rules are
  in the ordinary suite.

## Known limits

- Physical iPhone, dark theme and long-pause resume on a real run are not yet
  checked live; long-pause resume is covered by tests. Targeted live checks of
  workflow author/enable, connection/approval correction and desktop↔phone
  continuation are owed; From Clem reply retry is covered by tests.
- A "Run failed" notice for a workflow can carry no workflow reference, so
  Needs you cannot link it; it offers Dismiss only.
- Needs you has no search or filter yet.
- Chat itself is unchanged in this release.
- The CI test workflow's journey job has been red since 08-30 (partition-ledger
  timing and an ordinary-conversation expectation); local journeys are
  addressed separately.
- The harness database grows with every long task (each model batch stores
  its whole history). A lossless retention plan is designed; it ships in a
  later release with its own schema version.
