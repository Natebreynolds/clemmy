# Clementine v3.7.0

Release notes — 2026-08-04

This release makes everyday conversation trustworthy under real use. It was
driven by a live user session: typed approvals that applied nothing,
questions that spawned unwanted background tasks, and internal settlement
language surfacing where a plain answer belonged. Each of those is now a
deterministic behavior with a regression pin, alongside the continuing
graph-engine and capability work underneath.

## Approvals that just work

- Typing "Approved" (or "approve apr-xxxx", or "reject …") in the chat that
  spawned a background task now applies the decision directly to that task —
  the same durable continuation the Tasks board button uses — and the task
  resumes immediately. Previously these decisions could fall through to a
  fresh model turn that could not reach the task's approval at all.
- Replies lead with the work you recognize: *Approved — "CRM draft cleanup"
  is back underway and will report back here when it's done.* Card ids no
  longer lead the sentence.
- Ambiguity asks instead of guessing: with several tasks waiting, the reply
  lists exact choices and applies nothing until you pick.
- The same settlement runs on desktop, mobile, and channel surfaces alike.

## Conversation stays conversation

- A question ("what needs to be done to finish this task?", "how's it
  going?") is answered — it can never mint a background task. Only naming the
  background lane explicitly routes work there.
- Steering an already-running task ("keep working — and remember, no customer
  accounts") reaches that run instead of creating a duplicate sibling task
  titled with your reminder.

## Plain words when something is uncertain

- Every "cannot confirm this write" hold now says what it means in plain
  language and ends with an action you can take — say "check it" and
  Clementine verifies what actually happened. No more "read-only
  reconciliation attempt" prose, and no dead ends.
- After an approval is applied, a turn that failed to compose a summary says
  the approval WAS applied and not to approve again — never "send that
  again", which would have double-approved.

## Workflow writes unfreeze themselves

- A provider that rejects a request for invalid arguments ("fields are
  missing") is now recognized as proof that nothing was changed — the model
  fixes the named fields and retries once, on its own. Previously such
  rejections were treated as "the write may have landed", which froze
  workflows in a verification protocol with a human-attention flag for a
  mistake two corrected arguments would fix. Real ambiguity — a timeout after
  a genuine send — keeps every duplicate-send protection.

## Graph engine and capability groundwork (Clem 4 track)

- The workflow dispatch core runs on the shared graph executor; chat turns
  drive through the compiled turn-graph spine on both brains.
- Every agent build now seals its full admitted capability universe (every
  deferred tool with the schema it actually ships) with the active surface as
  binding revision 1; each schema-on-demand acquisition is recorded as a
  monotonic revision within that universe. Enforcement lands against these
  artifacts in a later release.
- A shared activity endpoint (`/api/console/activity/v2`) serves
  truth-preserving run snapshots (queued is never running; blocked is never
  idle; terminals are copied, never inferred) for client surfaces to migrate
  onto.

- Every fix above ships with a deterministic regression pin, most using the
