# v3.8.0 — verified procedural memory, exactly-once continuation, durable fan-out, unified activity

Release type: feature release. Four production capabilities, each shipped
with its causal test matrix and, for the memory loop, a live canary run
against a real connected workspace. Full evidence:
`docs/releases/v3.8.0-release-candidate-evidence.md`.

## Clementine learns the reads she has proven

One verified successful read — settled through canonical failure detection,
async job resolution, and a typed durable receipt — teaches the capability,
its live provider contract, the stable account it ran against, and a
privacy-bounded alias for how the user asked. On later turns, exact repeats
and natural paraphrases (local semantic retrieval, ~3 ms warm, never a
provider call) surface those proven capabilities to the brain as ADVISORY
candidates: the brain still chooses the tool, the arguments, and the
account, and every dispatch still crosses the governed gateway. A wrong
candidate costs one ordinary cold turn. Measured over 30-sample live
cohorts: warm turns cut discovery calls by 55%, with a fast tail of
memory-served answers in 4–17 s; end-to-end wall-clock in MULTI-account
workspaces stays comparable to cold because the brain still asks which
account (see limitations) — the win there is fewer provider calls, not yet
faster turns.

Fail-closed by construction: error payloads, thrown dispatches, unresolved
job handles, and unverified bodies never learn; a capability whose provider
contract has moved stops serving until a fresh settlement re-proves it; a
brief that read two accounts keeps both provenances; replays lose the
exactly-once claim. Learning was proven live against a three-account Outlook
workspace, including semantic retrieval of a fresh paraphrase.

## Moving work to the background is exactly-once

The foreground→background handoff is now a transactional SQLite state
machine: durable transfer intent and a digest-verified continuation capsule
are written BEFORE the foreground is fenced, transitions are monotonic with
an atomic revision CAS (proven across processes), and boot reconciliation
converges every interrupted handoff to exactly one owner. A turn that moved
to the background reports as TRANSFERRED with the task named — never as
cancelled.

## Many-item work runs on the durable scheduler

A typed manifest on `dispatch_background_task` (the brain's own plan — no
second classifier) compiles into an immutable plan contract plus a durable
item×phase journal. Windows become real background tasks with bounded
concurrency and restart reuse; items settle exactly once through
`fanout_settle_item`; reducer readiness is a query over the journal and the
reducer is admitted through a once-only lease. Proven at 40, 120, and 514
items through the real scheduler, including a mid-window crash whose restart
reused every settled item and still reduced exactly once.

## One activity truth on every surface

Slack and Discord progress messages are now driven by the shared transport
reducer over durable run state (one kickoff, rate-limited milestone edits,
one final replacement), and the console serves a single server-owned
activity projection covering chat, background work, and workflows —
liveness from leases, never message age; Working Now gated server-side to
detached/scheduled/long work; no client heuristic can turn an unresolved
terminal green.

## Hardened in the second review round

- Learning is one pipeline: settlement writes a durable pending-learning
  record and a bounded worker materializes off the tool-return path; the
  legacy auto-remember write path (which persisted historical invocation
  arguments) is retired; receipts are identity-bound and every binding
  validates; schema-bound retrieval declines without live catalog authority;
  two accounts stay two candidates into both brains.
- The handoff ladder takes exactly one pinned rung at a time, reserves its
  background task id inside the transaction, awaits reconciliation before
  daemon readiness (failing readiness closed on a store error), and capsules
  carry monotonic revisions with checkpoints at every durable lifecycle
  boundary — a worker follows a legitimately evolved capsule and parks on
  tamper or rollback.
- Fan-out plans derive identity from the complete admitted contract, enforce
  phase dependencies at settlement, authenticate every worker settlement
  against its claimed window and generation, keep internal windows silent
  (one kickoff, one reducer terminal on the persisted route), and run the
  reducer through a real lifecycle with bounded retry and full-journal
  paging.
- The activity projection is the ONLY activity truth: the console's client
  reducer is deleted, and the notch, Slack App Home, and Discord status read
  the durable projection.

## Also in this release

- Background drain concurrency is measured against the durable running count
  (policy-capped), so fan-out windows genuinely overlap.
- The local embedding model's weights cache is machine-level: a fresh
  install or second workspace no longer re-downloads ~130 MB.
- Learning on a clarification-answer turn binds the alias to the question
  that named the intent (when the ask is structurally marked).

## Known limitations (stated, not hidden)

- A clarifying question the model asks in PROSE (without the ask tool)
  commits as an ordinary answer, so an alias learned on that answer turn is
  weak. Structural asks are handled; classifying prose is deliberately out
  of scope.
- Retrieval candidates are advisory; a brain may still ask which account to
  use on a warm turn in multi-account workspaces.
