# v3.18.34 — Clementine on Windows, and a steadier Clem on both

Harness schema stays at 93; no database migration. The Mac build comes from
the release workflow (signed and notarized). The Windows x64 build of the same
commit is qualified by the private Windows pipeline from this tag and attached
to this release, **unsigned** until a code-signing certificate exists: a fresh
Windows install shows SmartScreen's "Run anyway"; updates install normally.

The first Windows tester's day drove most of this release: every fix below
came from a real failure on their PC or from the owner's own Mac.

## Reports, models and speed

- **Reports land where you look.** When a scheduled workflow tells you its
  result (a morning briefing, a trends report), it now shows in From Clem on
  Home, desktop and phone, with its full text, Open run and Done. It is also
  posted once into Clem's pinned thread, as she wrote it. It counts as
  finished work, so a registered phone is notified. Before, it was one plain
  row among hundreds in the inbox and a desktop toast. The inbox's
  notification detail now links to its run, and the Notifications tab leaves
  out silent history.
- **Only the models you connected.** A new home whose only model is Claude,
  or a BYO model, used to block every chat on a Codex login it never had.
  The brain now runs on the model you connected (an explicit Codex choice is
  never moved). Signing in to Claude makes it the brain even when an OpenAI
  key is saved: Clem runs agent work on subscriptions or your own model, and
  uses an OpenAI key for voice and embeddings only. Switching the brain to
  Codex needs a Codex sign-in, a rate-limited worker falls back within the
  connected brain's family, and scheduled jobs wait instead of failing on a
  home with only an OpenAI key.
- **Lighter reviews on reads.** A turn that only reads gets one light review
  instead of a full one: about 60% fewer review output tokens in the same
  live checks. Work that writes or sends keeps the full review. A cancelled
  turn now cancels its reviews and retries; Jev's check has a hard deadline;
  a turn that only repeats earlier results can settle on them; a workflow run
  that only reads or writes local files gets the lighter review (Codex's
  round).
- **The tray icon shows** on Windows and macOS. It was drawn from an SVG that
  Electron turns into an empty image, so the menu with Open Console, Save
  Diagnostics, Restart and Quit sat in an invisible slot.
- **Background memory follows your memory model.** The check that reads each
  message for a standing preference now runs on the memory model you chose in
  Settings (it ran on the reviewer); with none chosen it follows the reviewer
  as before.
- **Fewer wasted rounds.** A tool call with the wrong arguments gets the
  tool's own schema back inline; a carrier call missing its name is told
  which; every model knows a Mac's shell uses BSD tools. A workflow review
  reads setup notes in a description ("enable it, then switch off the old
  schedule") as configuration, not work the run owes.

## Spaces

- **A Space shows what feeds it:** the workflow, its last and next run, Run
  now, and what changed in each collection since the last real change.
- **One schedule.** A collection a scheduled workflow fills is refreshed by
  that workflow only; Refresh runs the feed. Other sources keep their timer.
- **Live data.** A page can subscribe to its data (`clem.onData`) and update
  without reloading; a Space's chat history is there when you reopen it.
- **Safer edits.** Clem's page edits land whole or not at all, can be undone
  to an exact earlier version, and errors on the page are caught and offered
  to Clem to fix. Pausing a Space yourself is never undone by a retry.

## What changed

- **Windows starts.** Every Windows credential read launched the native
  permission check four times, synchronously. The daemon was alive but never
  answered within 90 s and was stopped. An unchanged credential now reuses its
  verified permissions (a changed file, or a change to its permissions, is
  checked again at once). First launch answers in about 15 s.
- **A Claude call can no longer crash the daemon.** npm's real `claude.cmd`
  is now recognised on Windows (the old check expected one space where npm
  writes two, then started a shell script Windows cannot run). A Claude CLI
  that fails to start now fails that one call; it used to end the whole
  daemon and the app showed "Clem needs to reconnect".
- **Local projects are found where people keep them**, on both platforms:
  directly in the home folder, Documents\GitHub, source\repos and OneDrive.
  Linking a found project adds exactly that folder to Clem's work folders.
  Adding a folder in Connect no longer drops the default folders.
- **"Your computer", not "your Mac".** Clem's own guide no longer labels
  desktop-only places "(Mac only)", so she stops telling Windows users that
  things are Mac-only; about a hundred strings across the app, the phone and
  error messages say "your computer". macOS-only settings and hints (the
  notch, macOS permission dialogs, `brew`) show on macOS only.
- **Save diagnostics for support.** One redacted file (secrets, tokens,
  email addresses, your user folder and computer name removed) from the tray
  menu, the startup-error dialog or Help, even while the daemon is down.
- **Dictation works in the desktop app.** The composer's microphone used the
  browser's speech recognition, which the desktop app exposes but cannot run,
  so the button did nothing on Mac and Windows. It now records and transcribes
  on this computer (the local whisper model Meetings uses) and the words land
  in the draft. Confirmed by the owner on the Mac.
- **Tabs open at once.** Every screen's code is fetched in the background
  after start, so a busy daemon no longer makes a tab look dead.
- **A slow boot is not killed.** A starting daemon that is visibly making
  progress gets more time instead of being stopped at 90 s (the owner's Mac
  looped for 17 minutes under memory pressure).
- **"Can't reach Clementine", not "could not be found".** A conversation
  that cannot load while the daemon restarts says so and retries, and the
  last-opened chat is remembered.
- **The projects list no longer stalls the daemon.** Project summaries share
  one task and approval read and one batched conversation query (on the
  owner's Mac this request held the daemon about 20 s at a time, 37 minutes
  in a day). From Codex's round.
- **Stop reaches an approved action while it runs** (Codex's round), and an
  approved action still runs once and ends in what it did. The first cut of
  that routing ran an approved off-machine command or connected-app send and
  then told the owner it "can't tell whether it went through"; that never
  shipped. Approving a real command is now pinned end to end with no
  stand-in for the tool.
- **Stop reaches the running command** and its Windows child processes,
  with a cleanup receipt (Codex's turn work), and a "yes" to a queued card
  goes to Clem again instead of a fixed host line.
- **Composio says why it can't be reached.** Connect showed "connected"
  (a key is saved) while the app list stayed empty and Connect did nothing:
  every listing failure was swallowed and the screen waited minutes on the
  provider's own retries. Connect now answers within about 20 s, names the
  reason in plain words (an untrusted certificate, an address that can't be
  found, no answer, a dropped connection, a rejected key) with Try again,
  and never shows "No apps connected yet" for a list that failed. A failed
  connect says the same. The daemon now trusts the certificates this
  computer trusts, so a network whose proxy or antivirus inspects web
  traffic works for Clem as it already did for the app window. On Windows,
  npm's `composio.cmd` is found instead of its shell shim.
- **Signing in to Claude on a home with no working brain** makes Claude the
  brain, on the chosen Claude model or Sonnet; a working brain is never moved.
- **Windows:** notifications are delivered (the app claims its installer's
  identity); project pages and files open in their default apps; no Bonjour
  attempt on boot.
