# v3.18.45 — Fewer steps per turn, a daemon that stays responsive, the current Claude models

**Database migration: harness schema 95 → 98** (additive; the live store is
carried forward in place, and the packaged upgrade check runs the v3.14
fixture through to 98). The Mac build comes from the release workflow (signed
and notarized). The Windows x64 build of the same commit is qualified by the
private Windows pipeline from this tag, **unsigned** until a code-signing
certificate exists.

## Fewer steps per turn

- **A read is checked once.** When Clem fetches or looks something up and the
  reading covered what you asked, Jev's check stands on its own; the full
  second-model review no longer starts behind it and runs only when Jev gives
  no answer at all. A page read that took ~14 s with two checks now ends when
  Jev says it is done.
- **"Remember that …" is one review, not three.** A fact Clem's memory layer
  has already saved and verified completes the request; the reviewer is not
  asked to confirm a save the record already proves. A remember you asked for
  is placed by the standing review and is never rejected by it as "just a
  task". Saving a one-line fact went from ~80 s to ~40 s live.
- **A workflow step that says it writes may write.** A step you authored with
  a declared write (a CSV, a file) is covered by that declaration; it no longer
  needs a human gate card to be allowed to do what it says. A page-to-CSV
  workflow that blocked at its write step now runs end to end.

## The daemon stays responsive

- **The session list no longer rebuilds every preview on every poll.** The
  sidebar refreshes every 10 s; its previews were thrown away whenever
  anything in the store changed, so while Clem was working each refresh
  rebuilt 200 transcripts on the daemon's main loop (1–3 s each). A preview is
  now kept until its own conversation changes.
- **Workflow drains reuse finished runs.** Every drain parsed every run file
  (hundreds, 12 MB) to find the one or two still running, and a running step
  kicks a drain every few seconds. Finished records are reused until their
  file changes.
- **The Space scheduler lists Spaces once a minute, not every tick**, and
  paused Spaces are retried on a slower cadence.
- The hourly run reaper, the active-work inventory and the first message after
  a start or a model switch no longer freeze the loop (bounded worker reads,
  no re-hashing of unchanged files).

## Approvals

- **A tapped approval runs the stored action, once**, even when no live run
  holds the chat; the result is shown on the card and preserved across desktop
  and phone.
- **A card you do not answer goes away** when you send another message; the
  conversation moves on with you.
- Exact approval results, preparation steps and routing are bound to the
  accepted request that produced them, so a resumed approval can neither
  replay nor drift.

## Models

- **The Claude picker lists the current family** — Fable 5.1, Opus 5.5,
  Sonnet 5.5, Haiku 5.5 — from the subscription handshake, with the verified
  presets beside it. Memory and review jobs run on the model you choose for
  that role.

- **After you tap a card, the result is in Clem's words.** The line under an
  approved action is written by Clem from what actually ran ("The local check
  finished and showed…"), on whichever brain you use; before, a brain reached
  through an OpenAI-compatible connection could never author it and the card
  kept a fixed sentence.

## Fewer steps for her own tools

- **A tool Clem names with her own label runs the first time.** A command or
  workflow run whose request label Clem made up ("read.page") was refused as
  "not yet published" and sent her to search for the tool's exact name before
  retrying — two extra steps on the first use of a tool in a chat. The named
  tool and its arguments are the call.
- **Tool schemas land after one deferred turn in a long chat.** To keep a big
  prompt cached, the desk could defer sending a tool's schema indefinitely in
  a long conversation, so every new tool cost a search step; the deferral is
  now one turn.

## Known issues

- When a Space refresh's own run rewrites a file after the reviewer checked
  it, the turn can end "needs a look" even though the review passed; the reply
  itself is right.
- A write that has to leave this computer still takes extra preparation steps
  before its card appears.
- The Windows build is unsigned.
