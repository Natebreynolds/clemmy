# Clementine v3.6.3

Release notes — 2026-08-03

This patch moves Clementine's chat and long-running work onto one durable
graph contract. A natural request can start direct work, a compiled project,
or several background workflows without turning internal execution protocol
into the public answer. Every accepted source owns its work, tools, restart
state, and one terminal response.

## Faster, quieter chat

- Direct requests receive exact worker tool leases instead of the full tool
  surface. This reduces tool-selection noise while preserving on-demand
  discovery for connected tools and skills.
- Background workflows transfer ownership through a nonterminal dispatch
  edge. Chat can acknowledge the work and become available for the next
  request instead of polling or narrating each internal step.
- Several workflows accepted from the same user message form one source group.
  They can run independently and reduce into one evidence-backed terminal
  response after the complete group settles.
- Foreground chat no longer creates a misleading **Working now** card. That
  surface now represents durable background work, uses exact card identities,
  and reports honest activity recency.

## Durable projects and workflows

- Long-horizon project requests compile into a validated, persisted topology
  with immutable source, plan, capability, and run identities. Restart
  recovery resumes admitted work without asking the user to repeat it.
- Catalog workflows and compiled project roots retain separate authority and
  storage lifecycles. A malformed project record cannot widen into an ordinary
  workflow or block unrelated catalog runs.
- Model work, deterministic reduction, fan-out, convergence, mutation
  receipts, and the single public terminal are represented by graph state
  rather than conversational confirmation beats.
- Source-group admission is linearized across processes. A retry reuses the
  same canonical run even after it terminalizes; group close cannot strand a
  late member; and retention cannot delete a shared run during its pre-pin
  admission window.

## Exact effects, recovery, and delivery

- External evidence is bound to the exact tool invocation that produced it.
  Failed outputs, ambiguous writes, stale discovery, and unfamiliar mutations
  cannot certify success.
- Notification destinations are frozen into a durable delivery plan. Each
  destination owns its attempt, receipt, retry generation, and completion, so
  one successful channel cannot hide another channel's failure.
- Discord, Slack, gateway, desktop, and restart recovery consume the same
  accepted-source outcome. Delivery may be retried indefinitely from durable
  evidence without repeating completed workflow work.
- Cross-process JSON and run-record locks fail closed, recover verified dead
  owners, and preserve the directory durability needed across process or power
  loss.
- Terminal presentation strips compact internal protocol and secret-tainted
  branches before publishing a user-facing answer.

## Scope and compatibility

The behavior is global. It is not keyed to Platform 49, a particular prompt,
workspace, workflow shape, provider, or channel. Existing catalog workflows,
scheduled runs, memories, approvals, and v32 homes remain compatible.

`CLEMMY_CONFIRM_FIRST` remains enabled by default for the first irreversible
same-shape batch send. The retired `CLEMMY_CONFIRM_BEAT` mechanism is not
restored; durable graph nodes and typed receipts now own continuation and
terminal correctness.

The experimental runtime-bound project adapter lane is not included in this
patch. It remains separate until its local-write authority and artifact
identity contracts complete review.

## Verification

The release candidate passed 8,716 tests with zero failures and one documented
skip, 201/201 workflow-runner tests, 40/40 release-asset tests, TypeScript
typechecking, public-repository hygiene, and adversarial crash/restart tests for
source admission, group closure, exact delivery, reaping, compaction, and
project-terminal recovery.

## Toward Clementine 4

v3.6.3 is the durable graph-and-delivery foundation for Clementine 4. The next
iteration can focus on measured latency, token budgets, bounded specialist
fan-out, capability retrieval, and indexed large-workspace performance without
reintroducing prompt-specific classifiers or conversational gates.
