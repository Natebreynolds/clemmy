# v3.18.40 — Workflows you describe get built, tested the way they run, and run

**No database migration** (harness schema stays 94). The Mac build comes from
the release workflow (signed and notarized). The Windows x64 build of the
same commit is qualified by the private Windows pipeline from this tag,
**unsigned** until a code-signing certificate exists: a fresh Windows install
shows SmartScreen's "Run anyway".

## A test is the real run, rehearsed

- **A creation test now follows the same path as the real run.** Reads run
  for real, and anything that would make a change is shown as a preview
  instead of being made. Before, a test took a different path and failed where the real
  run would not: a research or monitoring step was refused its own
  authority ("authored write authority refused…") and the workflow stayed
  off.
- **The test builds the same graph a run builds**, so a workflow that passes
  can't fail its first run on a rule the test skipped. `forEach` accepts the
  same spellings everywhere (`steps.<id>.output`, `<id>.output`, a step id).
- **`workflow_test` rehearses any saved workflow without turning it on or
  off.** Enabling a workflow rehearses it first, and says so.
- **Structured calls refresh their provider check before they run**, so a
  scheduled run or a test no longer fails with `live_observation_missing`
  when nothing else had used that tool in the last minute.
- **Clementine's own tools run as local calls in workflow steps** on every
  model, so a file read on a bring-your-own model counts as the success it
  is, instead of leaving the step "not complete".
- **Monitors keep their own memory.** A step may read and update its own
  workflow's "already seen" ledger. A test leaves that memory untouched.

## Clem knows how to build a workflow

- **A built-in workflow-builder skill ships to every setup.** It covers how
  to:
  - shape steps and declare what each one does;
  - wire data between steps;
  - find exact tools;
  - rehearse a workflow instead of running it;
  - read a rehearsal and fix only what it flags.
- **She tells you what a run costs before she saves it.** That includes how
  many agents a run starts, about how long it takes, and what it changes.
  When a step runs an agent per item, she offers a cheaper alternative in the
  same message ("cap it at 10", "only new items", "batch it").
- **A missing app is something to connect, not a question or a failure.** A
  rehearsal says "needs X connected here" and the workflow stays off.
- **What a step does is decided by what its provider declares.** A step's
  tool counts as reading or changing things based on the provider's own
  description. Where the provider leaves it open, a model reads the tool's
  description and decides. A tool's name no longer decides it, and the
  special rules for two named research providers are gone. A verdict is
  re-read when the tool's definition changes.

## Honest reports

- **A test only says "I turned it on" after it did.** If turning it on is
  skipped or fails, the report says so and why. An account choice is saved
  after the workflow is on, so it can't stop it from turning on.
- **A run flagged for attention says why** ("target not confirmed",
  "goal not met"), and a rehearsal of a workflow with a goal says the goal is
  judged on real runs.
- **A read that answered in plain text no longer counts as a failed call.**
  A read that threw still does.

## Shared workflows

- **An imported workflow belongs to the setup that receives it.**
  - It arrives off.
  - It drops the author's accounts, connections and model choices.
  - It is rehearsed before it can turn on.
  - It turns on only if its author had it on and it passes here.

## Smaller fixes

- `workflow_create` accepts a workflow-wide tool list.
- An object sent where the schema keeps a JSON-text twin (`args` /
  `args_json`) is moved there instead of refused.
- Editing or enabling a workflow gets the time its test needs.
- A workflow step's prompt is never read as a request for Clem to save a
  personal memory.
- Multi-action tools mark their read actions, such as `workflow_state get`
  and `working_memory read`.
- The install guard accepts the blockmap the updater keeps beside its
  download.
