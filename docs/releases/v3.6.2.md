# Clementine v3.6.2

Release notes — 2026-08-01

This macOS patch restores concise, evidence-grounded chat completion without
changing the v3.6 workflow or memory schemas. A Windows artifact is not
included because the production Windows signing identity is not configured;
the release uses the documented `[mac-only]` path rather than publishing an
unsigned installer.

## What this patch fixes

A deferred tool request could be malformed before the real provider tool was
dispatched. The outer `call_tool` transport carrier was then mistaken for a
second external-write boundary, producing a false orphaned-write record. Chat
treated that record as unresolved work, entered extra reconciliation turns,
and could replace an already-correct answer with compact internal completion
protocol.

v3.6.2 makes the graph boundaries explicit:

- `call_tool` is a transport carrier. Only its validated inner tool owns the
  provider reservation and settlement lifecycle. A local validation refusal
  records typed proof that dispatch never started, without creating an orphan
  or poisoning a later corrected provider success.
- External-write completion remains fail-closed for genuine provider failure
  or ambiguity. A successful write cannot mask another target's failure, and a
  local carrier refusal cannot certify a write.
- Effect and artifact recovery is an evidence-only reconciliation node. It can
  add read-back evidence and settle durable state, but its prose has no public
  answer authority. Settled evidence releases the original verified answer
  exactly once; unresolved evidence produces a deterministic blocked terminal.
- Public terminal presentation rejects compact decision protocol such as
  assignment-form `done` and `nextAction` fields.
- Discord and Slack consume one canonical tool event rather than provider
  transport mirrors. Public progress uses only the runtime-owned canonical
  tool name; deferred carrier targets and provider slugs stay generic until
  validated, and arguments, commands, paths, queries, and payloads remain
  private.
- Explicit requests such as “do not narrate your plan or tool calls” select a
  request-scoped quiet presentation: generic elapsed progress, approvals,
  questions, errors, and the final answer remain visible, while internal
  agent/tool narration and partial structured output stay hidden.
- The hard per-turn tool-call ceiling remains terminal. Correctable local
  validation failures can be repaired below the ceiling, but over-limit calls
  cannot become a zero-cost retry loop.
- Code-mode idle time now starts from an ordered sandbox-ready signal rather
  than process spawn. Slow startup cannot consume the model program's idle
  budget, while the independent hard ceiling still bounds a sandbox that never
  becomes ready.

## Scope and compatibility

The behavior is global across chat tenants and tool providers; it is not keyed
to a particular workspace, workflow, spreadsheet, account, or channel. The
workflow graph, memory store, approval records, and v32 home schema are
unchanged and remain compatible with v3.6.1.

`CLEMMY_CONFIRM_FIRST` remains the irreversible same-shape batch-send safety
boundary. The retired conversational `CLEMMY_CONFIRM_BEAT` mechanism is not
restored; terminal correctness now belongs to typed graph evidence and one
authoritative terminal node.

## Verification

The release candidate includes biting regressions for malformed carrier input,
corrected writes, provider ambiguity, hard call ceilings, read-only no-effect
completion, settled and unresolved artifact/effect reconciliation, terminal
answer authority, compact-protocol rejection, sanitized canonical progress,
and quiet Discord/Slack presentation. It also passed an isolated replay of the
original Discord failure class in a fresh private home without contacting live
channels or write providers. Delayed-start sandbox regressions additionally
prove both healthy post-ready execution and fail-closed pre-ready hard timeout.

## Clementine 4 follow-up

v3.6.2 is the correctness freeze before the next graph-runtime iteration. The
next lane is to make intent, capability discovery, context retrieval, bounded
specialist fan-out, deterministic reduction, effect receipts, and terminal
publication first-class graph nodes, then measure latency, tool count, and
token use against representative chat and workflow corpora.
