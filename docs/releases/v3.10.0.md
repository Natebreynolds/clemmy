# v3.10.0 — approve once and walk away, steer her while she works

Release type: feature release. Four waves, every one root-caused from a live
run on release day and shipped with that run's evidence replayed as its
regression pin. Suite at the cut: 9,330 tests passing, 0 failures. All
commits are independently revertable slices.

## Autonomy: writes flow in autonomous mode

One "want me to go?" is the approval. A certified write batch now consults
the same layered approval authority every single tool call already uses
(plan scope, then your autonomy policy) — the batch lane used to card
unconditionally, which is why an approved 10-draft run stopped mid-flight
for a second approval. The formal approval edge and audit provenance are
still recorded; the card just doesn't park for work you already blessed.
Sends keep their card (the check-in-before-you-send default); a plan the
judge could not verify still routes to you as the fallback judge.

Two honesty corrections ride along:

- **Destructive writes require consent that names them.** DELETE-class
  provider calls used to classify as ordinary mutations and ride YOLO with
  zero gate (live: a mailbox delete executed ungated mid-run). They now
  card once in chat; launched cron/workflow/background lanes keep their
  autonomy grants, and the verb set is deliberately narrow so reversible
  bookkeeping (remove a label, respond to an invite) never nags.
- **Approval mirrors wait while you're in the app.** A desktop-origin
  approval used to DM Discord while the card was already on your screen.
  Mirrors now defer while a live session viewer is present and drop
  entirely once you answer; step away and they send. Fail-open on restart.

## Steering: talk to her mid-run without killing the run

Before this release, a chat message sent while a run was active SUPERSEDED
the running attempt — nudging Clem killed the very work you were steering.
Now the composer sends while she works: your message becomes a durable
steer note delivered to the model verbatim at its next tool boundary, on
every lane and both brains, exactly once. Steering is context, not
authority — a note that introduces a new external effect still meets the
normal approval path. Desktop and Discord have full parity; attachments
and control commands keep their existing paths.

## See the plan, see the image

- **The compiled turn plan is visible.** Every chat turn already compiles
  and executes through a real turn graph; the activity strip now shows
  "Planned: fan-out plan · 11 steps" the moment a turn starts. Shape only —
  hashes, policy internals, and the graph body are pinned private.
- **Paste images into chat, and Clem looks at the pixels.** Paste a
  screenshot straight into the composer; it uploads like a drag-drop, and
  the new read-only `view_image` tool hands the actual image to the
  vision-capable brain instead of settling for an OCR description. Native
  viewing needs no OpenAI key. Reads are confined to the attachment store,
  types whitelisted, provider size cap enforced honestly.

## Model lanes: never dial a lane you know is empty

Codex availability is now quota-aware. Auth alone was the whole check, so
judge chains and routing kept dialing an out-of-tokens lane — hourly
scheduled workflows turned that into an all-day 429 alert stream. The
provider's own captured quota headers (plus a direct 429 latch,
retry-after honored) now take an exhausted lane out of every judge chain,
route, and fallback; it rejoins by itself at the provider's stated reset.
Fail-open on missing data.

## Compatibility

No schema migrations. New env knobs (all optional):
`NOTIFICATION_APPROVAL_PRESENCE_WINDOW_SECONDS` (approval-mirror deferral
window, default 120). New events: `user_steer_note`,
`user_steer_note_delivered`; `turn_graph_compiled` now projects a bounded
shape summary to the public stream. Known-open items tracked for the next
wave: effect ceiling from beat authority at graph compile time, splitting
the compose_reply mega-core, compiler-driven fan-out provisioning, local
embedding space.
