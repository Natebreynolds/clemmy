# v3.18.20 — one base, an efficient harness, a judge that answers

Release type: integration of the `harness/3.19` series and an efficiency
wave, 238 commits after v3.18.19 from two agents, tagged from `main`. The fast
gates ran on the exact commit before the tag; the full suite, journeys,
packaged gates and live acceptance finished on it within the hour after, and
their results are below. Earlier candidates from `main` were accepted on the
owner's installed app before the tag.

## What a user notices

**Open-weight brains do real work.** DeepSeek V4.1 Flash through Together AI,
as brain and workers, followed a six-file outbound-email skill to an on-brand
draft in 30 seconds, and drafted three prospect emails through three parallel
workers with a real positive completion verdict. The harness, not the model,
was the bottleneck in both runs, and the two harness defects those runs found
are fixed in this release.

**Fewer wasted model rounds.**
- A read the brain already made in the same request is answered from its
  settled result when the resource has not changed: file, directory, Space,
  workflow or memory, each bound to a revision of what was read, refused when
  another session, run or editor moved it. Status polls always cross.
- A proven strategy that names a native MCP or reviewed CLI read is
  re-attested before the first frame, so a familiar question calls the
  operation by name instead of paying a discovery frame. Live: the same docs
  question went from 35 to 69 seconds and a discovery call every time to 26
  seconds and one read.
- Prior-turn reasoning never rides into a new turn; history is sized by an
  absolute budget rather than the model's window. The heavy status question
  went from 282 seconds and an untrue answer to 28 seconds and a correct one.
- The trajectory watcher lets Jev settle a confident on-track window and
  escalates to the flagship reviewer only on drift, doubt or silence. Measured
  on a week of traffic before the change: Jev agreed with the flagship on 214
  of 217 shadowed windows. Live after: five flagship calls became zero on the
  parent turn, reviewer tokens halved, and the escalation path fired once.

**Familiar work gets shorter.** A learned strategy now carries the request
shapes that succeeded in its proven run (values elided, method and path kept),
so a fresh session reuses the field names that worked instead of paying an
invalid-field call; a generic MCP passthrough such as a raw API request is
materialized exactly on the warm path instead of reporting the carrier
unavailable; and the tool catalog tells the brain that a listed name is
callable now, so saving a standing rule no longer costs a discovery frame.
All three came from the owner's organic-traffic test on the DeepSeek brain.

**A freshly connected app works on its first ask.** A Composio operation whose
name carries no verb, `MONDAY_BOARDS` for one, used to classify as a write,
route through the mutation consent gate, and be refused on a signal the gate
could not resolve, so the first read after connecting monday.com never ran. A
verb-less operation now learns its effect once from its own description and
schema, decided by a model at discovery and persisted, and the one classifier
every dispatch, approval and guardrail site already calls reads that verdict.
An unsure model leaves the conservative write default. A proven strategy that
only partly matches a request no longer spends the request's time provisioning
its operations before the first frame.

**Judges that answer.**
- A fan-out is no longer refused because a number in the request text looked
  like an item count. When the brain's declared items disagree with the
  detected count in chat, a model decides which the user meant; execution and
  background sessions stay strict.
- A reviewer that writes a review but omits its verdict line is asked once for
  the line from its own words before the review is declared unreadable, and a
  failure carries the head of what it wrote.

**Everything the series carried since v3.18.19**, in the handoff's words:
reviewer hedged behind Jev, judge lanes ranked by spend, human-in-the-loop
workflows whose approved step performs what was approved and whose change
request revises the producing step, authoring that settles inside the call,
provider steps that prove their operation on a cold daemon, calendar watch on
a heartbeat contract, live Codex-subscription model discovery, parked runs
that stay parked at boot, dead occurrences retired, workflow account
selection preserved through tool refresh, and the reviewed projection
produced before the goal judge so an approved read pilot lands its records.

## Known limitations, named honestly

- **Workflow write review depends on the bound judge.** The same exact-body
  Slack post passed under one reviewer and was refused as unverifiable under a
  stricter one on the morning of this release, because a deterministic step's
  output reaches the reviewer as prompt context, not as retained evidence it
  can open. The reviewer binding was restored; the evidence gap is open.
- **Parent completion review of a child workflow** has a fix with pins but
  its live parent run after the fix is not recorded in this series.
- **A request that pairs a search with a create can pay an extra discovery
  round.** A catalog ranking change made on 09-24 counts every word of a
  tool's opening purpose, so a request that leads with "search" lifts the
  built-in search tools, and the second operation the request needs can fall
  off the first discovery page. Found after the tag by the cold restaurant
  journey and bisected to that change; not fixed in this release.
- **Eight of 37 acceptance journeys fail at this tag.** All eight fail at
  v3.18.19 too, but six of them fail at a different point. The two
  restaurant-sheet journeys have stopped at their first step since 09-23, when
  an intentional change kept the work carrier visible on an empty catalog,
  and that hid the ranking regression above. The other four differences are
  not yet traced.
- **Host-side activation of a selected reviewed plan** is designed and parked:
  the activation must be a host-emitted first-frame call through the host
  pipeline, so Execute mode still spends one model round on it.
- Windows: signing secrets remain absent; this tag is Mac-only.
