# v3.12.0 — the smart-employee release: an informed first conversation, a manager on the floor, work you can watch

Release type: behavior + visibility release. Every change was root-caused
from one live run on v3.11.0 — a substantial build request that started
with no conversation, showed anonymous progress, and drifted from the
stated task with only telemetry noticing. All three fixes live at shared
chokepoints (turn preflight, the write bracket, the tool wrapper), so they
apply to every kind of task, every tool, and both brain lanes — nothing
keys on the surface that exposed them. Suite at the cut: 9,347 tests
passing, 0 failures.

## The first turn is an informed conversation

On a consequential ask (an external action, a mutation-carrying batch, an
artifact build — about one message in eleven, measured on a real corpus),
the opening directive is no longer generic. It now instructs the model to
ground its opening in what the turn has already computed — the capability
resolution's live connections, proven tools, and recalled memory — and
then to reason about the load-bearing unknowns: exact scope, time window,
format or destination, anything named but unbound. One or two of those
genuinely open → ask about them, conversationally, before any tool runs.
Everything specified → state the reading and proceed in the same turn. A
question whose answer the prompt already contains is noise, not diligence.

This costs nothing at runtime: the grounding data is assembled by the
deterministic local preflight every turn already runs — the directive
redirects attention, it never fetches.

**The words are always the model's own.** The directive describes what the
opening must accomplish, never what to say — and a permanent test now
fails the suite if any scripted sample sentence is ever added to it.
Templated voice is fenced off structurally, not by review vigilance.

## A manager, not a gate

The goal-fidelity judge could already see a run drifting from the pinned
task; its advisory verdicts went to telemetry, so the model never heard
them and off-task directions continued silently. The judge's observation
now reaches the model at the tool boundary as a manager's note: the
specific gap it found, an instruction to re-read the pinned task, and —
if the direction is not clearly the user's — to ask them in one short
sentence. The action still proceeds; inform, never block. Drifting just
stops being silent. Any tool, any provider, any session with a stated
goal.

## Progress you can actually read

Activity rows for wrapped tool calls showed the wrapper's name — "call
tool", dozens of times — instead of the work. They now surface the real
inner action (the CRM query, the file write, the send) through a strict
name grammar, so arguments, paths, and payloads still never leak. Long
runs read as a story of work instead of a wall of identical rows.

## Compatibility

No schema migrations, no new configuration, no new approval surfaces. The
confirm-first beat, goal judge, and activity stream are existing
mechanisms — this release upgrades what flows through them.
