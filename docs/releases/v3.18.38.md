# v3.18.38 — Kernel as the cloud browser, writes that go on in the dark, and working copies inside a budget

Harness schema stays at 93; no database migration. The Mac build comes from
the release workflow (signed and notarized). The Windows x64 build of the same
commit is qualified by the private Windows pipeline from this tag, **unsigned**
until a code-signing certificate exists: a fresh Windows install shows
SmartScreen's "Run anyway".

## The browser is the owner's choice

- **Kernel joins Browserbase, beside this computer's Chrome.** Settings →
  Connect has a Browser card on the desktop and on the phone: choose this
  computer's Chrome, Browserbase or Kernel, and connect a provider with its
  key (saved in the computer's credential store, never in the browser). The
  tools, the side-by-side panel and every workflow step follow the choice,
  and the listing tells Clem which browser the owner chose.
- **The live view shows in the conversation's panel for either provider.**
  The client, both docks and the desktop shell admit Kernel's live view
  alongside Browserbase's; watch, take control, and hand back as before. The
  panel in an older desktop shell says the view arrives with the update,
  which is this one.
- **A workflow step that reads drives the browser it reads with.** A step
  declared read gets a receipt that covers local instruments only, so it can
  open and read pages without becoming a write; a browser owned by a finished
  run is released at the next maintenance pass instead of idling until its
  timeout.
- **Refusals say what to fix.** A Browserbase 402 names the plan or billing,
  a 429 names another browser holding the slot; a key the credential store
  cannot read back is explained on the tool and on the card instead of
  reappearing as an empty form. Clem receives browser handles only, not the
  provider's session, project or timestamps, so they stop surfacing in her
  replies.

## A write with no reply goes on, and Clem answers

v3.18.37 said what was still dark: a write whose reply never came (a timeout,
a dropped connection, a process that ended early) stopped the turn to
reconcile in the harness's words. Now the turn goes on under a write freeze:
nothing is resent, the model reads the target first, the read that lifts the
freeze is named as the answer, and Clem says what landed in her own words. A
connection that dies under a call is closed and reconnected at once, so that
read succeeds. A host-reported refusal with no effect counts as an answered
refusal for the audit, and exact write uncertainty is preserved through
nested provider crossings, with useful recovery reports instead of orphan
holds.

## Reviews and workflows

- **One review on a read, when the fix is checkable.** A read-only answer
  revised to remove the exact claims a review quoted, or to the exact line a
  format finding spelled out, ships on the host's check that the change is
  there, not on a second full review.
- **A refused workflow write is never stranded.** The reviewer sees the tool
  that carries the write, a once-quoted argument object is read as the
  object, and the step either proposes the write again or reports it.
- **Learning and usage bind to the exact accepted task**, discovery learning
  stays tied to its source, and strategy selection has deadlines.

## Faster, and measurable when it is not

- The conversation list re-reads only the session rows that changed, about
  ten times faster on a large history; its lineage reads the rows the list
  already holds; workflow kind checks no longer load retained state.
- Main-loop holds over 750 ms are journaled with the phases that held the
  loop, and the daemon can capture a bounded CPU profile of its main thread
  on request.

## Working copies end inside a storage budget

Clem's own working copies (whole-request copies kept for provenance, raw tool
results already distilled into memory) now have a budget: 10 GB, one week of
working copies, one daily pass. This release only **reports**: each pass
records what it would remove and what still holds space, and nothing is
deleted until the owner turns enforcement on. Memory is never a candidate.
