# Clementine v3.6.0

Release notes — 2026-08-01

This release publishes signed and notarized macOS artifacts. A Windows artifact
is not included because the production Windows signing identity is not
configured; the release uses the repository's documented `[mac-only]` path
rather than publishing an unsigned installer.

## Why this is 3.6, not 3.5.1 or 4.0

This release repairs the chat publication and retry boundary without rolling back the 3.5 intelligence work. It is a minor release because request-id and live-stream contracts change observably. It is not Clementine 4: it introduces a shadow turn-graph compiler and a constrained workflow subgraph pilot, while executable provider-neutral chat nodes, unified capability/context resolution, and graph-owned effects remain the next architecture horizon.

## What changes for users

- Chat no longer publishes raw model deltas, control envelopes, retry prose, tool arguments, or judge narration. Surfaces receive typed progress and one committed terminal reply.
- One accepted user request owns one durable logical source. Provider attempts, retries, restart recovery, approval resumes, and brain fallover stay underneath that source.
- Console, mobile, webhook, Discord, and Slack retries replay the same typed terminal or fail closed when prior external work is uncertain; they do not blindly dispatch a second time.
- Approval replies bind to the exact card and source before mutation. Ambiguous, stale, expired, cross-channel, or runtime-unavailable replies produce deterministic typed outcomes instead of falling through to a new model turn.
- Transcript reopen and model history pair answers to exact source turns, suppress historical duplicate public terminals, and retain the raw rows privately for audit.
- Foreground report-back uses the exact source/status and a durable outbox, so a restart during the grace window neither loses the result nor labels a failure as completed.
- Combined and standalone chat listeners share one process-ownership boundary and open only after startup recovery is armed.

## Client contract changes

### `POST /api/message`

- `Idempotency-Key` is required and must be unique per logical send.
- Reuse the same key only when retrying that same payload.
- Missing key: `400`.
- Same key with a different payload/session/model: `409`.
- A replayed receipt includes `Idempotent-Replay: 1`.

### `POST /api/harness/chat`

- Supply a stable `clientRequestId` (the `requestId` alias or `Idempotency-Key` header is also accepted by the route).
- The shipped React client already supplies this value.
- Lost-response retries reuse the original session, run, accepted source, mutation, and terminal.

### Live events

- Transient raw `delta` events are removed.
- Clients should render typed public progress and `conversation_completed.presentation.text` (with the legacy public `reply` projection retained for compatibility where present).
- Private executor failures and tool payloads are not part of the public transcript/event API.

## Clementine 4 pilot groundwork

- Each exact accepted chat source now produces a private, provider-neutral shadow graph with a deterministic policy/graph hash, fast-path classification, capability requirements, effect ceiling, nodes, and edges. It is observation only: it cannot route, dispatch, approve, retry, terminate, or publish.
- Workflow authors can explicitly compile a heavy read-only reducer into two to six parallel specialists with `subgraph.mode: read_parallel_v1`. Branches and reducer are physically result-only and artifact-query-only; external reads, writes, and sends stay in separate authored nodes.
- The subgraph is part of create/update validation, run preflight, YAML round-trip, admitted-definition hashing, execution-surface change detection, creation testing, persisted run topology, restart recovery, and worker lifecycle telemetry.
- Existing workflows are not rewritten automatically, and there is no new rollout environment gate. Platform 49 remains untouched as the production positive control; a sanitized 500-record/final-page/restart/no-op characterization exercises the new topology offline.
- Durable worker reuse now requires typed manifest identity or exact execution-packet identity. Repeating the same target under a new phase, operation, or contract runs fresh work instead of reusing a semantically unrelated result; later contract revisions override conflicting prior requirements while preserving compatible completed evidence.

## Durable schema and rollback

- Memory schema advances to v32 for durable provider-inbox identity and legacy-unresolved-row quarantine. Pre-upgrade `claimed`/`failed` rows without enough authority to prove safe replay are made inert rather than re-executed.
- Harness eventlog schema advances to the source-owned terminal constraint while remaining rolling-writer aware.
- Before upgrading an existing memory database, Clementine creates a WAL-consistent, integrity-checked snapshot under `~/.clementine-next/state/pre-migration-backups/`. These rollback points are separate from nightly-backup retention. Migration fails closed if the snapshot cannot be created and verified.
- Older builds intentionally refuse a newer memory schema. To roll back to v3.5, stop Clementine and restore the pre-migration snapshot with a compatible recovery build/tool; do not point v3.5 directly at the upgraded database.

## Retired controls

The following ceremony/rollout switches no longer control production behavior:

- `CLEMMY_CONFIRM_BEAT`
- `CLEMMY_FANOUT_ALIGNMENT_BEAT`
- `CLEMMY_FANOUT_ALIGNMENT_ITEMS`
- `CLEMMY_LONGTASK_APPROACH_BEAT`
- `CLEMMY_CONFIRM_FIRST_ALL_WRITES`
- `CLEMMY_BG_OFFER_NUDGE`
- `CLEMMY_BG_OFFER_NUDGE_MIN_MS`
- `CLEMMY_CLAUDE_SDK_STREAMING`

`CLEMMY_CONFIRM_FIRST` remains enabled for irreversible same-shape batch writes. It is a real effect-safety boundary, distinct from the removed conversational confirmation beat. Clementine 4 should remove it only when the intent-and-authority graph node and durable effect receipts own the same invariant.

## Release verification

The final release runtime is `91e1966f`. Relative to the previously proven
runtime, its only production-code change repairs the graph specialist's
run-scoped artifact-query schema: clampable pagination requests now reach the
already-bounded executor instead of failing during schema validation. Four
captured-payload regression tests pin the repair while preserving run-workspace
and completed-event artifact containment.

Clean-checkout local evidence is green: release-focused acceptance 171/171;
full isolated corpus 8,270 total / 8,268 pass / 0 fail / 2 documented
environment/build-conditional skips; journeys 5/5; public hygiene 3/3; release
assets 40/40; unified report-back 7/7; proof self-tests 53/53; fresh-install
smoke; and root, desktop, mobile, and console typechecks/builds.

Stable-commit provider proof on predecessor runtime `0fbf2323` is green: Codex passed five critical scenarios at 93/93 plus the exact-brain-served backstop, and Claude passed the same set at 93/93 plus its backstop. Each 120-item endurance manifest passed 21/21 with 120/120 fresh worker starts, 240 lifecycle checkpoints, zero target-only reuse, exactly one terminal, and no narration leak. The contract-revision steering proof required 48 real worker starts and a v2 dispatch/output carrying `REVALIDATED` without `BASELINE`. An initial parity audit exposed and rejected target-only reuse that could falsely satisfy a revised contract; the proven runtime removes that shortcut instead of hiding the symptom. The final two-file runtime delta does not alter provider routing, terminal publication, or worker-reuse policy; its separate regression and canary evidence is recorded above and below. The isolated provider proofs used disposable homes and proof-local provider shims, not real connected-account effects.

These proofs and the controlled read-side canary do not replace independent private raw-log provenance review, exact live demo replay on every brain/surface included in the release claim, or a real Netlify/Railway or connected-account effect test. Executable long-task guarantees currently apply to authored workflows; chat graphs remain shadow-only. `CLEMMY_CONFIRM_FIRST` therefore remains the write-safety boundary until graph-owned intent/authority and durable effect receipts fully replace it.

The final controlled read-side canary used a fresh isolated home and a 514-row
connected-data artifact. Three specialists became ready concurrently, one
completed before an intentional hard process exit, restart reused that exact
completed branch and the durable source, the remaining branches finished, and

external-effect node with zero dispatch receipts and zero terminal publication.
No external deployment was approved or used as release evidence.
