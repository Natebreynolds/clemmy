# v3.16.0 — one interactive harness, less ceremony, stronger evidence

Release type: pre-Clem4 convergence and reliability release.

This release is a deliberate consolidation cut on the road to Clem 4. It
does not claim that the repository is SDK-free or that the final typed North
Star architecture is complete. It removes an unsuccessful execution mode,
converges interactive model behavior on one host-owned loop, and closes the
live failure classes found while making that transition.

## Chat is the primary desktop destination

Chat stays first in desktop navigation, including when an older saved layout
placed it under More. Untouched launch settings open the last conversation, or
Chat when none is remembered. Explicit Home and project launch choices remain
in place; this does not change the phone's default landing page.

## Normal, Plan, and Execute

Normal handles the task through the existing permission and tool checks without
requiring the user to enter Plan mode. Plan supports read-only investigation
and a saved proposal for review. Execute refers to that exact saved revision;
a revised or incomplete proposal must be resolved before it can run. These
controls are available in desktop and mobile chat. Reviewing a plan does not
replace account, schema, approval, or effect checks.

## Completion review is optional

Desktop and mobile settings include a separate completion-review On/Off control,
with the current judge and selection source shown. Review defaults to On; users
can select a judge from the same provider. The accepted task retains its review
setting and selected judge identity, so later settings changes apply to new
tasks. Turning review Off leaves permissions and saved-result checks in place.
Unavailable review is distinguished from an accepted review. This control is
separate from Fusion/Second opinion.

## Interactive Claude and Codex drive the same car

Interactive chat turns now use the same host harness for Claude and Codex:
one accepted-source binding, shared approval and confirmation checks, one
tool-dispatch boundary, and one terminal evidence path. Claude
subscription authentication remains fail-closed: only subscription OAuth is
accepted, API-key credentials are removed from the transport environment,
and an invalid or missing subscription token stops instead of silently
falling back to API billing.

Vendor SDK packages remain available as transport and brain adapters beneath
the host-owned orchestration path. They do not own an independent interactive
or unattended fallback loop. The accurate claim for this release is execution
owner convergence, not removal of every vendor SDK dependency.

## Code Mode is removed from the executable surface

`run_tool_program`, its sandbox, probes, efficiency metrics, registry lane,
and active dispatch context are removed. The replacement is the normal host
tool path with bounded parallel calls, direct local reads, and an explicit
inner-dispatch carrier where a nested call is structurally required.

Historical event/schema decoders remain so existing runs and activity feeds
can still be read. They are compatibility data, not an executable Code Mode.

## Confirm the material choice, then preserve it

For collect-then-construct work, Clem now asks one natural, model-authored
question when the source materially changes provenance, quality, or cost.
The selected source strategy is persisted across the answer, model switch,
restart, and provider boundary. A confirmed source is enforced before I/O;
an absent or mismatched binding fails closed.

Verified read learning now requires a clean provider envelope, exact durable
receipt and settlement provenance, current schema identity, sufficient
record cardinality, per-record projection fit, and compatible prior topology.
This prevents a failed provider envelope or a lexically similar tool from
becoming the next turn's "proven" source. Distinct account provenances remain
separate choices.

## Less search and less prompt weight

Available native lookup tools are named on the current model surface and can
use a bounded workflow metadata view instead of loading every workflow prompt.
New discovery requests use their exact source and call identity; queries no
longer need a role prefix. Account and schema validation remain in place, and
rephrasing a query does not itself count as discovery progress. Parallel host
tool calls retain bounded concurrency and deterministic result order.

## Write authority and evidence still apply

`create_new` is destination posture, not permission and not proof of
reversibility. Provisional clean bounded reads may feed only documented,
content-bearing atomic constructors. Blank artifact creation followed by an
ambient update is not treated as an atomic operation, and an artifact ID
appearing in arbitrary arguments never grants update/delete authority.

When a task uses a work graph, its required source reads, writes, dependencies,
and result checks must match the admitted contract. Direct native operations
use their current accepted-source scope and exact callable schema. Neither
path treats a model's plan or success message as proof that a write happened.

Provider-result pagination and completeness are interpreted only from the
collection-owning envelope. Empty, partial, contradictory, ambiguous, or
truncated collections cannot provision a downstream write; opaque cursors
and conflicting continuation fields are retained or rejected exactly.

## Typed kernel slice (architecture promotion, not the North Star)

After a semantic port participates, the turn stays on one typed kernel:
admitted graph, exact-call dispatch, settlement, evidence, one Outcome.
Conversation remains for greetings and host-only sketches. It is not a
second action executor for participated reads, writes, or unknown effects.
Unbound work parks or blocks with zero business calls.

Two provider-neutral shapes are in that kernel: a bounded collection read
with inspect/transform, and collect → transform → construct/update →
readback. Host bind is unique-or-null among attested contracts. When that
misses, one repair interpret may name an attested `capabilityRef`; the host
still validates. This is not “any task with any tool.”

## Schema v69 seals model-result handoff without copying result payloads

The host now records an immutable, source-bound receipt for each settled
logical result admitted into the next model request. The receipt binds the
accepted task/batch/call, exact settlement identity, result class, canonical
byte count, and SHA-256. It lets restart recovery distinguish a committed
result projection from work that never became model-visible without replaying
the provider body.

`logical_model_result_projection_receipts` is deliberately metadata-only. It
does not store provider output, projected content, or a JSON result payload;
the accepted model history remains the single copy of those bytes. The v3.14
upgrade rehearsal pins that exact schema-69 shape, requires zero invented rows
for a fixture with no eligible current checkpoint, and includes the table in
packaged two-boot work accounting.

## Schema v70 makes session retention atomic and complete

A valid source-universe amendment no longer strands its old terminal session.
The amendment now follows the exact session-bound work-contract and audit-event
cascade, while its existing trigger still rejects standalone mutation or
deletion. The retention reaper also freezes one exact eligible set and performs
replay-authority cleanup, physical-authority cleanup, and final session deletion
in one transaction. Pinned and archived conversations retain their replay
authority, and any unexpected final foreign-key blocker rolls the whole sweep
back instead of leaving a partially stripped session.

## Schema v72 makes asynchronous read outcomes restart-safe

Schema v72 adds mutually exclusive completion/terminal receipts and a durable
keyset cursor for host-owned asynchronous read refinement recovery. Homes that
already applied schema v71 receive the new owner tables and exclusion triggers
through the additive v72 migration; no provider or model call runs during the
migration.

## Schema v73 normalizes restart and Stop authority from stamped candidates

Schema v73 reopens homes already stamped by an earlier v71/v72 development
candidate. It restores the plan-seal and async recovery cursors, strengthens
terminal outcome constraints and reciprocal exclusion, and adds an immutable
source-bound Stop witness without replaying model or provider work.

An immutable preparation checkpoint now binds the exact `plan_task` call,
structured-model graph and expected-work contract to its content-addressed
conversation preamble before presentation I/O. A restart can finish a durable
desktop/mobile/API delivery without another model pass, while a channel-owned
placeholder remains held for its exact transport instead of being silently
redirected. A receipt committed before host settlement recovery activates the
same task once; historical ambiguous owners remain non-executing.

## Schema v74 guards the in-flight chat index against corrupt legacy metadata

Schema v74 drops and recreates `idx_sessions_chat_run_in_flight_updated`
behind `json_valid(metadata_json)`. SQLite evaluates a partial-index predicate
on every `sessions` write, so on a home already stamped v72/v73 one legacy row
with malformed `metadata_json` failed every update of that row and aborted the
periodic exact-checkpoint recovery scan. The restart-recovery read and clear
paths guard the same predicate. No row is rewritten and no model or provider
call runs during the migration.

## Schema v75 bounds sealed dispatch recovery arguments

Schema v75 rebuilds the dispatch-lease storage contract with a 16 MiB ceiling for
sealed recovery arguments. The forward migration preserves existing rows, foreign
keys, and integrity while preventing an unbounded recovery payload from becoming a
restart or storage failure.

## Schemas v76 and v77 project direct host writes durably

Schema v76 gives direct host-owned writes the same durable projection CAS used to
connect an authorized call to its physical and logical settlement truth. Schema v77
is the immutable forward correction to v76: it keeps an orphaned or ambiguous
crossing distinct from decisive success or failure, so restart recovery never
manufactures a green terminal or blindly repeats a possible effect. The two
migrations form one release unit; neither migration is rewritten.

## Schema v80 completes recovery, conversation recall, and discovery ownership updates

- **v78** adds an event-type/sequence index for recovery and learning scans;
  existing event payloads and recovery scope are unchanged.
- **v79** adds an incremental full-text index of public conversation turns and
  source-bound search receipts. Recall checks the same user's access and the
  exact public snapshot; the migration does not scan every historical payload.
- **v80** records exact discovery call/request identities for new accepted
  sources. Existing in-progress sources retain their legacy claim version, so
  the upgrade does not reinterpret their discovery ownership.

## Schema v81 records the per-item work a delegated worker discharged

- **v81** adds one immutable row per (accepted contract, per-item requirement,
  universe member) that a delegated worker child proved it completed, together
  with the child's session and the exact logical call that settled it. A
  parent's fan-out progress is credited from that proof instead of from a
  worker's prose, and the same row makes the once-per-item admission guard see
  work a child already did. The migration is additive — a new empty table, its
  index, and an immutability trigger. No existing table is altered, no earlier
  migration is rewritten, and nothing scans historical payloads.

The current harness schema version is **80**. These migrations do not invoke
models or providers.

## An answered clarification never parks the task

When Clementine asks a clarifying question and the answer arrives, the answer is
now consumed even when it comes with a sketched plan, and the host no longer
rejects its own long-lived capability ids while reading it. If an answer cannot
be read at all, Clementine re-asks the same question with a visible terminal
instead of holding the conversation open with no reply. Repeated identical
repair attempts spend a small bounded retry budget before the turn stops with a
named next step; the stop remains resumable.

## Known boundaries before Clem 4

- Plan mode over live CLI reads (for example Salesforce SOQL through the sf CLI)
  can investigate but may fail to publish: each live read mints its own
  capability identity, so publish_plan can report "provider schema changed
  after discovery". The stop is typed and resumable; run the same request in
  Normal mode until live-read identities are stable across a plan.

- This phase claims the typed kernel slice above. It does not claim universal
  completion or live catalog uniqueness for every connected app.
- Full graph-driver subtraction, universal graph-free write completion, same-turn
  consent asks, and the frozen Salesforce → local rehearsal → reversible-draft
  mutation canary are explicitly deferred to v3.17. v3.16 does not claim that
  live drafts crossed.
- Claude SDK brain, compatibility-loop, Claude/Codex/GLM/BYO/fallback
  transport, and the Salesforce, Sheets, Apify, and Ventura fixture suites are
  release gates for this tag. Credentialed live-provider canaries remain
  separate evidence and do not imply that every connected account is
  available.
- Vendor SDK packages remain in the repository as transport and brain
  dependencies under the host execution owner.
- Claude interactive transport is OAuth-or-stop. A live route proves that it
  cannot silently use an API key; exact Max/Pro quota accounting remains a
  live billing observation rather than a source-code claim.
- The release tag must point to a clean commit whose tree, build stamp, and
  daemon fingerprints match, with packed-candidate green on those bytes.
  Tagging a dirty tree or a mismatched fingerprint is not a pass.
