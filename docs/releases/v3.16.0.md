# v3.16.0 — one interactive harness, less ceremony, stronger evidence

Release type: pre-Clem4 convergence and reliability release.

This release is a deliberate consolidation cut on the road to Clem 4. It
does not claim that the repository is SDK-free or that the final typed North
Star architecture is complete. It removes an unsuccessful execution mode,
converges interactive model behavior on one host-owned loop, and closes the
live failure classes found while making that transition.

## Interactive Claude and Codex drive the same car

Interactive chat turns now use the same host harness for Claude and Codex:
one source binding, one preflight and confirmation contract, one approval
kernel, one tool-dispatch boundary, and one terminal evidence path. Claude
subscription authentication remains fail-closed: only subscription OAuth is
accepted, API-key credentials are removed from the transport environment,
and an invalid or missing subscription token stops instead of silently
falling back to API billing.

The standalone Claude Agent SDK path remains available for unattended
execution surfaces while those are migrated. The accurate claim for this
release is interactive turn-owner convergence, not removal of every vendor
SDK dependency.

## Code Mode is removed from the executable surface

`run_tool_program`, its sandbox, probes, efficiency metrics, registry lane,
and active dispatch context are removed. The replacement is the normal host
tool path with bounded parallel calls, direct local reads, and an explicit
inner-dispatch carrier where a nested call is structurally required.

Historical event/schema decoders remain so existing runs and activity feeds
can still be read. They are compatibility data, not an executable Code Mode.

## Confirm the material choice, then preserve it

For collect-then-construct work, Clem now asks one natural, model-authored
question when the source materially changes provenance, quality, or cost.
The selected source strategy is persisted across the answer, model switch,
restart, and provider boundary. A confirmed source is enforced before I/O;
an absent or mismatched binding fails closed.

Verified read learning now requires a clean provider envelope, exact durable
receipt and settlement provenance, current schema identity, sufficient
record cardinality, per-record projection fit, and compatible prior topology.
This prevents a failed provider envelope or a lexically similar tool from
becoming the next turn's "proven" source. Distinct account provenances remain
separate choices.

## Less search and less prompt weight

Exact local workflow reads are hot on the shared model surface and can use a
bounded metadata view instead of loading every workflow prompt. Discovery is
role-scoped and fail-closed; a denied or exhausted search cannot execute as
telemetry. Context-window scaling is capped, and parallel host tool calls use
bounded concurrency while preserving deterministic result order.

## Writes require evidence-shaped plans

`create_new` is destination posture, not permission and not proof of
reversibility. Provisional clean bounded reads may feed only documented,
content-bearing atomic constructors. Blank artifact creation followed by an
ambient update is not treated as an atomic operation, and an artifact ID
appearing in arbitrary arguments never grants update/delete authority.

A collect → artifact → delivery request must freeze the complete four-stage
contract before any provider call: source read, construct write, verification
read, then terminal delivery write. Incomplete, parallel, reversed, or
readback-free proposals are refused.

Provider-result pagination and completeness are interpreted only from the
collection-owning envelope. Empty, partial, contradictory, ambiguous, or
truncated collections cannot provision a downstream write; opaque cursors
and conflicting continuation fields are retained or rejected exactly.

## Typed kernel slice (architecture promotion, not the North Star)

After a semantic port participates, the turn stays on one typed kernel:
admitted graph, exact-call dispatch, settlement, evidence, one Outcome.
Conversation remains for greetings and host-only sketches. It is not a
second action executor for participated reads, writes, or unknown effects.
Unbound work parks or blocks with zero business calls.

Two provider-neutral shapes are in that kernel: a bounded collection read
with inspect/transform, and collect → transform → construct/update →
readback. Host bind is unique-or-null among attested contracts. When that
misses, one repair interpret may name an attested `capabilityRef`; the host
still validates. This is not “any task with any tool.”

## Known boundaries before Clem 4

- This phase claims the typed kernel slice above. It does not claim
  universal completion, live catalog uniqueness for every connected app, or
  Claude/loop suite green.
- Claude SDK brain tests, the compatibility loop, vendor fixtures
  (Salesforce, Sheets, Apify, Ventura), and legacy policy-gate traps remain
  release-stabilization work. They are out of this architecture tag.
- Vendor SDK packages remain in the repository as transport and unattended
  execution dependencies.
- Claude interactive transport is OAuth-or-stop. A live route proves that it
  cannot silently use an API key; exact Max/Pro quota accounting remains a
  live billing observation rather than a source-code claim.
- The release tag must point to a clean commit whose tree, build stamp, and
  daemon fingerprints match, with packed-candidate green on those bytes.
  Tagging a dirty tree or a mismatched fingerprint is not a pass.
