# v3.18.30 — "Continue" means continue, on every brain and in both modes

Mac-only release. Harness schema stays at 93 and memory schema at 37; no
database migration. A user on the Claude brain replied "continue" to a
question Clem had asked and got the same question back. The case they hit
was already closed in v3.18.29; this release closes the three remaining ways
the same dead end could still happen, found by probing the reply router with
every reading shape and tracing plan mode and act mode live on 2026-10-07.

## What changed

- A "continue" or "go ahead" the quick model bound to no goal, and a change
  ("make it shorter") against a stale revision, used to fall through the
  reply router with the question still pending and no steer, so the brain
  simply re-asked. Both now reach the brain with the question on hold and
  the standing instruction: carry on, choose sensible defaults, say what
  was assumed, ask only if something truly blocks.
- In plan mode a plain "continue" to a plan that was asking questions
  re-planned the same request with no answers and asked the same questions
  again. The planner now proceeds on sensible defaults, names each
  assumption in the step text so it can be corrected, and the asking plan
  is superseded by the new one.
- When the quick model answers in the wrong shape (a stray key, live
  `slotAnswersNote`), the strict output schema used to throw the whole
  reading away; the reply became unreadable and the revision step re-asked
  with "I received your reply: 'continue.' It does not select one of the
  listed options…". The interpreter now asks once more with the shape named.
  When a reply is still unreadable, Jev reads it first: a go-ahead or a
  question back goes to the brain without any re-ask; an attempted answer
  keeps the checked re-ask path and never binds. The revision proposer, when
  it is used, speaks as Clem in plain words.

All brains (Claude OAuth, Codex OAuth, BYO keys) run on the same host turn
engine, so one reply router serves every brain; the old SDK engine runs only
for sessions persisted on it.

## Live evidence (installed app, live home, 2026-10-07)

- Act mode: Clem asks the one question she needs; "continue" goes to the
  brain, which checks the calendar and asks one sharper question (the
  change was genuinely unknown). No verbatim repeat.
- Plan mode: an asking plan; "continue" goes to the brain and yields a
  partial plan card with only the still-unknown items left.
- Regression: write a file → one card → "Yes, go ahead." runs it →
  "Continue." finishes (3 of 3).
- The 3.18.29 scenarios re-run on the candidate (15:35–15:41Z, with the
  batch suite and a live-home cleanup running on the same machine): Outlook
  draft-then-delete 3 of 3, change-in-words 3 of 3, revise-then-edit 2 of 2,
  Slack reminder 4 of 6 — the two others ended done with honest words, one
  carrying a verification note ("2 business call failure(s) have no
  successful recovery") because the brain added a direct lookup that
  returned not_found; the settlement audit counts only a refused write as an
  answered refusal. Not a change from 3.18.29; a candidate for the next fix.

## Known limits

  slow quick model; the judges run together, the interpreter now retries
  once on a shape refusal.
