# v3.18.35 — files beside the chat, cards in plain words, faster turns

Harness schema stays at 93; no database migration. The Mac build comes from
the release workflow (signed and notarized). The Windows x64 build of the same
commit is qualified by the private Windows pipeline from this tag and attached
to this release, **unsigned** until a code-signing certificate exists: a fresh
Windows install shows SmartScreen's "Run anyway"; updates install normally.

## Cards and approvals

- **A tap is the approval.** Tapping a choice Clem offered on Home approves
  exactly that action; no second card asks again.
- **Cards say what they approve in plain words.** Ids, flags and raw JSON fold
  under Details. Every card names the files that would leave this computer,
  on desktop and phone. A card raised partway through a request opens with
  what is already done, and after a tap Clem's answer shows, with a working
  state until it does.
- **When an app refuses a write, Clem says so.** The turn ends in Clem's own
  words from what the app answered, not "uncertain, reconcile", and anything
  Clem would change before trying again is asked first.
- **Fewer repeat asks.** An invite the organizer changed after you answered
  is one re-ask that says why, and Noticing never raises what Home already
  asks.

## Files and this computer

- **Files beside the chat.** Files and PDFs Clem saves appear next to the
  chat on desktop and phone, including ones a shell command wrote, and work
  stays navigable while they are open.
- **You choose what Clem can reach.** First run asks once; Settings →
  Computer access offers Full access or Standard, with this computer's own
  gates. Adding a folder keeps the default folders.
- **Files go where they are asked to.** Connected-app uploads send the named
  local file, and MCP tools that take file content get its bytes.
- **Finding files.** On macOS Clem finds files by name through Spotlight; on
  Windows a card reads an outgoing command the way cmd.exe does. file_query
  refuses credential files and redacts secrets, as read_file does.
- **Images.** An image link Clem reads comes back as the image itself.

## Faster turns

- **More of the conversation stays cached.** The tools block stays the same
  from turn to turn, the list of ready actions travels with the turn, and a
  provider's cache miss no longer flips how the prompt is laid out. In the
  three-message test, turns started with 7–25K cached tokens instead of
  2–4K, the third turn cost half as much, and the whole conversation ran
  about 20% faster.
- **Searches stop waiting on a second model.** A search used to wait a median
  5.3 s for an account check on every write it found, even writes the turn
  never used. It now answers right away; the same check still has to pass
  before the write runs.
- **The right action, sooner.** When an app lists an action it cannot serve
  right now, Clem is pointed at the closest one that works (an email send no
  longer detours through a draft). A search that names a connected app
  answers from its current contracts after 2.5 s, and a guessed action name
  is searched as words in the same pass.
- **Fewer dead turns.** A slightly malformed tool call is repaired or refused
  with its own schema, never a turn-ending checkpoint failure; a read that
  failed no longer takes the turn's tools away.
- **Saved results.** Clem can pick one exact part of a saved result, reach
  text inside nested lists, and reuse a value only when it is exactly the one
  shown.
- **Reviews.** The completion review states its verdict reliably and judges
  only the evidence it was shown.

## What changed

Validated in the owner's installed app with hotpatches 115–124 on live
connected accounts: the three-message slide/drafts/PDF conversation (warm,
two or more runs per change), an Outlook send that stops at its card (three
runs per build, all declined, nothing sent), and a read-only drafts question
as a control. The full suite matches the build before these changes; CI's
unit-test failures are the same 22 known ones as v3.18.34.
