# v3.7.1 — external-effect safety hotfix

Release type: narrow safety patch on v3.7.0. No feature surface.

## The one change

Reverts `a03a3395` ("a validator-rejected mutation is proven no-dispatch").

That commit classified validation-looking provider text — returned failure
envelopes and thrown errors such as
`Invalid request data provided - Following fields are missing: {...}` —
as proof that a Composio mutation never dispatched. On that proof the write
boundary released the durable reservation and told the model it was safe to
retry once with corrected arguments.

The provider executor has already been invoked when such text arrives. A
remote adapter can partially apply a bulk operation, commit a downstream
sub-call, or lose the original response and still return validation-shaped
prose. Treating that prose as no-dispatch authority can duplicate sends,
records, rows, and other external writes in chat and workflows.

v3.7.1 restores the fail-closed rule: only local structural evidence produced
**before** a provider invocation proves `dispatch=not_started`. Post-invocation
validation failures settle as ambiguous orphans owned by the verify-before-
retry reconciliation protocol. Timeout, 5xx, orphan, and readback behavior are
unchanged.

## Known trade-off

The Platform 49 shape that motivated the reverted commit (a Sheets insert
missing its `insert_dimension` wrapper) parks safely for verification again
instead of self-retrying. The correct fix — an exact local schema preflight
that proves no-dispatch *before* the provider call — requires schema
co-travel and lands with the staged capability work, not in a hotfix.

## Regression pins

`src/runtime/harness/external-effect-safety.h0.test.ts` — four tests at the
adapter and durable write-boundary levels; three fail on the predecessor
commit by construction (invocation-counter executors + the exact live error
text on both channels), and a forge case proves provider-returned marker text
cannot mint the trusted no-dispatch class.
