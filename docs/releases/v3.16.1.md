# v3.16.1 — answers get consumed, reads get retried, the host asks its own question

Release type: same-day follow-up to v3.16.0 from live runs on Opus 5, GLM 5.2
and Grok 4.6 against the dev daemon.

## A slot answer is never re-judged

A clean answer to one of Clementine's own questions ("which calendar?") was
being rejected when the grounding judge re-judged the resumed goal's stored
plan against the current catalog. Grounding now applies only to work the
proposal itself supplies; a slot answer settles a slot.

## A failed read is retried, not preserved as an uncertain effect

A read that threw (for example the 60-second provider fuse on an Outlook
calendar lookup) used to stop a workflow with "effect must be reconciled".
Nothing irreversible can follow from a failed read; it is now a transient
failure retried within the existing backoff budget. Mutations keep the
cautious stop. (Shipped on main after v3.16.0 was cut.)

## The host asks the account question it already holds

When discovery reports that an operation needs one of several connected
accounts and the brain never asks, the turn used to end blocked after the
no-progress governor exhausted. It now ends as that question, with the exact
connected accounts as choices, so the next answer is adjacent and consumable.

## Known boundaries

- Smaller brains still spend minutes in discovery before asking; the
  host-raised question bounds the outcome, not the time.
- An answer that does not name the account ("my default calendar") still
  does not bind it; the refusal now says why and the question is re-asked.
