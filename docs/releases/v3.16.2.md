# v3.16.2 — a read is one call, and every stop says why

Two user traces on v3.16.1 drove this release: a one-line calendar question that
burned fifteen tool calls and died, and a plan-mode task that ended with a stop
that asserted a cause it did not know. The fixes are to the framework, not to
any one tool.

## Reads no longer wait on the judge

The cross-family judge exists so a write never goes out from the wrong identity.
It was also sitting on every read. A read with a nominated or established
account now routes directly; the judge reviews writes only. Reading the wrong
calendar is visible and correctable; sending from the wrong mailbox is not.

## One clarifying beat, host-owned

When discovery has twice come back "which account?" for the same operation and
more than one account is connected, the host stops and asks the user itself, with
each choice labeled (account label, alias, or email). Before, the model was told
it could ask and kept guessing instead.

## The judge is no longer a silent single point of failure

A failed account review is logged with its cause, is never cached as the answer
(the advertised "retry once" could never succeed before), and falls back to the
live brain for that call when the judge role's model is unavailable.

## Every stop says what stopped it

A no-progress stop renders the last concrete tool error from this turn — for
example the Salesforce CLI's own "No default environment found. Use --target-org" —
instead of only a stage name. Stops assert only what the ledger shows.

## Plan mode allows reads

A read-only command crosses no consequence boundary, whatever carries it. A
planning turn can list orgs or pull records to plan its work; writes stay closed.

## An error that names its own fix gets applied

The reviewed CLI transport applies the fix a tool names when it is unambiguous:
a Salesforce CLI with no default org lists its orgs and reruns with the sole or
default one; otherwise the error carries the exact command to run.

## Also in this release

- The desktop "something went wrong" on a fresh install: the vault seal key is
  created at every boot (shipped in v3.16.1, kept here for completeness).
- Reconciliation hard-blocks only irreversible external effects (v3.16.1).

## Four more hoops off every read

- A provider operation the model names as `composio:SLUG` classifies by its slug
  instead of being refused as "effect unknown."
- A read needs no plan sibling; that rule now applies to writes only.
- A refusal for an account-blocked operation names the labeled connected
  accounts first instead of "not proven, discover it."
- Tool-choice recall says when a known failure is stale, and when the CLI it
  blamed is present on this machine now.

## She remembers the answer

When you answer "which account?" for a read, that account becomes the remembered
read default for that toolkit. She will not ask again. A remembered read default
never routes a write.

## Workers can find their tools

A worker spawned mid-conversation now gets the same discovery policy as the
conversation itself, so a delegated inbox or calendar read can discover and
prove its operation instead of coming back "not done."

## A cancelled local carrier is not an uncertain write

Cancelling a delegation of reads (or any local write) no longer hard-blocks the
turn as an uncertain external effect. Only writes past the irreversible boundary
hold for reconciliation.
