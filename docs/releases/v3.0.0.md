# Clementine 3.0.0

Clementine 3 is a major upgrade to how work is planned, carried across time,
verified, and surfaced. The model remains the engine; the runtime now gives it
lighter, event-driven guidance for durable work instead of forcing every
request through the same heavy loop.

## A more capable runtime

- Long-horizon tasks can fan out, preserve item-level progress, survive a
  restart, and resume without quietly repeating completed work.
- You can keep talking with Clementine while work is underway. Collaborative
  state carries across turns so plans can be refined, redirected, paused, and
  continued without throwing away valid progress.
- Tool schemas, MCP capabilities, and execution guidance are discovered on
  demand. Simple conversations stay lean while complex work can expand into the
  tools and context it actually needs.
- Model-scoped failures can fall over to an available brain without treating
  the whole task as failed. Fusion remains optional and bounded, adding
  cross-model verification when its extra scrutiny is useful.
- Work delegated to a team agent can now be carried through to completion.
  Previously a delegated task could only be queued: nothing could record its
  result, so an execution that delegated a step waited on it indefinitely. A
  delegate can now see the work assigned to it and close it with a durable
  result, and the record always names who actually produced that result —
  including when Clementine did the work herself rather than a teammate.
  Agents do not yet pick up delegated work on their own schedule; delegation
  runs through Clementine.

## Truthful completion and safer actions

- Completion now comes from durable execution evidence, not a confident model
  claim. Collection work retains item manifests, workflow outputs retain their
  proof, and blocked steps cannot be counted as successes.
- External writes remain bound to the user's goal and approval policy. When a
  connection or authorization is missing, Clementine preserves the work,
  explains the exact next action, and can resume after reconnection.
- Natural external actions such as RSVPs, reservations, purchases, social
  changes, signatures, repository changes, and calendar updates now share the
  same request-bound receipt requirement as explicit provider writes.
- Report-backs, task cards, and the inbox show the evidence and real status
  behind the answer, including partial, blocked, or needs-attention outcomes.

## Memory that helps without bloating every turn

- Prospective memory preserves intended future work and reminders across turns.
- Procedural learning is gated on successful execution evidence, reducing the
  chance that a failed attempt becomes a learned workflow.
- Recall, pinned policy, and explicit forget behavior are more precise, while
  irrelevant generic harness context is kept out of the active prompt.

## Workspaces and workflows

- Workspaces now have a durable operating contract covering purpose, done-when
  conditions, and rules that must always be preserved. Contracts can be safely
  edited and recalled without silently mutating a blank workspace.
- Live workspace views must be wired to real data before they can be saved.
  Workspace data, approvals, task status, and evidence are easier to inspect
  from the console.
- Each workspace data source now keeps bounded, append-only snapshots instead
  of overwriting its only copy. Clementine can answer what changed using exact,
  on-demand history and diffs while projecting only compact, meaningful change
  signals into memory.
- Removed or renamed data sources are durably retired: their audit history
  remains available, but stale values cannot return as current data after a
  restart. Re-adding a source requires a fresh successful pull before its data
  becomes current again.
- Definition-driven workflows handle branch dependencies,
  reconnect-and-resume, collection thresholds, reusable code steps, and
  parallel work more reliably. A blocked dependency stops only the work that
  actually depends on it.
- Clementine can now reshape a workflow run while it is still in flight. When
  reality diverges from the plan she can widen a bottleneck into parallel
  branches, withhold a route whose source has gone dark, or restore one that
  recovered — and the run's shape, not just its progress, is what changes.
  Completed work is never edited or removed by a reshape, and a change that
  would let work run without waiting for an approval-gated send is refused
  with the exact reason. The console shows each reshape in plain language,
  including the ones that were refused.
- A workflow that writes and then verifies its own write — append a receipt
  and read it back, upsert a record and confirm it — can now pass its creation
  test. The mutating step is still previewed rather than executed while
  authoring; the step that verifies it is reported as not-yet-checkable
  instead of broken, so the pattern no longer leaves a workflow disabled.

## Integrations and model choice

- Composio connections can be created and inspected in Clementine, and local
  MCP tools are discoverable on demand and visible through the integration
  surfaces.
- Authenticated Composio CLI reads remain lightweight. CLI writes require a
  named, toolkit-scoped default-account grant in Connect plus the normal exact
  action approval; revoking or replacing that grant invalidates queued work.
- Older Recall meeting recordings that predate the canonical-transcript state
  now expose truthful retry and restart recovery instead of remaining stuck as
  unavailable.
- Claude, Codex, and GLM model discovery and routing are more resilient to
  provider changes. Cross-provider workers, fallback, and opt-in Fusion share
  the same evidence and completion contracts.

## A calmer, more useful console

- Chat, tasks, workspaces, integrations, approvals, and needs-attention states
  now tell a consistent story about what Clementine is doing and why.
- Compact surfaces no longer leak raw Markdown or misleading completion states.
  Fusion status, delivery sequencing, and durable report-back evidence are
  presented directly in the interface.

This release also refreshes the packaged desktop dependencies and strengthens
macOS and Windows release validation. Production Windows artifacts must be
signed and pass post-build Authenticode verification; private manual release
candidates may still be unsigned for rehearsal.
